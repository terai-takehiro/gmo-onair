# 入ってきた情報（`record_inquiry`）— 他のどこにも入らない有益メール

## 入れるもの

決定表の #8 #9 #10 #12 に当たったもの。要するに
**「人が書いていて、当社に用件があり、案件・書類・内覧会のどれでもない」**メールです。

実際に届いていたもの（1か月の実測）:

- 取材依頼（映像新聞社・サンレコ）／掲載原稿の確認
- 協業の打診（他社スタジオ・配信プラットフォーム）
- 施設・設備の連絡（世田谷ビジネススクエアのテナントポータル・東急の工事案内）
- 社内周知のうち緊急度・重要度が高いもの（`緊3/3` `重3/3`）
- **脆弱性・規約改定の告知**（例:「SRTプロトコルライブラリに関する重大脆弱性」）
  — **メルマガの体裁で届くが業務に効く。捨てないこと**
- 見学の受け入れ依頼・名刺交換の続き

## 入れないもの

- 外部からの営業・売り込み・コールドメール
- メルマガ・広告・展示会の案内（**日付のある招待だけは例外**）
- 自動通知の類（DMARC・GitHub・Zoom・Box・Eight）
- 他のツールが受けるもの（見積請求 → `record_finance_doc` ／
  内覧会 → `register_inview_attendee` ／ 案件の問い合わせ → `create_project`）

## 引数

| 引数 | 何を入れるか |
|---|---|
| `sender` | `氏名 (メール) / 会社名` |
| `subject` | メール件名 |
| `summary` | **1行**の要約。「誰が・何を・いつまでに」 |
| `importance` | `high` は**今日中に人が動かないと困るもの**だけ。ほかは `medium` / `low` |
| `action_needed` | 人がやることを1文で。**AI の感想は書かない** |
| `source` | メールからなら `mail`（**必ず渡す**） |
| `tags` | 短い語を1〜3個。関係する GLS 番号が分かればそれもタグに |
| `message_id` | メールの Message-ID（重複取込ガード） |
| `details` | 読み取れた項目だけ（下記） |
| `body_text` | **メール本文の全文**。切り詰めない |

### よく使うタグ

`取材` / `メディア掲載` / `協業` / `採用` / `設備` / `工事` / `セキュリティ` /
`社内周知` / `リード` / `資料ダウンロード` / `見学` / `先の話`

## `details` の組み立て方

**HTML やマークダウンを書きません。** 「何の情報か」を言うだけで、見せ方はアプリが決めます。

```
details = [
  { type: 'fields', items: [
      { label: '会社名',   value: '株式会社リットーミュージック' },
      { label: '担当者',   value: '松本 伊織' },
      { label: '要件',     value: 'サンレコ記事用の画像素材の提供' },
      { label: '返事の期限', value: '2026-09-10' },
  ]},
  { type: 'bullets', items: ['スタジオ全景写真', 'DCA901 の収音範囲設定画面'] },
  { type: 'quote',  text: '（判断の根拠になる原文をそのまま）' },
]
```

- **読み取れた項目だけ入れます。** 読み取れなかった項目を「不明」で埋めない
  （記録が無いことと「不明と書いてあった」ことの区別が付かなくなります）。
- `quote` には**原文をそのまま**入れます。要約し直さないこと。
- 使える種類: `heading` / `text` / `fields` / `bullets` / `table` / `quote` / `note` / `link`。
  知らない種類はサーバーが捨てます。

## 行き先（`state`）は AI が決めない

取り込んだものは必ず**「未仕分け」**で入ります。
ストック / チケット / 案件の受付へ送る / 見送り は**人が画面で決めます**。

⚠️ **「これは見送りだろう」と思っても取り込んでください。**
実測では AI が取り込んだ5件のうち5件が見送りになりましたが、その中には
`importance: high` で実際に対応中だった取材依頼が含まれていました
（見送りの判断は仕分けの運用側の問題で、取り込まない理由にはなりません）。
