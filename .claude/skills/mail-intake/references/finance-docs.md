# 受領書類 — 見積書 → 発注書 → 請求書 を「ひとつづり」で入れる

呼ぶのは **`record_finance_doc`** の1本です（migration 280 で引数が増えました）。

## 何が「ひとつづり」か

実際の取引は段を踏みます。しかも**ぜんぶ普通に起きます**:

- 見積書が何度も改定される（同じ取引で見積書が3通届く）
- 見積だけ取って発注しない（請求書が来ない）
- 請求書しか来ない（見積も発注も無い）
- 分割請求で請求書が2通来る

1通ずつ入れると、経理は「この請求書はどの見積の続きか」を毎回メールで探し直します。
**`group_key` を渡して束ねてください。**

## `group_key` の作り方

**同じ取引だと言い切れるときだけ**同じ鍵にします。迷ったら別の鍵にしてください
（束ね直しは人が画面からできますが、**別々の取引が1つにまとまるとどちらも払えなくなります**）。

優先順位:

1. **書類番号が同じ**（見積番号・注文番号が本文か PDF 名にある）
   → `doc:<番号>` 例 `doc:154939`
2. **同じメールスレッドの続き**（`Re:` で件名が同じ・差出人が同じ）
   → `thread:<スレッドの最初の Message-ID>`
3. 上のどちらでもない → **渡さない**（1通で1つの束になる）

⚠️ **取引先名だけで束ねないこと。** 同じ取引先から別件の請求書が来たときに混ざります。

## 引数の対応

| 引数 | 何を入れるか |
|---|---|
| `doc_type` | `quote`（見積書）/ `order`（注文書・発注書）/ `invoice`（請求書） |
| `sender` | 差出人（会社名 担当者名） |
| `vendor_name` | **会社名だけ**。署名から取る。台帳の取引先名になる |
| `subject` | メール件名 |
| `content` | 内容の1行要約 |
| `amount` | **税込**の金額（円）。書いていなければ渡さない（0 を入れない） |
| `closing_month` | 締月 `YYYY-MM` |
| `payment_due` | 支払期日 `YYYY-MM-DD`。**書いてあるときだけ** |
| `received_at` | 受信日 `YYYY-MM-DD` |
| `message_id` | メールの Message-ID（**必ず**。重複取込ガード） |
| `group_key` | 上の作り方で |
| `group_title` | 何の取引か（例 `8/28イベント 備品レンタル`） |
| `doc_no` | 書類番号（見積番号・請求番号） |
| `revision` | **見積が改定されたら 2, 3…**。同じ `group_key` で登録する |
| `project_hint` | GLS 番号か案件名。**AI は案件を決め打たない**（サーバーが探す） |
| `expense_kind` | `purchase`（案件の仕入）/ `sga`（販管費）。決めきれなければ渡さない |
| `payment_terms_days` | 販管費のとき。「30日サイト」なら 30 |
| `processing_month` | 販管費のとき。何月処理か `YYYY-MM` |
| `attachments` | 添付。下記 |
| `details` / `body_text` | 読める形の中身と、メール本文の全文 |

## 案件の仕入か販管費か

| | 仕入（`purchase`） | 販管費（`sga`） |
|---|---|---|
| 何か | **特定の案件のために買ったもの** | 案件に紐づかない会社の経費 |
| 例 | イベントの備品レンタル・ケータリング・臨時警備・外部スタッフ | 家賃・回線・ソフトの月額・事務用品・弁当 |
| 手がかり | 件名や本文に GLS 番号・イベント日・案件名がある | 「〇月分」「月額」「利用料」で、案件名が出てこない |

**どちらとも言えないときは `expense_kind` を渡しません。** 画面に「未定」と出て、
人が決めます。適当に `purchase` にすると、**案件の原価に他人の家賃が載ります**。

### 販管費のサイトの読み方

支払条件は本文か請求書に「月末締め翌月末払い」「30日サイト」と書かれています。

| 書いてある言い方 | `payment_terms_days` | 補足 |
|---|---|---|
| 当月末払い | `0` | |
| 30日サイト / 30日後 | `30` | |
| 翌月末払い | **渡さない** | 月によって日数が変わるので日数では表せない。`processing_month` だけ渡し、期日は人が決める |
| 書いていない | 渡さない | |

`processing_month` は「何月分の費用か」。書いていなければ**受信日の月**が既定です。

## 添付（PDF）— **中身ではなく在り処を渡す**

⚠️ **Gmail コネクタは添付の中身を返しません。** `get_message` が返すのは

```
attachments: [{ filename: '請求書.pdf', id: 'ANGjdJ9…', mimeType: 'application/pdf' }]
```

の**名前と id だけ**です（`FULL_CONTENT` で呼んでも同じ。実測で確認済み）。
**サーバーが Gmail API から取りに行く**ので、在り処をそのまま渡してください。

```
attachments = [{
  filename: '請求書_202608.pdf',
  mime_type: 'application/pdf',
  gmail_message_id: '<get_message で見たメールの id>',
  gmail_attachment_id: '<attachments[].id>',
}]
```

- ⚠️ **`gmail_attachment_id` は呼ぶたびに変わります。** 同じ添付を2回引くと別の文字列が
  返ります（実測）。**その場で取った新しいものを渡すこと** — 保存して後で使えません。
- **請求書の PDF は原本です。必ず渡してください。**
  渡さないと ONAiR には金額だけが残り、原本はメールボックスの中だけになります。
- 受け取れるのは `pdf / png / jpg / jpeg / xlsx / xls / csv / zip`、**1ファイル 10MB まで**、
  1通あたり 10個まで。超えたものは理由付きで記録だけ残ります。
- BOX の **「受領書類（メール）」フォルダ / 受信月** に入ります。
- 戻り値の `attachments[].stored` が `false` のときは `failure_reason` が付きます:

  | 理由 | 意味・どうするか |
  |---|---|
  | `NO_GMAIL_SCOPE` | Gmail の読み取りが許可されていない。**人が設定画面から Google 連携をやり直す**必要がある。**報告に必ず書く** |
  | `NO_GMAIL_ACCESS` | Google 連携が無い環境（検証・手元）。そのままでよい |
  | `GMAIL_UNAVAILABLE` | Gmail が応答しなかった。次の実行で拾い直せる |
  | `NOT_CONFIGURED` | BOX につないでいない環境。そのままでよい |
  | `TOO_LARGE` / `BAD_TYPE` | 10MB 超・受け取らない種類。人が BOX に手で置く |

  **`content_base64` は、手元にバイト列があるときだけ**使います
  （Gmail コネクタ経由の取込では使いません）。

### パスワード別送（PPAP）

`[パスワード通知] …` という**同じ件名の続きのメール**が必ず来ます。

- **パスワードのメールは `record_finance_doc` に入れません**（中身が無いので）。
- 元の請求書メールの `notes` に「パスワードは別送メールにあります」と書いてください。
- **パスワードそのものを ONAiR に書かないこと。**

## 取り込む前に確かめる

```
list_finance_doc_groups(pending=true)
```

**同じ取引の続きが既に入っていないか**を見ます。入っていればその `group_key` を使います。

## 見積書も必ず入れる

以前は「台帳に入るのは請求書だけ」として見積書を落としていましたが、**入れてください**。
見積だけで終わった取引も画面に残り、あとで「あの見積どうなった」を引けます。
台帳（仕入・販管費）に入らないのは変わりません — 画面がそう言います。
