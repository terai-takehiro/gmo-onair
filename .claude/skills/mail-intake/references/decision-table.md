## #4 お問い合わせの分け方（**全部が案件ではない**）

同じ問い合わせフォームに **スタジオを使いたい人** と **当社に売り込みたい人** の両方が来ます
（実測: 1か月20件のうち、AI 企業のサービス紹介・協業打診・見学依頼が混ざっていた）。
**案件の受付に送るのは「スタジオの利用の問い合わせ」だけ**です（ご指示）。

本文の `[お問い合わせ種別]` と `[お問い合わせ内容]` で分けます。

| 読み取れたもの | 行き先 |
|---|---|
| 空き状況の確認 / 見積依頼 / 収録・配信・イベントをやりたい / 会場を探している ／ **日付・人数・予算が書いてある** | `create_project`(stage=neta) ＋ `create_activity_log` |
| 見学したい / 内覧したい | `record_inquiry`(tags=[見学]) |
| 取材したい / 掲載したい | `record_inquiry`(tags=[取材, メディア掲載]) |
| 協業・提携の打診 / サービスの紹介 / 代理店のお誘い | `record_inquiry`(tags=[協業]) — **案件にしない** |
| 採用・求人 | `record_inquiry`(tags=[採用]) |
| 読み取れない | `record_inquiry`(tags=[その他]) |

**見分け方の芯は「当社の会場・技術を使いたい側か、当社に何かを売りたい側か」**です。
`[お問い合わせ対象の会場]` に会場名が入っていて、内容に**日付か人数か用途**が
書いてあれば利用の問い合わせです。会場名が `その他・分からない` で、
内容が自社サービスの説明から始まるものは売り込みです。

⚠️ **迷ったら `record_inquiry`。** 案件は人が受付から1タップで作れますが、
AI が作った案件は間違っていても失注として履歴に残り続けます。

本文の `[資料ダウンロードの目的を教えてください]` で分けます。

## #7 営業スレッドの扱い

`Cc: sales@` に入っている人の往復です。件名は
`【◯◯の件】GMOサムライスタジオ／担当者名` か `Re: お問い合わせいただいた件につきまして【…】`。

1. **見積・請求・注文の話なら #6 が先に当たります**（決定表は上から順）。
   見積書の PDF が付いていれば受領書類です。**金額を仕入としてここで作らないこと** —
   どの案件かは人が受領書類の画面で決めます（ご指示）。
2. それ以外は、`list_projects` で件名・取引先名から案件を探します。
   - **見つかった** → `create_activity_log`（`project_id` を付けて）。
     **次にやることが書いてあれば `next_action` と `next_action_due` を付ける** —
     これが案件管理のタスクになり、期限が来ると人に出ます
   - **見つからない** → `record_inquiry`。**ここで案件を新しく作らないこと** —
     既にある案件のやり取りを新しい案件として起こすと、同じ話が2件になります。
     人が画面で「チケットにする」を押せば案件管理のタスクになります

## 日程が明確なものには `予定候補` タグも足す（フェーズ1・2026-09）

`record_inquiry` に入れる用件（#7〜#9・#12）のうち、**具体的な日付・場所が
書かれていて、スタジオの予定表に登録すべきと読めるもの**（現地調査・入室予定・
搬入出予定・下見の日程など）には、他のタグに加えて `予定候補` も付けてください。

- 例: 東急PM・世田谷ビジネススクエアからの入室予定日・現地調査の連絡（#8）、
  営業スレッドで日程が決まった空き状況の確認（#7）
- **予約は作りません。** `create_studio_booking` は呼ばない — 部屋の選定・
  細かい調整は人が判断するもので、AI が確信を持てる情報ではありません
  （実装の是非は `.claude/skills/ai-feedback-loop/` で監査済み・2026-09。
  条件1〜5が整うまでは直接書き込みをしない判断）
- タグを足すだけで、「入ってきた情報」一覧が該当行を目立たせ、
  「カレンダーに登録する」ボタンを強調します（`client-daily/src/pages/inquiries/`）。
  **判断はそこでも人が行います** — このタグは「見てほしい」の合図であって、
  行き先を決めるものではありません
- 日付が無い／確定していない相談段階のものには付けないこと
  （「予定候補」が付いているのに登録できる日付が無いと、押した人が戸惑います）

## 迷ったときの原則

- **「捨てる」に迷ったら `record_inquiry` に入れる。** 入れたものは人が1タップで
  見送りにできますが、**捨てたものは誰の目にも触れません**。
- **「案件にする」に迷ったら `record_inquiry` に入れる。** 案件は人が受付から作れます。
  AI が作った案件は、間違っていても失注として履歴に残り続けます。
- **`importance=high` は「今日中に人が動かないと困るもの」だけ。**
  期日のある依頼・脆弱性・支払期限が近い請求書。それ以外は `medium` か `low`。
