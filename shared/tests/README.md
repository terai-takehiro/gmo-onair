# shared のテスト

**`src/` の外に置いてある。理由がある。**

各アプリの `tailwind.config.ts` の `content` は `../shared/src/client/**` を含むので、
**`src/` の中に置いたテストのクラス名まで CSS として生成される**。
実際に `cn('rounded-md','rounded-card')` というテストを1本書いたところ、
使っていない `rounded-card` / `rounded-badge` / `rounded-control` / `text-h1` の規則が
**凍結4アプリの CSS にも増えた**（ビルド出力の突き合わせで発見）。

`content` の否定パターンで外す手もあるが、`'!../shared/**/*.test.{ts,tsx}'` という
**shared からの相対パスで7アプリすべてに書く**必要があり（`'!**/*.test.*'` では効かない）、
1つ書き忘れるとそのアプリだけ静かに元に戻る。**置き場所を分けるほうが破れない。**

## 何をテストするか

**画面を見ても間違いに気づけない計算だけ**（`docs/v4-plan.md`「自動テストについて」）。
73画面ぶんのテストは書かない。いまあるのは:

| ファイル | 何を固定しているか |
| --- | --- |
| `numbers.test.ts` | 万円の丸め（負の数・`¥-0万` を出さない・0 と未入力の区別） |
| `utils.test.ts` | `cn()` の打ち消し（v4 の型スケール・角丸が組み込みの `text-*` / `rounded-*` を上書きできること） |
| `queryClient.test.ts` | **保存が黙って失敗しないこと**（MutationCache の受け皿が、画面が `onError` を持つときは黙り、持たないときだけ帯を出すこと） |
| `dueDate.test.ts` | **支払期日の逆算**（締め日を過ぎた売上は翌月の締め・2月に31日は無いので末日へ丸める・取引先の例外の重ね方） |
| `discountLimit.test.ts` | **値引きの上限**（率と額の両方・小計 0 で値引きだけを素通りさせない・`0％` と「上限なし」の区別） |
| `holidays.test.ts` | **祝日の計算**（ハッピーマンデー・春分秋分の近似式・振替休日・国民の休日）。件数は**1件ずつ曜日を数えて確かめた実数**で固定（緩い範囲で通さない） |
| `businessHours.test.ts` | **営業時間の外か**（境目・日をまたぐ予約・休業日が営業時間より強い・`open` の祝日は無視・読めない値では止めない） |

### server のコードもここからテストしてよい

`dueDate.test.ts` / `discountLimit.test.ts` は
**`../../server/src/shared/services/` を直接 import しています。**

この製品は **server が `shared/` を import しない構成**（`tsconfig` の `rootDir` が
`server/src` なので、跨ぐと型チェックが落ちる）です。かといって画面側にも同じ計算を
置くと**写しが2つ**になるので、**計算は server に1本だけ置き、画面はサーバーに訊く**
形にしました（お金のルールの「試すと何日になるか」がそれ）。

テストの側は Vitest なので `rootDir` の制約が無く、server のファイルをそのまま読めます。
**純粋関数（DB も HTTP も触らない）に限ること** — 触るものを入れると
`npm test` に DB が要るようになり、2 秒で終わる約束が壊れます。

`queryClient.test.ts` は特に「間違っても何も起きない」種類のコードを固定しています。
`onError` の引数の並びを1つずらすと**常に黙る**ようになり、元の不具合と見分けが付きません
（実際に並びをずらして4件落ちることを確認済み）。

実行: `npm test`（ルート）または `npm run test -w shared`
