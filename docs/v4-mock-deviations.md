# モックと実装の違い（v4）

モック（`docs/design/v4/mockups/`）に描いてあるのに**作らなかった／別の形にした**ものの一覧です。
レビューのときに「やり忘れ」と「そう決めた」を区別できるようにするためのものです。

## 違う理由は3つしかありません

| 印 | 理由 | 意味 |
| --- | --- | --- |
| 🗄 | **データが無い** | DB に列やテーブルが無く、出すと**作り話**になる |
| 🔌 | **動く先が無い** | サーバー側の実装が無く、置くと**押しても何も起きないボタン**になる |
| ⚖️ | **別の判断をした** | データも実装もあるが、実データ・用語の決めごと・業務の実態に合わせて変えた |

**🗄 と 🔌 は「作れるのに作っていない」ではありません。** どちらも
「無いものを、あるように見せない」という v4 の一貫した方針によるものです。
出すためには**データ設計か業務の決めごと**が先に要ります。

## 共通・トップページ

| | モックの予定 | 実装 | なぜ |
| --- | --- | --- | --- |
| ⚖️ | 凍結4アプリ（制作資料・技術資料・計時LIVE・リアルタイムCG）をアプリ一覧から外す | **残した** | プラン承認時は「外す」でしたが、モックは制作資料・技術資料を並びに残し、計時LIVE とリアルタイムCG を「イベントで使うもの」の列に置いています。4つとも今日使える画面で、消すと**URL を覚えている人しか開けなくなる**ため（**「検証環境なので消さなくてよい」とご判断いただきました。本番に出す前にもう一度確認します**） |
| 🔌 | 受付カードは3タイル（メール取込・録音・手で登録） | **動く2つだけ** | **録音がまだありません。** 押しても何も起きないボタンを置くと「壊れている」と受け取られ、以後この枠全体が信用されなくなります |

## 案件管理

| | モックの予定 | 実装 | なぜ |
| --- | --- | --- | --- |
| 🗄 | ダッシュボードに「今月の受注」 | **「今月の売上（確定）」** | **DB がステージの変更日を記録していません。** `projects.updated_at` は名前を直しただけでも動くので、「今月 受注になった案件」を数えられません。履歴を残すようにしたら差し替えます |
| 🗄 | 「見積を送ったまま連絡がありません」のような**具体的な停滞理由** | **ステージから導いた一般的な文言** | 具体的に言うにはステージ変更の履歴が要ります。**作り話をしない** |
| 🗄 | ネタ一覧に「入口（メール／電話）」と「確信（高／中／低）」の列 | **出していない** | どちらも DB に列がありません。MCP の `create_project` も確信度を渡しません。代わりに**「必須なのに空」を赤で名指し**しています |
| ⚖️ | 受付は引き合い（メール・電話）だけ | **4種類のまま** | この受信箱は「お客様を待たせているもの」を集める別の目的で既に使われており、片方を消すと**期限超過のアクションを見る場所が無くなります** |
| ⚖️ | ネタを「E 問合せ」に改名 | **「ネタ」のまま** | 社内で定着している呼び方です |
| ⚖️ | 「D 仮押さえ」を灰色 | **淡い青** | 灰色だと「終わったもの」に見えます（仮押さえは生きている案件） |
| ⚖️ | タブ名「エピソード」 | **「回」** | `docs/wording.md` の用語の決めごと（`check-ui-tokens` が画面に出る「エピソード」を弾きます）。**用語の決めごとを優先しました** |
| ⚖️ | 案件詳細に「請求」タブは無い | **見積タブを「見積・請求」にした** | 案件を開いている人が請求額を探しに行かずに済むほうを取りました（ご判断） |
| ⚖️ | PC サイドバーに「受付」が無い | **メニューに出した** | 毎日開く画面なので、ダッシュボードのカード経由だけだと遠回りになります（ご判断） |
| 🗄 | 料金表を**拠点ごと**に持ち、案件の場所に応じた表が見積に出る | **1つの表のまま** | `pricing_categories` に場所の列がありません。足すと ①テーブルの作り替え ②見積の積算と MCP が「どの場所の表か」を持つ ③既存78品目の割り当ての決め、が同時に要ります |
| 🗄 | 料金表の「変更の記録」パネル | **載せていない** | 履歴テーブルが無く、出せる中身がありません |
| ⚖️ | 案件をつくるのは**全画面モーダル1枚（16項目）** | **いままでのフォーム画面のまま**（分割はした） | モーダルの16項目のうち**6項目は DB に列がありません**（ご担当・継続区分・規模・やりたいこと・返事の期限・求められているもの）。枠の入れ替えと中身の作り直しを同じ回でやると切り分けられなくなるので、**まず不具合を直して分割**しました |
| ⚖️ | タグ／案件種類（その他）／教訓・学び を**欄ごと消す** | **残した** | 既存データが入っている可能性があります。**消す判断は業務の決めごとなので確認してから**（→ ご判断ください） |
| ⚖️ | GLS 番号は「受注が決まったときに自動で採る」 | **いままでどおり手で発番** | 番号を採る時期が変わるのは**業務の変更**です（→ ご判断ください） |
| 🔌 | ⑦ 標準工程テンプレート | **未着手** | **社内で工程を整理中のため後回し**（ご判断）。スタジオ案件とプロジェクトで工程がまったく別なので、テンプレートは2系統つくります |

## 財務管理（8画面すべて v4 になりました）

| | モックの予定 | 実装 | なぜ |
| --- | --- | --- | --- |
| 🗄 | 取り込みの行ごとに **AI の読み取り信頼度 %**（98% / 74%・80未満は橙） | **出していない** | 解析は正規表現のパーサで、**スコアという概念がありません**。モックのサンプル値はベタ書きです。それらしい数字を置くと、他の画面で守っている「数えられないものを出さない」をここだけ破ることになります。代わりに**警告の中身**をそのまま出しています |
| ⚖️ | 「BOXに置く必要はありません」と書く | **書かない** | 解析は Box の抽出テキストを読む一本道で、**直接アップロードも Box に保存してから解析します**。Box が使えない日はどちらも動かないので、書くとその日に「壊れた」と言われます |
| 🗄 | 販管費を**勘定科目**（通信費／地代家賃／旅費交通費）で絞る | **固定費／都度・社員／経理 で絞る** | `sga_expenses` に勘定科目の列がありません。持っている軸だけを出し、無い理由を画面に書いています |
| 🗄 | 取引先ごとの**取引額** | **出していない** | 期間の取り方（今年度／直近12か月／全期間）が決まっていません。仕入先だけは既存の「仕入先集計」へ送るボタンを置きました |
| 🗄 | 請求書番号 | **採番していない** | `revenues` に列が無く、①連番の単位 ②取り消したときの扱い ③いま経理が使っている番号との突き合わせ を決める必要があります。**勝手に採番すると会計側の番号と二重になります**。画面に明記しました |

### モックのほうが正しかったので直したもの

| モック | それまでの実装 | 直した内容 |
| --- | --- | --- |
| 「受け取った書類」は**財務**にある | **日常業務**にあった | `dailyops` 権限だけを要求していたので**経理が開けませんでした**（実測で 403）。中身は 金額・締月・支払期日・GLS番号 で完全に経理の道具です。財務に移し、`budget` か `dailyops` のどちらかで通るようにしました（`/daily/finance` は転送で生かしています） |
| 取り込みは**1画面3タブ** | **3つの別画面** | やることは全部同じ（外の数字を読む → 確かめる → 台帳に入れる）なのに、手順の見せ方も結果の出し方も確認の訊き方もバラバラでした |

## 日常業務

| | モックの予定 | 実装 | なぜ |
| --- | --- | --- | --- |
| 🔌 | デイリーニュースに「採用した行を週報に送る」ボタン | **出していない** | サーバーに口が無く、由来を残す列もありません。画面に「自動では送られません」と書いています |
| 🗄 | 週報トピックの「ニュース由来」バッジ | **出していない** | `ops_report_items.source` は `ai` / `human` の2値だけで、どこから来た行かを記録する列がありません |
| ⚖️ | セキュリティカードのレベルを**3分類**（全域 No.1-4 ／ 技術 No.5-14 ／ 共用 No.15-24） | **DB の6レベルのまま** | モックのレベル帯は**実データと一致しません**（DB は master が No.1-9 で10エリア、meeting は No.19-21 で1エリア）。3つに畳むと ROOM A と ROOM B が同じに見え、**違う部屋のカードを渡す**ことになります |
| 🗄 | 入ってきた情報に **出どころ（mail／slack／phone／talk）・4段階の状態（未仕分け／ストック／チケット／見送り）・タグの配列・チケット（案件管理のタスク）連携** | **重要度と対応済みかだけ** | どれも `misc_inquiries` に列がありません。作るなら**AI の取込側（MCP と本番スキル）も同時に直す**必要があり、画面の作り直しより規模が大きくなります。無い理由を画面に書いています |
| ⚖️ | セキュリティカードに「アクセス表」タブは無い | **タブをやめて右パネルに畳んだ** | 実装には3タブ（カード／貸出履歴／アクセス表）がありました。開けられる部屋は**選んだ1枚の情報**なので、タブではなく右に集約しています |

## 機材管理（16画面 → 8画面）

| | モックの予定 | 実装 | なぜ |
| --- | --- | --- | --- |
| ⚖️ | 機材台帳は**3タブ**（機材／貸出機材／**ケーブル・コネクタで1つ**） | **4タブ**（ケーブルとコネクタを分けた） | 両者は別テーブルで、**ケーブルにしか無い列が2つ**あります（長さ・色）。1つにするとコネクタ行に空列が並びます |
| 🗄 | 設定「貸出の決めごと」の**6つのスイッチ**（返却予定日の初期値／遅延を知らせるタイミング／社外貸出の可否／承認の要否／QRから貸出返却／修理中は貸出不可） | **出していない**（6つを画面に列挙して「保存する場所がまだありません」と書いた） | **保存先が DB にありません。** 押しても次に開くと戻ります。代わりに実際に効く「貸出可の切り替え」をこのタブに置きました |
| 🗄 | ダッシュボードに「本日・明日の入出庫」 | **「返してもらう」（返却予定日ベース）** | `equipment_lendings` は**持ち出した瞬間の記録**で、「これから出す予定」を持っていません |
| 🗄 | QRスキャンの**読み取り履歴**と、その場で貸出・返却 | **出していない** | 読み取りを残すテーブルがありません。画面に明記しました |
| ⚖️ | 機材台帳の列に「貸出可」チェック | **設定タブに置いた** | 書き込みに `equipment` の **owner 権限**が要るので、台帳に出すと大多数が押して 403 になります |
| ⚖️ | ラック図も v4 の見た目に | **意図して据え置き** | 1,502行に 座標計算・印刷・棚卸しモード が同居しており、**触ると印刷が1ページ目で切れます**。分割しても印刷が壊れないことを実機で確かめてから |

### v4 で外した既存機能（モックにも無いもの・要判断）

- **ケーブル／コネクタの「表示列の出し入れ」と「表編集」** — 列の並びが人ごとに違うと口頭で通じず、
  7段の列幅とも噛み合いません。数の一括更新は Excel 取込に寄せ、その旨を画面とマニュアルに書いています。
  **機材タブでは両方とも残しています**（カスタム列があるため）

## プロジェクト管理（新規）

| | モックの予定 | 実装 | なぜ |
| --- | --- | --- | --- |
| 🗄 | ⑥ 見積・請求（提出先＝自社／依頼元／PM会社 を持つ） | **作っていない** | `estimates.project_id` が `NOT NULL REFERENCES projects(id)` なので、**自社構築のプロジェクトは見積を1枚も持てません**。「提出先」に相当する列も 0 件。足すとサーバー12か所・画面4か所（案件詳細の見積タブ・見積請求一覧・案件ダッシュボードの KPI）に同時に効く**見積のデータ設計の変更**になります（→ ご判断ください） |
| 🗄 | ダッシュボードの KPI **5枚** | **3枚** | 「個別見積 未提出」「検収待ち」は上と同じ理由で数えられません。**枠ごと出さず**、出していない理由を画面に書いています |
| 🗄 | ⑤ 全プロジェクトの**タスク一覧** | **「未確認事項」＋「プロジェクトごとの次の1件」** | GPM のタスクは `project_tasks` に紐づきますが `project_id` が NULL で、既存の一覧・かんばん・ガント・MCP はすべて `JOIN projects` するので**1件も返りません**。タブ名で期待させないよう「次にやること」にしました |
| ⚖️ | ③ 詳細に**体制図**（発注者／PM会社／自社 のボックス図） | **一覧にした（読むだけ）** | 組織図の描画は別の仕事です。また `gpm_members` に**書き込む API がありません**（入れる口が無いことを画面に書いています） |
| ⚖️ | ④ 新規作成は**5段** | **3段** | 4段目（体制＝組織図）と5段目（メンバー・書類）は上記の理由で置けません |
| ⚖️ | BOX のサブフォルダ構成（個別見積／原価・発注／議事メモ／図面／仕様書／工程表） | **作らない** | 既存の `box-folder.service.ts` の構成と食い違います。**本番の BOX に実際にフォルダができる**ので、間違えると人手で消すことになります |
| ⚖️ | モックの色（`#a6ceeb` など生の色コード） | **トークンに写した** | 生の色コードは `check-ui-tokens` が弾きます（色を切り替えたときにここだけ取り残されるため） |

## この一覧の使い方

- **🗄 と 🔌 を作るには、先に「データをどう持つか」か「業務としてどう決めるか」が要ります。**
  画面だけ先に作ることはできません（作ると数字が嘘になります）
- **⚖️ は作り直せます。** 判断を変えたいものがあれば言ってください
- モックそのものは `docs/design/v4/mockups/` にあります。画面ごとの項目名は
  `docs/design/v4/*.md`（生成物）を見てください
