## ① モックどおりにすると実害が出る4件（ここだけ止めます）

判断をいただくまで実装しません。**それ以外はモックに合わせて進めます。**

### 1. セキュリティカードのレベルを3分類に畳む — **違う部屋のカードを渡すことになります**

モックは「全域 No.1-4 ／ 技術 No.5-14 ／ 共用 No.15-24」の3分類ですが、
**この帯は本番の実データと一致していません**（実測）。

| モックの帯 | 実データ |
| --- | --- |
| 全域 = No.1-4 | `master` は **No.1-9**・入れる部屋 **10** |
| 共用 = No.15-24 | `meeting` は **No.19-21**・入れる部屋 **1** |

6レベルを3つに畳むと、**ROOM A のカードと ROOM B のカードが画面上で同じに見えます**。
セキュリティカードは実物を人に手渡す運用なので、**入れない部屋のカードを渡す**か、
**入れてはいけない部屋に入れるカードを渡す**ことになります。

- **推奨**: レベルは DB の6段のまま。**モックの3分類は「絞り込みの束ね方」として採用**し、
  カード1枚の表示は実際のレベル名と部屋数を出す（見た目はモックどおりにできます）
- モックの帯どおりに畳むご判断なら、**先に台帳側の番号とレベルを実運用に合わせて振り直す**必要があります

### 2. 請求書番号の自動採番 — **会計側の番号と二重になります**

`revenues` に請求書番号の列がありません。採番を始める前に3つ決める必要があります。

- **連番の単位**（年度ごと／月ごと／通し／拠点ごと）
- **取り消したときの扱い**（欠番にする／詰める）
- **いま経理が使っている番号との突き合わせ**（既存の請求書に付いている番号をどう扱うか）

決めずに採番すると、**同じ請求書に ONAiR の番号と会計システムの番号が2つ付きます**。
入金消込は番号で突き合わせるので、ここがずれると**入金が消し込めなくなります**。

- **推奨**: ①年度ごとの通し ②取り消しは欠番（詰めると過去の請求書と食い違う）
  ③既存分は空のままにして、新規発行分から採る。この3点でよければ実装します

### 3. GLS 番号を「受注が決まったら自動で採る」 — **押し間違いで番号が焼けます**

いまは `POST /projects/:id/issue-gls` を人が明示的に叩きます。モックどおり
ステージが `a_won` になった瞬間に採ると、**ステージを押し間違えただけで番号が消費されます**。
GLS 番号は BOX のフォルダ名・Qシート・請求書に載るので、**取り消しても番号は戻せません**。

- **推奨**: 自動採番にするが、**`a_won` に上げるときの確認ダイアログに「GLS番号 GLS◯◯◯ を採ります」と出す**。
  モックの「自動」を満たしつつ、押し間違いは止まります
- 「発番済みの案件を `a_won` から戻した場合」の扱いも決めが要ります（番号は保持する想定）

### 4. プロジェクト管理の BOX サブフォルダ — **本番の BOX に実物のフォルダができます**

モックは 個別見積／原価・発注／議事メモ／図面／仕様書／工程表 の6フォルダですが、
既存の `box-folder.service.ts` は案件用の別構成（01_見積・提案 …）を作ります。
**BOX に作ったフォルダは人が手で消すしかありません**（アプリからは消せない）。

- **推奨**: プロジェクト用のフォルダ構成として**別に定義**し（案件用と混ぜない）、
  **検証環境の BOX で1件作って中身を確認してから**本番に出す
- 命名（プロジェクト番号の形）も先に決めが要ります
