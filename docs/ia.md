# 情報設計 (IA) — 刷新前の事実と、刷新後の入口

UI/UX 刷新 (v2.9.251〜) の合意事項。**「入口は1つ」を判定するための基準表**。
新しいメニューを足したくなったら、まずこの表のどのレールに入るかを決める。入らないなら足さない。

### レールに出さないもの

現場ツール (Qシート・技術資料・機材・計時LIVE・リアルタイムCG・翻訳・インタラクティブ) は
**レールに出さない**。到達経路は次の3つ:

1. **案件から開く (既定)** — 案件のタブ。開いた時点で案件・イベント・言語が入っている
2. **単発で開く** — ⌘K から。案件欄は空のまま進められる
3. **後から紐づける** — 単発の成果物は「まだ案件に紐づいていないもの」に残り、後で案件に付ける

`DbBackupsPage` の `data?.environments.map`)。あわせて案件ワークスペースの
`simulationData?.data` を `Array.isArray` で守った (配列でないものが来ると `reduce` で落ちる)。

⌘K は**同じ行き先の項目を2つ並べない**方針にした。`/tools` の2項目は
1つに統合してキーワードで拾い、「チームの負荷」は `#team-load` まで送る

### 朝の1通を Slack に送る (v2.9.268)

**設定画面が約束していることをサーバーが守っていない**唯一の箇所だったので閉じた
(`user_notification_prefs` は保存されていたが、読む側がいなかった)。

- **個人への DM** と **チャンネルへの投稿**は**中身を分ける**。個人 DM に全社の話を混ぜると
  読み飛ばされ、チャンネルに個人の ToDo を流すと自分の行を探す作業になる
- チャンネルは **1件 = 1回の投稿**。同じチャンネルを何本でも登録できるので
  「朝は今日の現場・夕方は終わったこと」と**時刻ごとに内容を変えられる**
- 出す内容は 10 種から選ぶ。**中身が0件の項目は本文に出さない**
- **金額のブロックだけ扱いが違う**: 選ぶと「このチャンネルにいる全員に見える = 権限の外に出る」
  と画面に赤く出す。止めはしないが黙っては通さない。**個人名は出さない**
- **送る前に本文を読める** (「本文を確認する」)。全社に出るものなので、これが無いと初回が事故る
- 時刻を過ぎてから起きたときは **1時間以内なら追いかけ、それより遅ければ送らない**
  (朝の内容が夜に届くほうが困る)

### 見積・請求の原本を開く (v2.9.269)

承認画面が**原本を見ずに金額を承認する**画面だったのを直した
(`finance_docs` は AI が読み取ったテキストだけを持ち、PDF の実体を指す列が無かった)。

- **ブラウザから落とす**形にした。運用者に Box のフォルダ ID を調べさせない —
  社内限りの親フォルダの下に `00_受信した請求書` が無ければ**サーバーが作る**
- 実体は **Box に置く**。サーバーのディスクに置くと再デプロイで消える
  (リアルタイムCG の画像で実際に起きた = v2.9.50)
- **原本は読み取り値より上**に置く。金額を承認する画面なので、先に原本を見る順にする
- **PDF は画面内にそのまま表示**する (承認しながら読めないと意味がない)。
  表示できない端末では「別のタブで開く」に落ちる
- **写真 (JPEG/PNG) も通す** — 請求書は撮った写真で回ってくる。
  ただし文字は読み取らないので「目で確かめてください」と書く
- **PDF を落とすと行そのものを作れる** (メールが無い請求書)。下読みできた値はフォームに埋め、
  読めなかった項目は空 + 注意にする。**読めないことをエラーにしない**
- 差し替えても **Box の前のファイルは消さない** (差し替えの記録が要る書類)
- 種別は中身のマジックバイトで見る (拡張子と Content-Type は名乗りなので信じない)

まだ残しているもの (理由つき):

| 見送ったもの | 理由 |
| --- | --- |
| 案件内タブ (概要・やり取り・お金…) | いまはクイックリンクで各アプリに飛ぶ。タブにすると1画面の担当範囲が広がりすぎる |
| Qシートのマスターの `/settings` 移設 | `doc.data` 内の**その台本のための設定**で全社共通のマスターではない (立ち位置図は番組固有) |
| 朝の1通のメール送信 | Slack は繋いだがメールの送信経路はまだ無い。`morning_email` は保存だけしている |
| 権限の変更履歴 (誰が変えたか) | 監査テーブルを持っていない。「いつ」だけ出し、持っていないことを画面に書いた |
| 問い合わせの返信の下書き | AI 経路が必要。読んで返すのは人の仕事のままにしている |
| メールの添付を AI が自動で原本にする | 先に人の手で動く形を作った。同じフォルダ・同じ列なので、AI 側を繋ぐだけで後から自動化できる |
| 案件の内容そのものの同時編集 | 409 で**上書きを止める**ところまで。同じ欄を2人で同時に打てるようにするのは Yjs をこの画面に載せる話で別 |

### Phase 8 (v2.9.262) — 済

**お金**: KPI 7 枚を並べるのをやめ、カードの間に `−` と `=` を置いた**損益の流れ**にした。
関係を注釈文で説明していたのを、並びそのものが関係を表す形に。

| 表示 | URL | 用途 |
| --- | --- | --- |
| 損益の流れ (既定) | `/finance` | 日常。数字はクリックで明細へ |
| 3列レビュー | `/finance?view=review3col` | 財務MTG。合計+件数つき3列 + 「MTG用に出す」で A4 横印刷 |

**取込の1本道** (`/finance/import`): 「取り込む → 確認する → 登録する」の3ステップの枠の中で
取込元を選ぶ (`?tool=xpoint|kessan|dedup`)。既存3ページに `embedded` を足して、
枠のステップ表示と自前の見出しが二重にならないようにした。
決算CSVと二重計上は**管理者だけに出す** (日常のメニューには置かない)。

**入口を2つのままにした理由**: 精算PDFは画面に直接アップロードできるが、決算CSVは

### Phase 12 (v2.9.266) — 済

設定と権限 (20a/20b) + ふりかえり (21a/21b) + 現場の道具 (12a)。

**この人にできること** (`/settings/users/:id`): 10モジュール × 4段階のプルダウンを1つずつ選ぶ
ダイアログをやめ、**役割テンプレート (営業 / 制作・技術 / 外部パートナー / 経理 / 管理者) を先に当てて
必要な行だけ直す**形にした。運用は職種で決まっているのに毎回手で当てていたため、
人によって微妙に違う権限ができ「なぜこの人だけ見えないのか」が後から分からなくなっていた。
右に **その設定で見えるレール**を出す (下書きの状態で出るので、保存前に結果を確かめられる)。
4段階の表示名 (見えない / 見るだけ / 書ける / 任せる) は DB の `reader/editor/manager` と 1:1、
旧値 `exporter`/`owner` は表示時に寄せる。

**変更履歴は「いつ」だけ**。`user_permissions.updated_at` を GET に足して行ごとに出す。
**誰が変えたかは記録していない**ので、画面にそう書いた (監査テーブルは作らなかった)。

**ふりかえり** (`/review?tab=week|keep|pl|sales`): 報告資料 / 営業レビュー / 日常業務の週次 の3つに
分かれていた「終わったことを見る画面」を1つに。**レールには出さず**、⌘K と お金 の画面から辿る。
`/sales/keep-report` と `/sales/review` は `RedirectPreserveState` でここへ寄せた。

**今週は件数より割合を先に出す** (`GET /dailyops/weekly-stats` に `quality` を追加):
今週が期限だったタスクの 期限内 / 遅れ / 未完了 と期限内完了率、AI の無修正採用率
(既存 `getFeedbackDigest` から借りる — 同じ数字を2か所で計算しない)。
期限は `due_at` を正とし旧 `due_date` はその日の 18:00 として読む (v2.9.244 の決めごと)。
**完了フラグが立っていて完了時刻が無い行は「遅れ」に数える** (安全側)。

**現場の道具** (`/tools` + 案件のカード / migration 138 `external_tool_outputs`):
翻訳・インタラクティブ・CG は 案件から開く / 単発で開く / 後から紐づける の3通りで使われる。
案件を必須にすると入口の摩擦になり、何も残さないと「あの翻訳どこ行った」になるので、
**メタだけ** (種類・題名・外部URL・作った人・案件は nullable) を残す。
「社内利用」を押したものは以後案件を求めない (`is_internal_use`)。
**中身 (翻訳文・演出データ) は各ツール側にあり複製しない** — 二重に持つとどちらが新しいか分からなくなる。
外部ツールに案件やイベントを流し込むことはできないので、**できるのは「この案件で使った」を残すことまで**
と画面に書いた。

## 4. 壊してはいけないもの

刷新の途中で URL や契約を変えると現場が止まる。次は**フェーズをまたいで維持する**:

- 既存URL (仕様書 §3.3 のリダイレクト表。削除せず残す)
- ICSフィードのURLとトークン (`studio_calendar_settings`)
- 音声サポートの公開URL (`/qsheet/audio/:docId` — 認証なしで開く)
- サイネージURL (`/signage/:roomId`)
- MCPのエンドポイントとツール名 (`/api/v1/mcp`・82種)
- 金額は税抜保持 / `billing_key` の採番規則 / GLS採番の `ON CONFLICT` 原子性
- 権限判定 (`hasPermission` と `LEVEL_ORDER`) と、案件メンバーによる可視判定 (権限とは別軸)
  - 正確には **2段**: モジュール権限で「どのアプリを触れるか」を決め、そのうえで案件メンバーが
    「どの案件のものが見えるか」を広げる。Qシートは `requirePermission('qsheet')` が先に効くので、
    **案件メンバーでも qsheet 権限が無ければ開けない** (メンバーであることは共有設定の代わりになるだけ)。
    自分に割り当てられたタスクは `sales` 権限が無くても返す (金額は返さない)。
