### レールに出さないもの

現場ツール (Qシート・技術資料・機材・計時LIVE・リアルタイムCG・翻訳・インタラクティブ) は
**レールに出さない**。到達経路は次の3つ:

1. **案件から開く (既定)** — 案件のタブ。開いた時点で案件・イベント・言語が入っている
2. **単発で開く** — ⌘K から。案件欄は空のまま進められる
3. **後から紐づける** — 単発の成果物は「まだ案件に紐づいていないもの」に残り、後で案件に付ける

⌘K は**同じ行き先の項目を2つ並べない**方針にした。`/tools` の2項目は

### 朝の1通を Slack に送る (v2.9.268)

**設定画面が約束していることをサーバーが守っていない**唯一の箇所だったので閉じた
(`user_notification_prefs` は保存されていたが、読む側がいなかった)。

- **個人への DM** と **チャンネルへの投稿**は**中身を分ける**。個人 DM に全社の話を混ぜると
  読み飛ばされ、チャンネルに個人の ToDo を流すと自分の行を探す作業になる
- チャンネルは **1件 = 1回の投稿**。同じチャンネルを何本でも登録できるので
  「朝は今日の現場・夕方は終わったこと」と**時刻ごとに内容を変えられる**
- 出す内容は 10 種から選ぶ。**中身が0件の項目は本文に出さない**
- **金額のブロックだけ扱いが違う**: 選ぶと「このチャンネルにいる全員に見える = 権限の外に出る」
  と画面に赤く出す。止めはしないが黙っては通さない。**個人名は出さない**
- **送る前に本文を読める** (「本文を確認する」)。全社に出るものなので、これが無いと初回が事故る
- 時刻を過ぎてから起きたときは **1時間以内なら追いかけ、それより遅ければ送らない**
  (朝の内容が夜に届くほうが困る)

### 見積・請求の原本を開く (v2.9.269)

承認画面が**原本を見ずに金額を承認する**画面だったのを直した
(`finance_docs` は AI が読み取ったテキストだけを持ち、PDF の実体を指す列が無かった)。

- **ブラウザから落とす**形にした。運用者に Box のフォルダ ID を調べさせない —
  社内限りの親フォルダの下に `00_受信した請求書` が無ければ**サーバーが作る**
- 実体は **Box に置く**。サーバーのディスクに置くと再デプロイで消える
  (リアルタイムCG の画像で実際に起きた = v2.9.50)
- **原本は読み取り値より上**に置く。金額を承認する画面なので、先に原本を見る順にする
- **PDF は画面内にそのまま表示**する (承認しながら読めないと意味がない)。
  表示できない端末では「別のタブで開く」に落ちる
- **写真 (JPEG/PNG) も通す** — 請求書は撮った写真で回ってくる。
  ただし文字は読み取らないので「目で確かめてください」と書く
- **PDF を落とすと行そのものを作れる** (メールが無い請求書)。下読みできた値はフォームに埋め、
  読めなかった項目は空 + 注意にする。**読めないことをエラーにしない**
- 差し替えても **Box の前のファイルは消さない** (差し替えの記録が要る書類)
- 種別は中身のマジックバイトで見る (拡張子と Content-Type は名乗りなので信じない)

### 権限の変更履歴 (v2.9.270)

`user_permissions.updated_at` しか無く「いつ」だけが分かる状態だったので、
**「なぜこの人だけ見えないのか」を後から追える**台帳を作った (migration 142)。

- **1行 = 1モジュールの変化**。保存1回でまとめて1行にすると「どの行がどう変わったか」が読めない
- **実際に変わった行だけ**記録する。保存を押しただけで履歴が伸びると読めなくなる
- **消さない** (soft-delete も持たない) — 消せる監査記録は監査にならない
- 変えた人は id だけでなく**そのときの名前も残す** (FK を張らない)。
  退職して users から消えても履歴が「誰か分からない」にならない
- **役割テンプレートを当てた保存かどうか**を残す (`template:sales`)。
  「営業のテンプレートを当てた」のか「1行だけ直した」のかで読み方が変わる
- 履歴が空のときは「**記録を始めたのは v2.9.270 から**」と書く。
  空の一覧を見せて「変更が無かった」と誤解させない
- 記録に失敗しても**権限の保存は成立させる** (履歴のために業務を止めない)

### 問い合わせの返信の下書き (v2.9.272)

**AIが作る → 人が直して保存する → コピーして自分のメールで送る → 「送った」を記録する**。
`ONAiR はメールを送らない`ことを画面に必ず書く (保存が送信だと誤解されると
「送ったつもりで誰にも届いていない」という一番悪い事故になる)。

会社方針「AIを使い捨てにしない」の5条件を**既存の共通レイヤーで**満たしてある
(新しい仕組みは作っていない):

| 条件 | どこで満たすか |
| --- | --- |
| ①出力を記録 | `ai_outputs` (kind=`inquiry_reply`・payload_snapshot に**切り詰めなしの全文**) |
| ②修正を差分で | `ai_corrections` (`field_path='reply_text'`・直した=`fix` / 直さず保存=`none` / 使わなかった=`reject`)。**差分はサーバーが自動で取る** — 人に「何を直したか」は入力させず、任意の理由欄だけ置く |
| ③成果を紐づけ | `ai_outcomes` (`sent` / `unused` + `days_to_reply` 受信から返信までの日数 + `edit_ratio` 直した割合) |
| ④AIに戻す | **生成前に `getFeedbackDigest('inquiry_reply')` を読んでプロンプトに載せる**。傾向を載せた回は `prompt_version` を `+fb` に分ける (同じ版に混ぜると効いたか言えない) |
| ⑤レビュー | MCP `get_ai_feedback_digest` と `/review` から読む |

- 作り直しても**前の `ai_outputs` は消さない** (教師データを消さない)
- AI のキーが無いときは 503 で「本文は自分で書いてください（保存すれば記録は残ります）」と言う
- 元メールの全文は持っていないので、下書きは**要約・分類・AIの見立て**から作る。
  プロンプトで「日程・金額・可否を断定しない」「数字を作らない」を縛る

まだ残しているもの (理由つき):

| 見送ったもの | 理由 |
| --- | --- |
| 案件内タブ (概要・やり取り・お金…) | いまはクイックリンクで各アプリに飛ぶ。タブにすると1画面の担当範囲が広がりすぎる |
| Qシートのマスターの `/settings` 移設 | `doc.data` 内の**その台本のための設定**で全社共通のマスターではない (立ち位置図は番組固有) |
| 朝の1通のメール送信 | Slack は繋いだがメールの送信経路はまだ無い。`morning_email` は保存だけしている |
| 投入から生まれたタスクを案件のボードに出す | **やらないと決めた (v2.9.271)**。案件のボードに「案件なし」の列を作ると、案件の進行を見る場所に個人の ToDo が混ざり、ボードが「案件がどこまで進んだか」を表さなくなる。投入時に案件を推定して紐づけるのも、外すと個人タスクが案件に混ざるので採らない。**代わりに「全体」の画面に「ここに出るのは案件に紐づくタスクだけ」と書いた** — 黙って出さないと「自分のタスクが無い = 壊れている」に見えるため |
| メールの添付を AI が自動で原本にする | 先に人の手で動く形を作った。同じフォルダ・同じ列なので、AI 側を繋ぐだけで後から自動化できる |

### 案件の同時編集 (v2.9.273)

**対象は「みんなで書くメモ」と「チェックリスト」だけ**。土台 (`project_collab` / Yjs の部屋 /
`/project-collab` ネームスペース) は v2.9.249 で作ってあり、画面をそこに載せた。

- メモは **Y.Text** (文字単位マージ)。同じ段落を2人で同時に打っても両方残る。
  **まるごと置き換えず、変わった部分だけ splice する** — 置き換えると相手の入力が消え、
  いま解こうとしている「後勝ち上書き」そのものになる
- チェックリストは **Y.Array\<Y.Map\>** で、行の id を鍵に並び替え・削除を競合フリーにマージする
- **保存ボタンは無い** (打った時点で共有される)。画面にもそう書く
- 同期が来るまで**打たせない**。8秒で来なければ「読むだけ」に落として断り書きを出す
  (黙って編集させると「書いたのに保存されていない」になる)
- 閲覧のみの人には socket を張らず、HTTP の `GET /projects/:id/collab` で**読み取り専用**に見せる

**同時編集の対象にしなかったもの**:

| 対象外 | 理由 |
| --- | --- |
| 金額 | 監査の対象なので「誰がいくらに変えたか」を1本の線で辿れる必要がある。「両方の編集を残す」Yjs とは目的が逆。**409 で保存を止める**方式のまま (v2.9.267) |
| 案件の中身 (フォームの欄) | `projects` の列で、フォームの PUT・MCP・決算インポートが直接書いている。Yjs を重ねると同じ列への書き手が2系統になり、調停を誤れば消える (タスクを外したのと同じ理由)。**代わりに「誰がどの欄を触っているか」を awareness で見せる** — 全項目まとめて保存するフォームでは、これが見えるだけで衝突のほとんどが避けられる |
| タスク | `project_tasks` の**行**で、かんばん / ガント / リスト / MCP / 依頼フローが全て直接 SQL で書いている (v2.9.249 の判断を維持) |

### 案件のコメントと変更の記録 (v2.9.274)

**コメント (B3) はメモとは役割が違う**。メモ (v2.9.273) はいまの状態を全員で書き直す場所で
後から誰が何を書いたかは残らない。コメントは**言った・言わないの記録**なので 1件=1行で残す。
混ぜると「メモを直したら相談の経緯が消えた」が起きる。

- **知らせる相手は選ばせる**。本文から `@名前` を機械的に拾うと、日本語の氏名は区切りが曖昧で
  取り違えたときに**別の人に知らせてしまう**
- 知らせるとその人の**ベル**に「案件で名前を呼ばれた」として出る。**Slack には送らない**
  (ベルは全アプリの上辺にあり、朝の1通とあわせて通知の入口を増やさない = §4.15)
- ベルは既読の概念を持たないので、記録するのは「読んだ」ではなく **「対応した」**。
  読んだだけで消える仕組みにすると嘘の «片づいた» が生まれる
- 消せるのは**書いた本人だけ** (やり取りの記録は当事者の一方の操作で消えてはいけない)。
  消しても行は残す (soft-delete)
- 送信ボタンは「コメントする」。すぐ上に「やり取りを記録」(お客様との接点) があるので、
  どちらに書くのか分かる言葉にした

**変更の記録 (B4) は主要な項目だけ**。全列を残すと履歴が伸びて読めなくなり、
「なぜこの金額になったのか」を探せなくなる = 履歴の目的を失う。

| | |
| --- | --- |
| 記録する | 案件名 / ステージ / お客様 / 主担当 / 実施日 (開始・終了) / **想定金額** / 案件種別 / GLS番号 / 案件分類 |
| 記録しない | 備考・タグ・書類フラグ・BOX の URL など (画面にもそう書く) |

- **金額は記録する**。同時編集の対象から外した理由が「誰がいくらに変えたかを1本の線で辿れる
  必要がある」だったので、それを担保するのがこの履歴
- **1行 = 1項目の変化**・**実際に変わった行だけ**・**消さない** (migration 142 の権限履歴と同じ形)
- 値は raw と「人が読む形」の両方を持つ。お客様や担当者が改名・退職しても履歴が読めるように
  (id だけ残すと後で引けなくなる)
- 記録に失敗しても**保存は成立させる** (履歴のために業務を止めない)
- ステージ変更と GLS 発番は保存とは別の経路なので、そこにも記録を入れてある
- 履歴が空のときは**記録を始めた時期を断る** (空の一覧で「変更が無かった」と誤解させない)
- 既定は畳んである。毎回見るものではないので、開いたときだけ取りに行く

### AI が編集中の案件に追記する (v2.9.275)

要件 B5。**追記だけ**を許す経路で、全置換 (`PUT /projects/:id/collab`) は編集中は 409 のまま。

- **既存の文字を1文字も消さない**。AI が人の書いた文を書き換えられるようにすると、
  「勝手に消された」が起きたときに人は二度とこの欄を信用しない
- メモは末尾に「AIが追記（日時）指示: ○○」の見出しつきで足す。
  チェックリストは `by_ai` を立てて画面に **AI** の印を出す
  (見分けが付かないと「勝手に増えている」になり、消すか残すかの判断ができない)
- **開いている画面に即出る**。サーバー由来の更新を配る口が無かったので
  `YjsRoomManager.setBroadcaster` / `mutate` を足した (無いと「開き直すと出てくる」挙動になる)
- **誰も開いていなくても足せる** (必要なら部屋を開いて種化し、書いたら閉じて永続化する)
- MCP 3ツール: `get_project_collab` (読む) / `append_project_note` / `add_project_checklist`。
  書き込みは `gate.ts` に `sales/editor` で登録済み (未登録ならビルドが落ちる)
- **足したものは提案で、決定ではない**。人が残す・直す・消すのが前提 (勝手に確定させない)

**AI を使い捨てにしない5条件** — 新しい仕組みは作っていない:

| 条件 | どこで満たすか |
| --- | --- |
| ①出力を記録 | `ai_outputs` (kind=`project_note_append` / `project_checklist_append`・全文) |
| ②修正を差分で | `ai_corrections`。**次に AI が読んだときに突き合わせる** (バッチを作らない = v2.9.239 と同方針)。消された=`reject` / 直された=`fix` / そのまま=`none` |
| ③成果を紐づけ | `ai_outcomes` (`done` 完了になった / `kept` 残った / `unused` 全部消された + `kept_ratio`) |
| ④AIに戻す | `get_project_collab` が **advice と kept_rate を返す**。呼ぶのは外の AI なので、読んだ時点で次の追記に効く (こちらのプロンプトを直さなくてよい) |

(同じファイルの `upcomingDays` は `?? []` で守られていて、片方だけ無防備という不整合だった)。
サーバーは必ず配列を返すので現在の経路では起きないが、1件で画面が落ちる作りは残さない。
| ガント | 案件横断はそのまま描画 | PC誘導 + 「リストで見る」 |

**絞った3つ (お客様・お金・設定) は ⌘K から辿る。** さがすタブが ⌘K を開くので行き先は1つも失われない。
`RailItem.mobile` を立てた項目だけ下タブに出す。**レールは全7アプリで共有の定義**なので下タブはどのアプリでも同じ5つ
(アプリ固有のメニューは従来どおり二次ナビ = ハンバーガーから)。

この form を submit するので、外すと**畳んだ状態で保存が黙って効かなくなる**。

**音声入力は端末のものを使う。** 独自の音声入力は作らず、キーボードのマイクで話せると1行書いた
(端末側の方が精度も良い)。

## 4. 壊してはいけないもの

刷新の途中で URL や契約を変えると現場が止まる。次は**フェーズをまたいで維持する**:

- 既存URL (仕様書 §3.3 のリダイレクト表。削除せず残す)
- ICSフィードのURLとトークン (`studio_calendar_settings`)
- 音声サポートの公開URL (`/qsheet/audio/:docId` — 認証なしで開く)
- サイネージURL (`/signage/:roomId`)
- MCPのエンドポイントとツール名 (`/api/v1/mcp`・85種)
- 金額は税抜保持 / `billing_key` の採番規則 / GLS採番の `ON CONFLICT` 原子性
- 権限判定 (`hasPermission` と `LEVEL_ORDER`) と、案件メンバーによる可視判定 (権限とは別軸)
  - 正確には **2段**: モジュール権限で「どのアプリを触れるか」を決め、そのうえで案件メンバーが
    「どの案件のものが見えるか」を広げる。Qシートは `requirePermission('qsheet')` が先に効くので、
    **案件メンバーでも qsheet 権限が無ければ開けない** (メンバーであることは共有設定の代わりになるだけ)。
    自分に割り当てられたタスクは `sales` 権限が無くても返す (金額は返さない)。
