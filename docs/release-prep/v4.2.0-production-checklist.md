# v4.2.0 本番公開チェックリスト

対象: PR #343（`release: v4.2.0`）が `main` にマージされたあと、GitHub Release を Publish するとき。
**本番（VPS・本番DB・Release公開）へは Claude のセッションから到達できないため、以下は全てユーザーが実施し、
結果をこの文書か `docs/reviews/phase3-2-plan.md` に記録してください。**

このリリースには**元に戻せない DB 変更**（`customers`/`vendors` テーブル削除・23テーブル削除・列削除ほか
migration 204〜233、うち208が customers/vendors 削除）が含まれます。公開前のバックアップは必須ゲートです。

## 1. 公開直前 — バックアップ（必須ゲート）

元に戻せない migration を本番に適用する前の最終スナップショット。

```bash
docker exec gmo-onair-app_prod-1 node /app/server/scripts/backup-db-to-box.mjs
```

- [ ] 実行が成功した（BOX の `00_DB_Backup/prod/` に `onair_prod_YYYYMMDD_HHMMSS.sql.gz` が増えている）
- [ ] **復元できることを確認する**（本番を壊さない検証方法）:
      ```bash
      docker exec gmo-onair-app_prod-1 node /app/server/scripts/restore-db-from-box.mjs --list
      ```
      直近のバックアップがリストに出ることを確認するだけでよい（実際の復元実行はしない）。
      詳しい復元手順は [docs/ops/db-backup-restore.md](../ops/db-backup-restore.md)

## 2. 公開直前 — 列単位ドリフト確認（必須ゲート）

migration 209（列削除）が消す列に、本番だけの実データが残っていないかを確認する。
生成済みの SQL は [`db-drift-check.sql`](db-drift-check.sql) に置いてあります（`npm run db:drift-sql` で再生成可）。

```bash
docker cp docs/release-prep/db-drift-check.sql gmo-onair-app_prod-1:/tmp/
docker exec -it gmo-onair-app_prod-1 sh -c 'psql "$DATABASE_URL" -f /tmp/db-drift-check.sql'
```

- [ ] 実行結果が **0行**（`kind` 列に `only_in_dev` / `only_in_migrations` が出ない）
- [ ] 差分が出た場合は **止める**。差分の中身を確認し、migration が本番データを壊さないか判断してから続ける
- [ ] 結果（0行だったこと）を `docs/reviews/phase3-2-plan.md` に追記する

## 6. 何かあったとき — 戻し方

⚠️ **このリリース以降、コードだけ・DBだけを戻しても正しい状態になりません。**
Phase 3-3（`customers`/`vendors` テーブル削除を含む）以降、旧タグへのロールバックは
**コードを戻すのと同時に DB もその時点まで復元する**必要があります（詳細は
[docs/deploy-pipeline.md](../deploy-pipeline.md#ロールバック)）。

**手順**:
1. まず問題の範囲を判断する。**techops の見た目・liveops の表示崩れなど「コードだけの問題」**なら、
   DBは触らず旧コミットの `sha-<hash>` イメージへ差し替えるだけで戻せる
   （`docs/deploy-pipeline.md` の「その場でイメージだけ差し替える」手順）
2. **DBの整合性が疑わしい**（customers/vendors 周りでエラーが出ている等）場合は、コードを戻すだけでは直らない。
   1で用意した本番バックアップから DB を復元し、同時にコードも v4.1.7（1つ前のタグ）に戻す
   （`docs/ops/db-backup-restore.md` の CLI 復元手順）
3. 判断に迷う場合は、**まず No-Go**（公開を止める・戻す）に倒し、原因を切り分けてから再度このチェックリストを最初からやり直す
