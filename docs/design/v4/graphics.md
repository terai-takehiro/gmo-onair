# テロップ・CG（リアルタイムCG の後継）— ゼロベース再設計

**状態: 初版設計（2026-08-30）。段1〜6 を実装したあと、2026-09-06 に利用者に見せる語・画面の数・本番の操作モデルを
[graphics-redesign.md](graphics-redesign.md) で作り直した（**UI はそちらが正**。出力の契約・部品の思想・組版の数値はこの文書のまま）。**
初版のモックは [mockups/v4-mockup-graphics.dc.html](mockups/v4-mockup-graphics.dc.html)（経緯として残す。再設計のモックは
[mockups/native/telop-cg/](mockups/native/telop-cg/)）。

## 0. これは何か

移行中（2026-09-06 に「凍結」から整理）の「リアルタイムCG」（`client-awards/`・アワード授賞式専用の CG 送出）を、
**番組を問わず使える汎用テロップ・CG システム**として作り直し、
**制作技術支援（techops）のミニアプリ**に組み込む計画。

再設計にあたり、次の4系統をディープリサーチした（要点は §8）:

1. **クラウド/HTML5 系**: Singular.Live・Viz Flowics・H2R Graphics・Tagboard・SPX-GC/Loopic
2. **プロ用 CG 送出機**: Vizrt (Artist/Trio/Pilot Edge/Arc/Mosart)・Chyron (PRIME/LUCI/Lyric)・
   Ross XPression・CasparCG
3. **国産テロップ**: NIXUS（CG-NEXTA/Telop Canvas/celio/TELOP BOX）・FOR-A（VWS/ceacaa）・
   ラムダシステムズ（Neo・n/GRID/リムパネル）・フォトロン（TFX-Artist）
4. **現行実装の棚卸し**: `client-awards` の全画面・DB・Socket、techops のミニアプリ統合点

**結論の骨子**: 業界60年の共通型は「**テンプレート → ページ → 送出リスト**」の3層と
「**番号で呼ぶ → プレビューで読む → TAKE で出す**」の運用。国産システムの強みは
「**発注 → 作画 → 校正 → 送出**」という分業のプロセス密着。クラウド系の強みは
「**デザイナーが公開したフィールドからオペレーター画面を自動生成する**」こと。
この3つを Web ネイティブで束ねたものは市場に無く（国産のクラウド対応は VDI 止まり）、
内製する価値がある位置にある。

**組み立ての思想**: いろいろな要素を「部品（ツール）」としてパッケージ化し、
その組み合わせで番組・コンテンツごとのテンプレート＝テロップシステムを作る（§2）。

## 1. 名前と置き場所

- **呼び名: 「テロップCG」**（ミニアプリのラベル。「リアルタイムCG」は旧称として残さない）
- **制作技術支援のミニアプリ**にする。単独アプリとしては再登場させない
  （`client/.../AppTiles.tsx` の `EVENT_KEYS` には**足さない**）
- 導線は techops の正順どおり: `/techops/top` で番組・案件を選ぶ →
  ハブ（`JourneyPage`）のタイルから「テロップCG」へ。
  **「どの番組の？」が定まらない入口は作らない**（ミニアプリタイル直置きで一度失敗した教訓）
- `shared/src/production/miniapps.ts` に `key: 'graphics'`・`kind: 'panel'`・
  `path: '/techops/graphics/:ownerKey'` で登録（サーバー側複製
  `server/src/shared/production/miniapps.ts` も同時に。`check-collab-parity.mjs` が見張る）
- 権限は先例（計時・視聴者 = migration 232）どおり **`qsheet` 区画へ統合**。
  `permissionModule: 'awards'` は移行 migration を書いて畳む
- アワード授賞式・クイズの現行機能は**「アワード」テンプレートパック**として
  この汎用エンジン上に移植する（機能を失わない）。移植完了まで旧 `/awards/*` は現状のまま生かす

## 2. データモデル（部品 → テンプレート → ページ → 送出リスト）

**考え方（ユーザー指示 2026-08-30）: いろいろな要素を「部品（ツール）」としてパッケージ化し、
それを組み合わせて、その番組・コンテンツ専用のテンプレート＝テロップシステムを作っていく。**

```
部品ライブラリ（全番組共通・パッケージ化されたツール）
 └─ ネーム ／ 題字 ／ 一覧表 ／ ティッカー ／ カウントダウン・時計 ／ スコア ／
    速報帯 ／ サイドスーパー ／ 投票・クイズ（アワード継承） …
    ※ 1部品 ＝ 描画＋フィールド定義＋In/Outアニメ＋専用の操作UI＋データの口 を1袋に

番組・案件（owner: project / program — 計時・視聴者と同じ resolveOwner の型）
 └─ CGプロジェクト（部品を組み合わせ、テーマを当てた「この番組のテロップシステム」）
     ├─ テンプレート（部品の組み合わせ・配置・公開フィールドの絞り込み。作画担当が組む）
     ├─ ページ（テンプレートに中身を入れたインスタンス。番号を持つ）
     └─ 送出リスト（本番の順番。ページの並び。Qシートの項目から自動生成できる）
```

- **部品はそれ自体が完結したパッケージ**（Singular.Live の Subcomposition と同じで、
  「アニメの単位・操作画面の生成元・データ束縛・オンエア状態」の4役を1つの抽象が担う）。
  部品を足せば、ページ編集のフォームと送出時の専用操作（例: スコアの ±ボタン、
  カウントダウンの時刻指定、ティッカーの ON/OFF）が**自動でついてくる**
- **テンプレートは部品の組み合わせ**であり、ゼロから描く場所ではない。作画担当の仕事は
  「部品を選んで置き、テーマ（配色・ロゴ・書体）と文字スタイルを当て、公開フィールドを絞る」こと
- 新しい表現が要るときだけ**部品そのものを開発**する（HTML/CSS。社内Web開発者の領分）。
  部品が増えるほど、次の番組の立ち上げは速くなる — 使い捨てにしない

- **テンプレート**: レイヤーツリー＋In/Out アニメ＋公開フィールド（型・文字数上限・
  画像制約つき）。**公開フィールド以外はオペレーターから触れない**（XPression の
  Publish Object / Singular の Control Node 方式）
- **ページ**: フィールド値の入った1枚。**コールアップ番号**（例: 201）を持ち、
  テンキー入力で即スタンバイできる（Viz Trio / Chyron の Message-ID 方式）
- **送出リスト**: ページの並び。進行台本（Qシート）の項目にページを紐づければ
  台本順から自動生成（MOS 連携の最小実装。順序の正は台本側）

### スロット（レイヤー）は役割名で固定する

`フルスクリーン / 下部テロップ / サイドスーパー / ティッカー / 時計・カウント / 速報` の
名前付きスロットを定義し、**1スロット1枚**を構造で強制する。同じスロットに新しいページを
TAKE したら、**古いページは規定の退出アニメで自動的に下りる**（Chyron のチャンネル
"Effect out" ＝ Vizrt transition logic の簡易版）。スロット間ルール
（例: フルスクリーンが来たら下部テロップを自動 OUT）はテンプレート側に宣言的な表で持つ。
**衝突の解決をオペレーターの注意力に任せない。**

現行 `OneShotCueState` が下部テロップ＋ティッカー＋カウントダウンを1オブジェクトに
抱えている設計負債は、**スロットごとの独立 cue** に分解して解消する。

## 3. 役割と業務フロー（国産システムの分業を Web で再現）

```
発注（テロ原）→ 作画 → 校正 → 送出リスト → 本番送出
```

| 段 | 誰が | 画面 | 要点 |
|---|---|---|---|
| 発注 | ディレクター | スマホ可の発注フォーム | テロ原（出したい文言・用途・出すタイミング）だけ書く。手書き指示画像も添付可 |
| 作画 | デザイナー | テンプレート編集（PC） | テンプレートを作る／既存から選ぶ。発注は「未作画」列に並ぶ |
| 校正 | 依頼者・第三者 | ページ編集のプレビュー | 表記チェックして「確認済」に。**未確認・未完成のページはリスト上でバッジ表示・TAKE 時に警告** |
| 送出 | オペレーター | 送出コンソール（PC） | 本番中は組み立てない。**並びどおり出すだけ** |

- 記入フォームは**フィールド定義から自動生成**し、検証（文字数・必須・画像の縦横比）は
  **記入時に完結**させる。本番画面にバリデーションエラーが出た時点で設計の負け
- 記入フォームには**常時ライブプレビュー**を付け、選択中フィールドを絵の上で
  ハイライトする（Viz Trio のバウンディングボックス方式）。長文の溢れは記入者自身が気づく

## 4. 送出コンソール（本番の1画面）

動詞は5つだけ: **スタンバイ（Read）/ TAKE / 続き（Continue）/ OUT / 次へ（Read Next）**。

- **PGM（いま出ている絵）と PVW（次に出す絵）を常時2枚表示。**
  PVW は本物のレンダリング（同じ HTML/CSS/フォント/実画像）。
  **TAKE できるのは PVW に見えているものだけ** — 「リストから直接オンエア」ボタンは作らない
- **番号呼出欄を常設**: テンキーで `201` → スタンバイ。ディレクターが「201出して」と
  口頭で言える運用にする
- **次へ（Read Next）** = いまの PVW を TAKE し、リストの次をスタンバイ（1操作）。
  番組進行はほぼこの反復で回る
- 画面最上部に**スロットごとのオンエア状態**（現在ページ・経過時間・OUT ボタン）と
  **オールクリア**（確認つき）を常設。「今出ているものが一目で分かる」が最終防衛線
- キーボードファースト（Space=TAKE / ↑↓=スタンバイ移動 / テンキー=番号呼出）。
  Stream Deck 等の外部制御は HTTP/WS の小さな API（take-in/take-out/update）で受ける
- **本番中の自由記入はさせない**。表示中データの差し替え（update）は許すが、
  確定操作（青い「反映」ボタン）を挟む。得点・票数など高頻度データだけ
  フィールド単位の「即時反映」フラグで例外にする（Singular の Immediate Update 方式）

## 5. テンプレート編集（作画）と日本語組版

- 入口は**部品ライブラリ**: 部品カードを選んで置くところから始める。キャンバス＋
  部品ツリー＋プロパティ＋ **In/Out タイムライン**（既定は
  「Out = In の逆再生」。別途作り込みたいときだけ 2 タイムライン化 — Singular 方式）
- アニメ途中の割込みは**逆再生で戻す**（スナップ禁止・Flowics 方式）
- HTML テンプレートの実行契約は CasparCG に合わせる:
  `load → play → next → update → stop(out付き) → remove(即時)`
- **文字スタイル**（フォント・ウェイト・多重エッジ・シャドウ・座布団）を
  **名前付きプリセット**として一体管理（「ネーム用」「速報用」…）。
  作画者ごとの揺れを潰し、テーマ差し替えで番組横断の見た目替えを可能にする
- 日本語組版で最初から持つもの（後回しにすると作り直しになる層）:
  - 多重エッジ（`paint-order`＋多重 stroke/shadow）・座布団
  - 縦書き（`writing-mode`）・縦中横・ルビ・詰め（`palt`）・異体字（`font-feature-settings`）
  - **等幅数字**（`tabular-nums`・スコア/時計はプロジェクト共通原則）
  - **フィット（自動縮小・長体）はテキスト部品の内蔵機能**にする（Singular ですら
    スクリプトが要る部分。長い社名・肩書がある日本語では必須）
- フォントは**サーバー同梱の再配布可能書体**（LINE Seed JP ほか）を基本セットにし、
  テンプレートに使用フォントのメタデータを残す（ライセンス監査可能に）
- **CG の見た目は v4 トークンの対象外**（放送に出る映像。`/live/display/` と同じ例外扱い）。
  v4 化するのは業務画面（一覧・編集・送出コンソール）だけ

## 6. データバインド（2系統に分ける）

| 系統 | 用途 | 経路 |
|---|---|---|
| 確定系 | 名前・肩書・題字などの穴埋め | ページのフィールド値（記入→反映） |
| 高頻度系 | 得点・票数・カウントダウン・時計 | Socket push の専用データノード（サーバー時刻同期つき） |

- 差し込みソース: 手入力 / **名簿（レコード表。Excel 取込の列マッピングは現行実装を継承）** /
  Google Sheets / ONAiR 内データ（案件・進行台本・クイズ票数）
- 名簿は現行の `Nominee` 固定型をやめ、**「レコード＋フィールド定義」**の汎用形にする
  （`resolveBinding` の `${field}En` 規約は日英対応としてそのまま活かす）
- 大量ページの一括生成（受賞者20名分のネームなど）はテンプレート×名簿から作る

## 7. 出力（OBS・スイッチャーへの契約）

現行の運用資産をそのまま継承する:

- **公開URL・認証なし・1920×1080 固定・既定透過**。`?bg=1`（不透明黒）/ `?lang=ja|en` /
  `?audio=1`（SE は送出用1枚だけ）
- チャンネル（メイン合成・サブ・多言語別など）ごとに URL を分け、
  ハブ画面に「**出力URLの配り方**」カードを常設（QR・コピー導線つき）
- 時刻は**サーバー基準**（`serverClock` の skew 補正を継承）
- 旧 `/awards/output/*` URL は後方互換リダイレクトで生かす（qsheet→techops の前例どおり）

## 8. リサーチからの主要な学び（要約）

1. テンプレート→ページ→送出リストの3層は全ベンダー共通。独自モデルにしない
2. 本番の動詞は Read/Take/Continue/Take Out/Read Next の5つに絞る（Viz Trio）
3. ページに短い番号を振る。テンキー呼出は口頭運用と桁違いに速い（Lyric 以来の実績）
4. TAKE できるのはプレビュー済みだけ、を構造で強制（プレビュー規律の3点セット）
5. プレビューは本物の絵（簡略サムネイルは「確認したのに違った」を生む）
6. スロット＝役割名で 1スロット1枚・新しい方が古い方を規定アニメで押し出す（Chyron/Flowics）
7. スロット間の自動退出ルールをテンプレート側に宣言（Vizrt transition logic の簡易版）
8. アニメ契約は CasparCG の6動詞。実装例が世界一多い
9. 記入フォームは自動生成・検証は記入時・未完成ページはバッジ＋TAKE 警告
10. フォームに常時ライブプレビュー＋選択フィールドのハイライト（Viz Trio）
11. 確定系と高頻度系のデータ経路を分ける（Singular の Control/Data Node 分離）
12. グラフィックは台本の行に住まわせ、順序の正は台本側（MOS の本質。Qシート連携で実現）
13. デザイン変更に専門家を要求しない範囲（色・ロゴ・文言スタイル）を管理画面に出す。
    ただし「誰でも全部編集」には振らない — フィールド公開の絞り込みが安全と速度を作る
14. 発注→作画→校正→送出の分業ステータスを持つ（ラムダ/テレ朝 ANTS の型）
15. 日本語組版（多重エッジ・座布団・縦書き・詰め・ルビ・フィット）は最初から。
    ブラウザは国産専用機より組版プリミティブが揃っており、UI に出すかが勝負

## 9. 実装への段取り（モック確定後）

1. **段1**: ミニアプリ登録＋ハブ画面＋出力URL（旧 awards 互換）＋スロット型 cue の器
2. **段2**: 送出コンソール（PGM/PVW・5動詞・番号呼出・スロット状態）
3. **段3**: ページ編集（フォーム自動生成・検証・ライブプレビュー・校正ステータス）
4. **段4**: 部品ライブラリ＋テンプレート編集（部品の組み合わせ）・文字スタイルプリセット・テーマ
5. **段5**: 発注（テロ原・スマホ）・Qシート連携・名簿/Sheets 差し込み
6. **段6**: アワード・クイズのテンプレートパック移植 → 旧 `/awards` 画面の畳み込み。
   現行実装の棚卸し・新エンジンとのギャップ・段6-1〜6-9への分割は
   [graphics-awards-migration-plan.md](graphics-awards-migration-plan.md) を参照

技術上の要注意（コード棚卸しより）: techops の Socket.IO で `cue:*` が既に本番進行に
使われているため、CG のイベント名は `cg:*` を新設する。NEXT 状態がサーバーの
in-memory Map な点はスロット化と同時に DB へ寄せる。`SlotStyle` 未適用・
`oneshot_raw` 未接続など「宣言だけあって実装が無い」箇所は引き継がず作り直す。
