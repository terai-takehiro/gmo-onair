## 経緯

「制作資料」アプリ（[`client-qsheet/`](../../../client-qsheet/CLAUDE.md)、v4.0.0では凍結）の
v4化に着手するにあたり、ユーザーから次の第1段階の依頼を受けました。

> 第１段階: `/design` モックアップ作成（PC/スマホ）
> 第２段階: コーディング

対象は3領域（トップページ・スケジュール表・Qシート）。**iOS/macOSのネイティブアプリの
ような美しいデザイン・操作性**を目指す指定でした。

⚠️ **初版は Qシートの機能を大きく取りこぼしていました。** 既存モック
（`mockups/v4-mockup-production.dc.html`、それ自体すでに簡略化された参照物）だけを見て作り、
**実装ソースを読まずに構成を再発明していた**のが原因です。ユーザーの指摘
（「Qシートはかなり機能が変わってしまっていますが、どうですか？」）を受けて
`client-qsheet/src/pages/*.tsx` を全て読み直し、下の④〜⑦を作り直しました。
**「進行台本編集を中心に大幅にやり直す」という明示の判断**をいただいています。

さらに続けて、**「Apple の UI/UX 思想で改善できることは果敢にやる（機能は一切落とさない）」
「大雑把なところから台本の精緻なところにブレイクダウンしていくジャーニーが重要」**という
方針をいただき、⑧の段階ビューを追加しました。

## ⑧ 制作のジャーニー ── この提案の背骨

ディレクターは「当日どう動くか」から入り、「番組がどう流れるか」を決め、最後に
「何を喋り、どのマイクを開けるか」まで降りていきます。①〜⑦は道具としては揃っていますが、
**別々の画面を行き来する形**で、この降りていく順番が表現できていませんでした。

⑧は**同じ1日を3つの詳細度で見る**形にした提案です（カレンダーの日／週／月と同じ考え方）。

| 段階 | 決まること | 対応する既存画面 |
| --- | --- | --- |
| 1. 案件を選ぶ | 対象の案件（GLS発番前・案件化前も可） | ① |
| 2. 当日の枠を置く | 会場・支度・運営の列、各ブロックの時刻 | ②③ |
| 3. 番組の流れを組む | 項目の並びと尺、押し・巻きの吸収先 | ④⑤ |
| 4. 台本を詰める | 台本・マイク割当・テロップ・立ち位置 | ⑤⑥→⑦ |

具体的に足したもの:

- **詳細度の3択**（上部のセグメント）で、画面遷移なしに同じ1日の粒度を変える
- **ブレイクダウンの進み具合**をブロックごとに3本のバーで出す（枠だけ／流れまで／台本まで）。
  締切前に「祝賀会がまだ枠だけだ」と気づける
- **親を見失わずに子を開く** — 項目をクリックするとその場で中身が下に開く（別ページに飛ばない）
- **「次に決めること」** を常設（PCは右、スマホは下部）。未着の素材・台本の無い項目・尺の不足を、
  そこへ飛べる形で並べる

⚠️ **機能は1つも減らしていません。** ⑧は既存画面を置き換えるものではなく、
案件を開いたときの**入口として上に載せる**想定です。

## 各領域の設計判断

### ① トップページ

案件を4グループに分けました: **進行中の案件**（GLS番号あり）／ **案件化前（GLS未発番）**
（`stage=b_verbal` 相当）／ **ネタ（検討中）**／ **この制作資料だけの資料**（案件に紐づかない）。

`client/CLAUDE.md` の案件ライフサイクル（`neta → d_hold → c_proposal → b_verbal → a_won`）と、
`qsheet_documents` が `project_id`・`episode_code` とも nullable である
（＝案件未化の資料は現行スキーマでも表現できる）という調査結果に基づいています。

### ①′ トップページ（2026-08-22 作り直し）

**ご指摘**「制作技術支援のトップページがあまりにもだめ。iOS、MacOS の美しさ、機能性を
UIUX に落とし込んで」を受けた作り直しです。**①を置き換えるもの**で、①は経緯として残します。

対象は実装済みの `/qsheet/top`（[`ProductionTopPage.tsx`](../../../client-qsheet/src/pages/ProductionTopPage.tsx)）。
①の当時とは構成が変わっており（案件のライフサイクル別の4グループ → 「まず番組・イベントを
選ぶ」1画面）、いまの画面は**「案件管理の番組・イベント」と「ここだけの番組」の2つの一覧を
素の枠線で縦に並べているだけ**で、開いた瞬間に目が止まる場所がありません。

作業ファイルは [`mockups/native/qsheet-top/`](mockups/native/qsheet-top/)。
**アートボードは4枚**（`Main.dc.html` = PC トップ 1440×1200 ／ `Hub.dc.html` = PC ハブ 1440×1040 ／
`Mobile.dc.html`・`HubMobile.dc.html` = スマホ 390×844）。**クリックできる試作**です
（さがす・案件／ここだけの絞り込み・アーカイブの出入り・「番組を作る」のシート・
ハブの折りたたみ・「決まった」「要注意」のピン・「次に決めること」の無視が実際に動き、
未実装の行き先は帯で「どこへ移るか」を出します）。

| 変えたこと | 理由 |
| --- | --- |
| **① 直近の本番・収録を最上段に置いた**（きょう＝青／あす／今週の3枚） | ディレクターが最初に探すのは「今日どれを開くか」。一覧の中から日付で探させない |
| **② 「続きから」（最近開いたもの）** | 同じ番組を1日に何度も開き直す。1タップで戻れるようにする |
| **③ 2つの一覧を1つの表にまとめ、案件／ここだけはセグメントで切り替え** | 同じ「番組を選ぶ」という行為が2つの箱に割れていた。出どころの違いは行頭のアイコンと2行目で足りる |
| **④ 面・罫・角丸・押し心地を iOS の inset grouped list の作法にそろえた** | 角丸16のカードに行を入れ、区切り線を先頭アイコンの分だけ内側に入れる。押した瞬間の面の変化を持たせる |
| **⑤ 終わったものはアーカイブへ**（ご指示・2026-08-22） | 本番日（実施日）の翌日から自動でアーカイブに入り、一覧の最後の行から開ける。アーカイブ中は「直近」「続きから」を出さない（別の場所として扱う）。通常の一覧で検索してアーカイブ側に当たりがあるときは「アーカイブに N 件みつかりました」を出す |

**色・書体・角丸は v4 トークンの実値をそのまま使い、新しい色は1つも足していません**
（面 `#f7f8fa` ／ 罫 `#e6e9ed`・行間 `#f2f4f7` ／ 文字 `#1a1d24`・`#5d6470` ／
ブランド `#005bac`（面 `#f4faff`・枠 `#cfe4f4`）／ 角丸 カード16・ボタン10・バッジ7 ／
書体は LINE Seed JP →（無ければ）Noto Sans JP の 400/700/800 のみ）。
上辺バー64px・左メニュー248px・下タブ3本は
[`shared/src/client/shell/`](../../../shared/src/client/shell/) の実装値に合わせています。

#### 案件を選んだあとの「選ぶページ」（ハブ・`JourneyPage.tsx`）

ご指示で同じキャンバスに足しました（PC②・スマホ②）。**実装の機能は1つも落としていません** —
ミニアプリ4つ・3段（当日の枠／番組の流れ／台本の中身）・「決まった」「要注意」のピン・
当日の枠・進行台本・「次に決めること」の無視、すべてあります。変えたのは見せ方です。

| 変えたこと | 理由 |
| --- | --- |
| ミニアプリのタイルを主役にした | この画面の仕事は「どの道具を開くか」。小さい枠ではなく、中身の件数が見える大きなカードにした |
| **3段ごとに並んでいた「決まった にする」「要注意 にする」の2ボタン（1日に6個）を 44px の印にした** | 文字量が 1/3 になり、その下の事実の行（「スケジュール表 1件（8/20 17:42 更新）」）が読めるようになった。押すと色が入る |
| 日ごとのカードを折りたためるようにした | 回数の多い案件（GLS-A002 は13回）で縦に伸び続けるのを止める。⑧の「親を見失わずに子を開く」と同じ考え方 |
| 「次に決めること」を右に常設した | ⑧の方針どおり（PCは右・スマホは下）。ただし**スマホではタイルのすぐ下に上げました** — スマホは「今やること」を先に出す決めごと（`_rules.md`「3. スマホ」）があるため |
| 見出しに「次の本番まで あと1日」を出した | 開いた瞬間に急ぎかどうかが分かる |

⚠️ タイルの件数（進行台本1件・スケジュール表1件）は journey API の `facts` から出せます。
収録設定・配信設定は状態を持たない（`kind: 'panel'`）ので、**あえて何も出していません**。

#### 実装する前に決めること

- **①②はサーバー側の追加が要ります。** モックのタブ（「足す情報」）で①②を消せるので、
  無い場合と見比べてから決められます
  - ①直近 … `/lookup/gls-options` は `id`/`gls_number`/`name`/`customer_name` しか返さない。
    回（`project_episodes`）の放送日・収録日を返す口が要る
  - ②続きから … 閲覧履歴を持つ仕組みが無い。`localStorage` だけでも成立する
- ⚠️ **スマホの下タブに「トップ」がありません**（[`nav.ts`](../../../client-qsheet/src/components/layout/nav.ts) の
  `QSHEET_MOBILE_TABS` は実装どおり3本のまま）。この画面へ戻る導線が上辺のロゴだけになるので、
  タブを「トップ／ドキュメント／スケジュール」に差し替えるかは別途ご判断ください
- 一覧に**その番組の資料の有無**（進行台本◯件・スケジュール表◯件・収録配信 設定済）を
  出す案は、今回は入れていません（件数を返す API の追加が要るため。ご指示で外しました）
- **アーカイブの判定をどこで切るか。** 案件（GLS）は回が複数あるため、モックでは
  「一覧に出している実施日（＝直近の回）の翌日」で切っています。**最後の回の翌日**にするか、
  **回ごと**にするかは決めていません。手で戻す操作を用意するかも未定です
  （「日付なし」の番組は終了しない扱いにしています）
