# テロップCG デザイン実測仕様（ピクセル基準）

**2026-08-30 ディープリサーチ3本（報道系・バラエティ/式典系・画面レイアウト規格）の統合。**
テロップCG（[graphics.md](graphics.md)）の部品 CSS・文字スタイルプリセット・キャンバスガイドの
**数値の正**はこの文書。AI が雰囲気で作るテロップを排し、実際の放送の作法を数値で固定する。

確度の凡例: **【規格】**=規格文書で確定 ／ **【実務】**=複数ソース一致の業界相場 ／
**【推定】**=傾向からの合成値（実機検証で締める）。出典は各節末。

## 0. キャンバスとセーフエリア【規格】

論理キャンバスは **1920×1080 固定**（4K は `scale(2)` の整数倍出力。%で持てば解像度非依存）。

| ガイド | 座標 | 用途 |
|---|---|---|
| 文字セーフ 90% | (96, 54) – (1824, 1026) | **常駐物・重要文字の既定枠**。ARIB旧/SMPTE ST 2046-1/EBU R95 が一致 |
| アクションセーフ 93% | (67, 38) – (1853, 1042) | 映像的要素の限界 |
| ARIB目標 文字 95% | (48, 27) – (1872, 1053) | 現行番組の攻め位置（配信のみならここまで可） |
| 字幕放送想定域 | x 360–1560, y 880–1026 | 字幕付与番組では恒久物を避ける参考枠 |

- 4:3 セーフは**原則考慮不要**（地デジ移行後の実務で撤廃済み）
- テレビはいまだ出荷時オーバースキャン ON が多い → **テレビ送出兼用は 90% 厳守**、
  配信専用レイヤーだけ 95% まで攻めてよい
- **持ち場のルール【実務】**: 左上=時刻（下に LIVE バグ）／右上=局ロゴ・サイドスーパー／
  下部=テロップ帯・字幕。速報時は上辺。互いの持ち場に入らない

CSS 定数: `--safe-x:96px; --safe-y:54px; --safe-stream-x:48px; --safe-stream-y:27px`

## 1. 書体【実務】

- **報道・情報の本文は UD系角ゴシック一択**。実在の採用: NHK=UD新ゴ（2023 UD刷新）、
  テレ朝=テレ朝UD（UD角ゴ_ラージベース）、フジ=UD新ゴ系、日テレ=ニューロダン
- 明朝は普通の明朝ではなく**横太明朝**（フォントワークス「テロップ明朝」= 筑紫明朝の横画を
  太らせた画面用）。通常明朝は横線が細く画面でちらつく → 式典系も**太ウェイトの明朝**を選ぶ
- **疑似ボールド（faux bold）は禁忌**（ずらし重ねで画が潰れる）。必ず実ウェイト。
  CSS: `font-synthesis: none` を全部品に必須
- 同梱書体での割当（ライセンス安全圏）: 角ゴ=LINE Seed JP（400/700/800）＋
  Noto Sans JP（UD系の代替・500/600 が要るとき）、横太明朝の代替=Noto Serif JP の 700–900
- ウェイト相場: 報道本文 DB〜B（CSS 500–700）、氏名・見出し 700–800

## 2. 文字サイズの階層（px @1080）【実務】

| 階層 | px | 用途 |
|---|---|---|
| 題字・強調 | 90–120（強調は基準の1.5–2倍） | 式典題字・大見出し |
| 見出し | 60–80 | サイド見出し・コーナー |
| メイン | 48–60（基準 ≒ 画面縦の6–8%） | 発言テロップ・本文 |
| 字幕系 | 42–48 | 下部字幕 |
| 補足 | 36–42 | 肩書・出典・注記 |
| 絶対下限 | **30（テレビ視聴距離基準。26未満は不可）** | — |

**全文同サイズは素人の典型** — 階層は「位置・大きさ・色/書体」の3軸で作る。

## 3. エッジ（縁取り）・シャドウ・袋文字

- 太さの相場: **文字サイズの 5–10%**（50px文字→片側2.5–5px）。報道は下限寄り（5–7%）、
  バラエティは実測レイヤー: 塗り／内フチ **6–8px**（感情色）／外フチ **14–16px**（黒 #1A1A1A）【実務】
- **多重フチは2重まで**。3重以上・細字に太フチ・**ぼかしたフチ**は名指しのNG【実務】
- エッジ色は文字と**反対の明度**（白文字→黒〜濃紺）。内:外 ≒ 1:2【推定】
- シャドウ: テレビは**ベタ落ち影**（`text-shadow: 8px 8px 0 rgba(0,0,0,.9)`・ぼかし0）か
  短距離ソフト影（`0 3px 8px rgba(0,0,0,.45)`・式典系）。**報道はシャドウ無し〜ごく浅め**。
  全方位グロー・ぼかしすぎは素人サイン【実務】
- **袋文字のレイヤー順（正）**: 塗り → 内エッジ → 外エッジ → シャドウ → 座布団
- CSS 技術選定【実装】: `-webkit-text-stroke` は1重のみ → **同一テキストを重ね描き**
  （grid 同セル重ね・背面ほど stroke 太く・`paint-order: stroke fill`）が唯一正確。
  `text-shadow` 8方向重ねは太フチで角が割れるのでフチには使わない（影専用）

## 4. 座布団（ベース）

- 不透明度 **50–80%**。ベタ100%は画面を殺す【実務】
- **単色ベタ矩形が素人臭い理由**: 質感ゼロ・余白の詰まり・無関係な彩度。処方は3点セット:
  ①上下で明度差5–10%の縦グラデ（または上10–15%にハイライト帯）
  ②`1px` の明縁 or 暗縁 ③短距離の `box-shadow: 0 4px 12px rgba(0,0,0,.35)` まで【推定】
- 余白: 文字サイズの **左右 0.5–0.75em・上下 0.25–0.4em**【推定】
- 角丸: 報道・式典=スクエア〜4px、バラエティ=大きめ可。**角丸過多は幼く見える**
- 報道の帯色: 半透明黒 `rgba(0,0,0,.5–.7)`・NHK型グレー `rgba(40,40,45,.75)`・
  紺 `#001c50` 系が民放定番【推定】。式典=黒70%＋左端 4px の金アクセントバー

## 5. 色の規範

- 報道: **白＋黒＋アクセント1色が鉄則**。色数の少なさが「報道らしさ」の最大要因。
  赤は速報・緊急**以外に使わない**（速報=赤地白 or 黄地黒の反転）【実務】
- **輝度セーフ**: 純白 #FFF（スーパーホワイト）を避け、白は **#F5F5F5〜#EFEFEF**
  （SDI送出まで見据えるなら 235=#EBEBEB 上限・黒は #101010）。彩度100%の原色も落とす【実務】
- 式典の金【実務】: 上品系 **#D4AF37**（本命）／標準 #FFD700／アンティーク #B8860B／
  シャンパン #F7E7CE。**金は黒・白（または濃紺）と組んで初めて品が出る**
  - 輝く金グラデ: `#FFD700 → #FFF9E6 → #FFD700`
  - 金属感の強い金（Premiere公開レシピのCSS換算）:
    `linear-gradient(180deg,#E8C34A 0%,#FFFDF0 44%,#8A5A0E 52%,#D98E1F 60%,#E8C34A 100%)`
    ＋ `background-clip:text`（グラデ文字は strokeと層を分ける）
- グラデ塗りは**強調語だけ**。小さい文字への縦グラデは可読性を落とす
- バラエティ感情色: 強ツッコミ=赤系／ボケ・笑い=黄〜橙／独白=白明朝＋影のみ（フチ無し）。
  **1本の中でデザイン種類は3〜4種に固定**

## 7. 組版ルール（テレビ的ルール）【実務】

- 1行 **最大18字**（実務は16字×2行以内）。改行は意味の区切り・行頭に助詞を置かない
- **句読点「、」「。」は使わない**（全角スペースで代用）
- 表示時間: `max(2秒, 文字数÷4)` ＋消すのは話し終わりの1拍（0.5秒）後。最低3秒（報道）
- 長体（自動縮小）は **80% が可読性の限界**（`scaleX(.9)` 無難・`.8` まで）
- 文字詰め: 本文=ベタ〜やや詰め（`letter-spacing: -0.02em〜0`）、題字=広め（`0.08–0.2em`）
- 数字は半角・**等幅**（`font-feature-settings:'tnum'`）。桁増減でレイアウトを動かさない
- 見出しはツメ組（`'palt'`）可・本文はベタ寄り

## 8. アニメーションの作法

- バラエティ発言: **カットイン（0フレーム）**が基本。ポップは
  `scale 0→200%(5f)→100%(3f)` ≒ **0.27秒**（オーバーシュート付き easing で代替）。
  通常フォローに毎回アニメを付けるのは素人パターン
- 式典: **フェード 0.5–1.0秒**（カットインは不躾）。ネームは左→右マスク展開 0.6–0.8秒 可。
  表示は最低4秒・`文字数÷6 + 余裕`
- ティッカーのループ・速度は §6。カットの都合より**読み切れること**が優先

## 9. 「AIっぽい／素人っぽい」NG集（部品実装のレビュー基準にする）

1. デフォルト書体のまま・疑似ボールド
2. 1本の中で見た目がバラバラ（統一が最優先）
3. フチが細字に太すぎ／**フチをぼかす**／3重以上のエッジ
4. 彩度100%の原色・色数過多
5. シャドウのぼかしすぎ・距離ゼロの全方位グロー
6. 純白 #FFF（スーパーホワイト）
7. **単色ベタ矩形の座布団**（質感ゼロ）
8. セーフ無視の画面端ギリギリ
9. 全文字同サイズ・メリハリなし
10. 小さい文字への縦グラデ
11. 毎テロップにアニメ・長すぎる出し尺（ポップは0.3秒未満）
12. 角丸過多・字間ゆるすぎ

## 9.5 造形文法（2026-08-30 追補 — 「AIっぽい」を潰した2周目のリサーチ）

初回実装が「黒い角丸カード＋細い金枠＋左バー」を全要素に使い回して**Web UI の文法**に
なっていた反省から、実物の造形を再調査した。結論:

1. **実物のテロップの語彙は「面（座布団）・エッジ（袋文字）・罫」の3つだけ。
   透明面を全周の枠線で囲む造形は実物に存在しない** — 枠線囲み＋角丸＋カード化が
   Webっぽさの最大因子。さらに**罫は1要素1本まで**（3周目の学び: 面の上下罫＋見出し下線の
   ような細罫の重ね使いも AI 臭になる）。第2の分離は罫でなく面の明度差で行う
2. **要素ごとに構造を変える**（全要素同一構造が最大のAI臭）:
   時刻=座布団なしの袋文字 ／ ネーム=面＋金は文字と細罫 ／ サイド=袋文字＋下罫（面なし）／
   速報=ラベル面（黄ベタ・赤ベタ）と本文面の色分割（罫で分けない）／
   フルスクリーン=全面暗幕に文字直置き（セルの箱を作らない）
3. **ネームスーパーの実物構造**: 単一の箱に2行ではなく、役割ごとの層
   （賞名・役割=金の明朝＋広字間＋短い金下線 → 氏名=主役・最大 → 所属=小さな灰ゴシック）。
   報道系は「肩書タブ（暗色の小プレート）＋名前面」の2枚重ねで、2面は必ず明度反転
4. **金はベタ塗りした瞬間に黄土色になる**。金に見えるのは縦グラデ
   （#FFF3C4→#D4AF37→#8A6414・ハイライト上1/4）だけ。使用先は文字・1〜2px罫・◆の3つ、
   1画面2種まで。面は真っ黒でなく**紺寄りグラデ**（#141C2E→#070A12）＋弱いビネット
5. **書体**: LINE Seed JP は「カドマル」のUI書体で放送の絵に使わない。
   同梱/GF圏の割当 — 題字・氏名=**Noto Serif JP 900**（横太明朝の代替・無料圏で横画が最太）／
   実務テキスト=**Noto Sans JP 900/700**（放送極太ゴの代替）／UD感が要る補助=BIZ UDPGothic 700／
   数字=Roboto Condensed 700 可。**疑似ボールド禁止**（`font-synthesis:none`）
6. 格調の源泉は「金の量」ではなく **余白・細罫・少ない色数（暗面・金・白の実質3色）・
   広い字間（見出しのみ +25〜50%）**。紅白が明朝を大きく使う通り、式典の主役書体は明朝

検証手順もこの追補の一部: **参照見本（`scratchpad/telop-refs2/` に実フォントで描いた比較10枚）
との目視比較 → 実レンダリングのスクリーンショット → §9 NG集に照らした自己批評 → 修正**を
1周として回す。1周目で「枠線・ベタ金バー・LINE Seed」を全廃した。

## 9.6 テーマ（2026-08-30 追補 — 「式典しか無い」の解消）

テーマは色替えではなく**別の造形**として実装する（`nameParts.tsx`・`telopTheme.ts`）。
`graphics_projects.theme` の4キーと構造:

| キー | ラベル | ネームの構造 | サイドの構造 |
|---|---|---|---|
| `ceremony-gold` | 式典（金） | 暗紺グラデ面・金は見出し文字と1本の短い下線のみ・明朝900 | 袋文字の明朝＋罫なし |
| `news-navy` | 報道（紺） | **肩書タブ（紺ベタ白抜き）＋白面黒文字の2枚重ね**・罫0本・UD系ゴシック | 紺帯の白抜き |
| `corporate-light` | コーポレート | 面なしの袋文字＋**アクセント色の下罫1本**（下罫1本型） | 袋文字のみ |
| `variety-pop` | バラエティ | 下中央・多重エッジ（塗り→内フチ色→外フチ黒→ベタ落ち影）・座布団なし | 黄座布団に黒文字 |

時計（座布団なし袋文字）と速報帯（ラベル面分割）は全テーマ共通（報道の文法が汎用の正）。
切替はハブの「テーマ」ピッカー → `PUT /graphics/projects/:id` → `cg:sync` で出力へ即時反映。
`?theme=` は試写用の上書き。

## 9.7 実測データ（2026-08-31 追補 — 実画像のピクセルから測った値）

「実際のデータから学習しろ」というご指摘を受けた4周目。それまでの参照は
**文章の記述から自分で描いた見本**（自己参照ループ）だったため、実物の画像を収集し
（放送テロップの忠実再現・実放送フレームを含む39点。GitHub 上の再現系リポジトリ・
実行レンダリングから採取）、ピクセルを直接実測した。設計への反映値:

| 実測項目 | 値 | 出所 |
|---|---|---|
| **文字の充填率** | 地名文字＝行高の **0.805**・ヘッダー文字 0.64（→ 実装は 0.7〜0.8 を規律に。**余白たっぷり＝AI臭の最大因子**） | NHK型津波テロップ再現（実運用スクリーンショット）の縦スキャン |
| 行グリッド | ヘッダー＝行＝**同一高さの均一グリッド** | 同上 |
| 災害・速報系の色 | 黄 **#FAF601**・赤 **#FF2801**・紫 **#A202A7**・行は**純黒ベタ**・数値セルは**純白** — グラデも影も無い | 同上（領域最頻色） |
| 速報帯の実構造 | ラベル **#EA0358** ベタ白抜き＋**白ベタ帯 #FEFBFE に同系色文字 #E70555**（黒半透明帯ではない） | 実放送フレーム（ANN ニュース・速報帯）の領域最頻色 |
| 場所スーパー | 小さな黒旗形タブ＋素の袋文字2行（面なし） | 同上 |
| バラエティ帯 | **左肩ラベルが帯の角に乗り上げる**（少し回転・ベタ影）＋帯はグラデ可＋語単位の色替え | バラエティ用テロップ実装のデモ実レンダ |
| セル分割 | 情報の区切りは罫でなく**面の色替え**（黒地白／黄文字／白セル黒数字の3分割） | 津波テロップ再現 |

検証環境も是正: 黒背景でなく**実写風の busy 背景に合成して**判定する（黒背景は
何を置いてもそれらしく見えてしまう）。画像はライセンス上リポジトリに入れない —
測った**数値だけ**をこの文書に残す。実測手順（Chromium canvas での領域最頻色・
縦スキャン・充填率）は再現可能なので、新しい実画像を得るたびここに追記する。

## 9.8 スコアボード（2026-08-31 追補 — 実放送オーバーレイ実装からの構造抽出）

スコアボード部品の実装にあたり、放送・配信で**実際に使われた**スコアボード実装
（格闘ゲーム大会中継の実キャプチャ1点＋実運用オーバーレイの CSS 実装4本 —
`git clone` 経由で取得。NodeCG／StreamElements 系のバレーボール・チーム対戦・
マップ別対戦の各スコアボード）を集め、構造だけを抽出した（配色・角丸・グローは
§9.5 の語彙に反するため模写しない — 見るのは「何と何がどう並ぶか」だけ）。

| 実測項目 | 観察 | 出所 |
|---|---|---|
| **名前セルと得点セルの分離** | 罫線は無く、**面の色替えだけ**で区切る（チーム色の名前セル→無彩色の得点セルへ切り替わる）。実測4本すべてで一致 — §9.7 の「セル分割は面の色替え」がスコアボードにも成立する | バレーボール・格闘ゲーム大会・マップ別対戦の3実装のCSS |
| **得点の文字色は面の色を継がない** | チーム色は名前セル（面）だけに使い、**得点の数字は白か黒で固定**（格闘ゲーム実装は得点セルに赤アクセントを使うが文字は白のまま）。数字に感情色・チーム色を乗せた実装は無かった | 同上（§6「スコアバグ…文字は白黒固定」と符合する独立確認） |
| **得点セルは固定の狭い幅** | 桁が変わっても他要素が動かない専用の小セル（実装は 30〜50px 幅で1〜2桁の数字用）。テキストの一部として流し込む実装は無かった | 同上（§6「桁は固定幅予約」と符合） |
| **実物の格闘ゲーム大会オーバーレイの意匠** | 名前プレートは平行四辺形（`skewX`）・暗面＋1px アクセント縁・短距離ドロップシャドウ。**角丸・発光は無い** | WASD-Gaming/fgc-scoreboard の実キャプチャ＋CSS |
| **多エントリ（3件以上）の並び** | 同一寸法のセルを横に反復するだけ（マップ別対戦=1マップ1セル）。セルごとに違う装飾は付けない — 装飾は「面の役割」（名前/得点）で決まり「何番目か」では決まらない | vtv-scoreboard（VanillaTV 実運用オーバーレイ）の `.map` 反復セル |

**設計への反映**（`scoreParts.tsx`）: エントリー＝「名前セル＋得点セル」の2セル1組を
横に並べる骨格を全テーマ共通にし、テーマごとに面の作り方だけを変える
（式典=暗紺グラデ面＋金は罫なしの数字ハイライトのみ／報道=紺ベタ名前セル＋白ベタ得点
セル＝§9.7の「黒地白／白セル黒数字」と同型／コーポレート=面なしの2セル分の袋文字＋
下罫1本／バラエティ=黄座布団の名前セル＋黒座布団の得点セル）。得点は
`font-variant-numeric: tabular-nums` で固定幅・**エントリー全員の数字桁を揃える**
（1人だけ2桁になっても他の1桁のセル幅は動かさない）。角丸・発光・平行四辺形は
実物にもあるが（格闘ゲーム大会実装）§9.5 の語彙（面・エッジ・罫の3つだけ）を優先し
持ち込まない。

## 9.9 投票・クイズ（2026-08-31 追補 — 選挙結果CGの実装コードから構造抽出）

投票・クイズ結果グラフィックの実装にあたり、**実際に放送・報道の現場で使われた**開票・投票
結果の実装（`git clone` 経由で取得。大学系テレビ局の実選挙特番向け CasparCG テンプレート1本
＋ NPR（National Public Radio）が実際に公開した米国中間選挙2022の結果ページのソース一式
（うち1点は実運用のスクリーンショットを含む））を集め、構造だけを抽出した（配色は各局・各社
固有の党派色であり模写しないが、「何と何がどう並ぶか」は投票・クイズの選択肢一覧に転用できる）。

| 実測項目 | 観察 | 出所 |
|---|---|---|
| **行の骨格** | 「選択肢ラベル＋数値」の2要素が基本。数値は得票数・パーセントのどちらか、または両方を右詰め・等幅数字で出す | NaSTAuk/General-Election-Graphics（実選挙特番のCasparCG CG）・nprapps/elections22（NPR実運用サイト） |
| **プレート型（罫なし）** | ラベルを不透明のベタ面プレート（党色）に白抜き、数値も同色ベタのプレートに白抜き数字。**バーの長さでは比率を表現しない**——面の分割だけで区切る（§9.7の「セル分割は面の色替え」と同型） | NaSTAuk の `.constpartyname`/`.constvotes`（実際の開票CGのCSS実装） |
| **バー型（罫1本）** | ラベルの下に**細い**（実装値0.6em＝フォントサイズの6割程度の高さ）バーを1本だけ敷き、幅を「得票 ÷ 合計 × 100%」に比例させる。**トラック（未達部分の溝線）は描かない**——塗り部分だけを描く。上位・当選の行は面の濃淡だけで強調し、バー自体の色は変えない | nprapps/elections22 の `resultsTableCandidates`（実際に公開された結果ページのLESS/JS実装） |
| **パーセント表示の丸め** | 小数1桁または整数（実装は `Math.round(percent*1000)/10` と `Math.round(percent*10000)/100` の2箇所を確認・どちらも四捨五入）。得票数は3桁区切り | 同上 `resultsBoardPresident`／`resultsTableCandidates` |
| **合計0件の扱い** | 実装は `percent * 100 || 0` で確実に0%を出し、割り算のクラッシュを避けている——「まだ誰も投票していない」状態は実運用でも起こりうる前提で書かれている | nprapps/elections22 |

**設計への反映**（`voteParts.tsx`）: 細いバーを使う理由が元からあるテーマ（式典＝金の細罫、
コーポレート＝既存の下罫1本と同じアクセント色バー）は**バー型**、面の分割だけで区切ってきた
テーマ（報道＝紺ベタ×白ベタの2枚重ね、バラエティ＝黄座布団×黒座布団）は**プレート型**にした——
**どちらも実際に運用された CG のソースから見つかった2系統であり、新しい第3の意匠は作っていない**。
バーはトラック（未達部分の線）を描かず塗り部分だけ（実装と同じ）。パーセントは整数％表示、
得票数は3桁区切りの小さな補助数字。合計0件は全選択肢0%・末尾に「まだ投票がありません」の
1行を添える形に倒し、0除算やNaN表示は起こさない。

## 9.10 写真枠（2026-08-31 追補 — 実際に使われた放送グラフィックの構造抽出）

題字画面（フルスクリーン題字・`FullscreenTitle`）に写真枠を足すにあたり、`git clone` 経由で
放送・配信で実際に使われたグラフィック実装6本（米大統領選挙特番の開票中継を模したタイトルカード
実装1本 `eigentaylor/margin-matters`＝候補者名＋写真を実測寸法込みで再現したコメント付きCSS、
放送用ロワーサード／CasparCGテンプレート5本 `chukwumaijem/vMix-Titles`（実運用XAML）・
`JonFreer/CasparCG-LowerThirds`・`sytem/esport-templates`・`rse/lowerthird`・
`WASD-Gaming/fgc-scoreboard`（実キャプチャ画像つき））を集め、構造だけを抽出した。
参考として、会議・カンファレンスの登壇者紹介ページ（Web、放送物ではない）も22件横断で見たが、
下記のとおり**放送物とは別の文法**だと分かったため模写しない。

| 実測項目 | 観察 | 出所 |
|---|---|---|
| **写真枠を持つ実装は稀** | 放送用ロワーサード・スコアボード実装5本（vMix-Titles・CasparCG-LowerThirds・esport-templates・lowerthird・fgc-scoreboard）はいずれも人物写真を使わない（ロゴ画像はあっても氏名は文字のみ）。**常設のロワーサードは写真無しが実物の主流**——写真が付くのは「開票特番の候補者紹介」のような単発のタイトルカードに限られる | 上記5実装横断確認 |
| **矩形クロップ・角丸は最小限** | 唯一写真を使う実装（開票特番タイトルカード）は角丸 **10px**（写真枠の一辺110–168pxに対し6–9%）——**正円のアバターではなく矩形の軽い面取り**。会議登壇者ページ（Web）は22件中ほぼ全てが正円（`border-radius:50%`）だったが、これは「Web UI」の文法であり放送物には見られなかった——正円は使わない | `eigentaylor/margin-matters` `.en-cp-overview-photo` |
| **写真の脇の区切りは罫1本（面は敷かない）** | 写真そのものに **2〜3px の縁取り**（アクセント色）を回し、短距離ドロップシャドウ（`0 6px 20px rgba(0,0,0,.4)` 程度）で背景から浮かす。座布団（面）は敷かず、写真自体の縁だけで区切る——§9.5「罫は1要素1本まで」に合致する最小構成 | 同上 `.en-cp-overview-photo` |
| **配置は「題字→写真→氏名」の縦積み** | 開票特番タイトルカードは見出し文字が最上段、**その下に写真、さらに下に氏名**の順（写真が主役氏名の直上に来る＝写真と名前が対になる）。写真とテキストの左右分割は**ロワーサード**（画面下端の帯）で使う配置であり、フルスクリーンの題字カードでは縦積みが実物の型だった | 同上（`.en-cp-overview-title` → `.en-cp-overview-photos` → `.en-cp-overview-name` の実装順） |
| **写真サイズは画面に対しごく控えめ** | 実装のカード全体に対し写真は一辺20〜30%程度（`clamp(110px,26vw,168px)`）——写真を画面の主役にせず、氏名・題字と釣り合う脇役として扱う | 同上 |

**設計への反映**（`outputPartsExtra.tsx` FullscreenTitle）: `photoUrl` があるときだけ、既存の
題字（無変更）と金細罫の下に矩形の写真を追加する。写真は `object-fit: cover` で矩形にクロップし、
**角丸は最小限**（6px）、**縁は金の罫1本**（2px・`GOLD` 色）＋短距離ドロップシャドウ（既存の
`0 3px 8px rgba(0,0,0,.45)` と同じ処方）で暗幕から浮かせる——座布団（面）は敷かない。サイズは
画面比で控えめ（240×300px・セーフエリア幅1728pxの約14%）にとどめ、写真の下に発表者の肩書・氏名を
続ける（**題字→金細罫→写真→肩書→氏名の縦積み**。実物の「タイトル→写真→名前」の順をそのまま
踏襲）。`photoUrl` が無いとき、または画像の読み込みに失敗したときは写真枠を一切描画せず、
既存の中央揃えレイアウトのまま変更しない（写真の有無・成否でレイアウトが破綻しないことを優先）。
題字パーツは他のテーマ分岐（`telopTheme.ts`・§9.6）をまだ持たない実装のため（`FullscreenTitle` は
常に式典テーマの造形で描く）、写真枠も式典テーマの語彙だけを対象にした——他テーマへの展開は
テーマ分岐そのものが実装されるときに合わせて判断する。

## 11. In/Out トランジション契約（実装値・2026-08-31 追補・段6-3）

[graphics.md](graphics.md) §5「Out = In の逆再生」の実装値。**部品固有の演出ではなく、
全部品共通の汎用フェード**（`GraphicsOutputPage.tsx`・`ConsolePreview.tsx` の外側に被せる
ラッパー1枚・`pages/graphics/CgTransition.tsx`）。個々の部品（`nameParts.tsx` 等）は
一切変更していない。

- **cue の pageId が変わった瞬間** = そのスロットの鍵（`page.id`）が入れ替わる:
  - **In（新しいページ）**: `opacity 0→1` ＋ `scale(0.98)→scale(1)`。**400ms**・
    `cubic-bezier(0.16, 1, 0.3, 1)`（軽い減速＝ease-out）
  - **Out（古いページ）**: 即座にアンマウントせず、`opacity 1→0` ＋
    `scale(1)→scale(1.02)`。**同じ 400ms**・`cubic-bezier(0.7, 0, 0.84, 0)`
    （In の逆再生＝ease-in。厳密な時間反転カーブの近似）
  - スケールの基準点はキャンバス中央（`transform-origin: center center`）。
    トランジション用の層はキャンバスと同じ 1920×1080 を明示するので、部品側の
    `bottom` / `right` 基準（例: `nameParts.tsx` の `bottom: SAFE_Y`）はそのまま効く
- **同じ pageId が残っている間はアニメーションを再生しない。** ページの `fields` が
  変わっても（±ボタン等）中身だけを差し替える。時計・カウントダウン・速報帯が
  フェード中でも刻み続けるのはこのため（`serverNowMs` の再描画はラップの外側で起きる）
- **PVW の文脈表示（`dim`）はフェードの不透明度に掛け算する**（0.4 倍）。他は透明度・
  スケール以外のプロパティに触れない
- DOM からの除去は `onTransitionEnd` を主経路にし、発火しない環境向けに
  `setTimeout`（400ms + 80ms）のフォールバックを添える
- 実ブラウザ確認（`npm run verify:up` の DB・実 Chromium・出力画面／送出コンソール両方）で、
  crossfade・時計の秒更新継続・OUT 後の完全消去を確認済み
