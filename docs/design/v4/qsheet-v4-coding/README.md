## 3. 決めたことの要約（ここだけ読めば方針が分かる）

1. **バンドルもベースパスも `/qsheet/` のまま。** 資料ID付きの既存 URL 5本
   （`editor` / `onair` / `rundown` / `prompter` / `audio`）は**1つも変えない**。
   本番当日に配る URL がそこで成立しているため。
2. **資料は案件配下にネストしない。** 案件の URL は入口（ジャーニー）専用。
   絞り込みはクエリ（`?project=` `?date=` `?scope=`）で表す。
3. **`qsheet_documents.data`（JSONB）は Yjs の所有物。サーバーは書かない。**
   `collab.persist` が3秒ごとに丸ごと上書きするため、これは好みではなく**構造上の要請**。
   スケジュール表も AI の提案も Excel の取込も、**全部この制約から設計が決まっている。**
   **例外は新規 INSERT だけ**（ルームがまだ無いので安全）。
4. **書き込みはクライアントが `applyDataUpdate` で行い、サーバーは記録するだけ。**
   `updater` は必ず `prev` の関数にする（定数を返すと同時編集で入った行が黙って消える）。
5. **スケジュール表は `qsheet_documents` に相乗りしない。** 専用テーブル5本＋共有1本。
   時刻は `INTEGER`（その日の 00:00 JST からの分）で持ち、日跨ぎは `25:30 = 1530`。
6. **ひな形の適用は「その場でコピー」。** `source_template_*` に **FK を張らない**ことで、
   「適用後にひな形を直しても既存の表は動かない」を**約束ではなく構造で**保証する。
7. **進み具合に画一的な判定式を作らない。** サーバーは数えた事実だけ返し、
   画面は3値の手がかり（資料なし／触ってある／最近動いた）に落とす。
   **「決まった」と言えるのは人がピンを押したときだけ。**
8. **Excel を入出力の正にする**（`.xlsx`）。ヘッダは2行（日本語見出し＋非表示の機械キー）、
   行に ID 列を置き、**取込は既定で差分マージ**。破壊的な `replace` は廃止。
   書き出しはサーバーの1か所に寄せて「2本あって出力が違う」を構造的に消す。
9. **11ブロック型は1つも減らさない。** 減らすのは「AI が書く型」だけ（第1版は `scenario` のみ）。
   `slide` は**編集 UI を作る**（作らないと実質10型になる）。
10. **AI の出力は `data` に直接書かず、提案テーブル（`qsheet_ai_proposals`）に置く。**
    人がプレビューで取捨選択して取り込み、**採番された id を記録**する。
    差分は**その id 集合だけ**を突合するので、人が後から足した行を AI の誤りに数えない。
11. **締めは2段。** 取り込みから7日（＝AI 起因の修正）と、本番の翌日（＝本番直前の動き）。
    片方だけだと、当日の直しを取りこぼすか、数か月の通常の練り直しが AI の誤りに混ざる。
12. **成果の主指標は「AI が置いた尺の精度」。** 人が直したあとの尺（`planned_sec`）ではない。
    そのために**本番の実尺を保存する `qsheet_cue_actuals` を新設**する
    （**AI が無くても次回の尺見積もりに効くので、単独で価値がある**）。
13. **ベクトル検索は入れない。** 欲しいのは自然文の類似ではなく構造の類似（案件種別・会場・尺・
    ロール構成）で、全部カラムか JSONB から数えられる。`CREATE EXTENSION` を1本も打っていない
    本番 DB に、1機能のために拡張を入れない。
14. **MCP は「提案まで」。** 台本そのものは MCP から変えない。
    制作資料のツールだけは**静的 API キーを拒否し OAuth actor 専用**にする
    （台本は文書単位の秘匿で、共有 actor に見える範囲を定義できないため）。
15. **AI が落ちても業務は止まらない。** 提案は別テーブル、記録は全部 best-effort、
    無人バッチに AI 呼び出しを1つも置かない。**本番中は AI を1回も呼ばない。**
16. **今ある操作を落とさない。** InsertGap・Shift 範囲選択・列とロールの折りたたみ・
    マイクの前 cue 継承・Ctrl+S・競合バナー・ゴミ箱・QR 共有は**そのまま維持**する。
17. **画面と帳票に出す名前は `MINI_APPS[].label` だけ**（`進行台本` / `スケジュール表`）。
    `Qシート` / `qsheet` は URL・テーブル名・MCP ツール名の**内部識別子**としてのみ残す。

## 9. この設計群が守っている「絶対に踏まない」地雷

新しく参加する人向けの要約です。**どれも実測で踏んだ実績があります。**

1. **IME 安全な入力部品（`BufferedInput` / `BufferedTextarea` / `EditablePill`）を
   素の `<input>` に replace しない。**「さくら」→「ささくさくらさくら」になります。
2. **全セクション・全行に安定した id（`genId()`）。** 欠くと Yjs の差分器が行を
   指数的に複製します（**実測 3→769→100万行**）。deep copy で**id を重複させるのも同じ地雷**です。
3. **`applyDataUpdate` の3手順（`backfillIds` → `yDocToData` → `ensureStableIds(updater(prev))`）を崩さない。
   `updater` は必ず `prev` の関数にする。**
4. **上書き保存で下書きを消さない。** 確定前スナップショット（`applied_payload` /
   `before_data`）が無いと、AI の修正差分が**永久に**取れません。
5. **正常な業務更新を AI の誤りとして数えない。** ONAiR の案件は数か月更新され続けます。
6. **切り詰めたログを教師データと呼ばない。** `mcp_audit_log.args` は1000文字で切れます。
   全文の正は `ai_outputs.payload_snapshot`。
7. **確認フラグを差分と呼ばない。** 「見ました」は修正差分ではありません。
8. **数えられないものを数えたふりをしない。** 見えない資料は件数に入れない。
   顧客反応は**測れないと正面から書く**。
