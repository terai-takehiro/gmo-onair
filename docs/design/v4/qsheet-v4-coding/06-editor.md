## 3. `slide` に編集 UI を作る（11型を実質10型にしないため）

`CueRow.tsx:565-574` は**破線の枠を描くだけで、書き込み経路がありません**（読みだけの幽霊型）。
04 §2-4 は「AI に書かせない」、05 §5 は「常に空文字」、03 §11-2 #5 は
「v4 で画像を入れる UI を作る前提。作らないなら Excel 側も列を出す意味が薄い」と
**全員が保留**しており、**誰も「作る」と言っていませんでした。**
このまま実装すると `slide` は v4 でも空欄のままで、
**「11種類は1つも減らさない」という利用者の絶対条件が実質破れます。**

**決め: 作ります。新しい仕組みは1つも要りません。**

- セルの値は `cell.image`（`scenario`/`video`/`audio`/`telop` の `entries[0].image` と同じ持ち方）。
- アップロードは**既存の `ImageDropZone` と `/qsheet/upload-image`** をそのまま流用
  （5MB 上限・マジックバイト検証・重複ハッシュ命名・FS 保存）。
- 表示は既存の画像セルと同じ。差し替え・削除も同じ。
- Excel では**ファイル名を読み取り専用列**に出す（03 §4-2 のまま。**画像の本体は往復しない**）。

**作らない選択をする場合**は、「**11型のうち `slide` は表示のみ**」を
§10 の先頭に上げて利用者に明示してください。黙って空欄のままにしないこと。

## 5. ゴミ箱と「テンプレとして保存」

### 5-1. ゴミ箱は残す（用途を限定する）

`lib/trash.ts` / `TrashDrawer.tsx` は**人が画面で消したもの専用**にします。

- ⚠️ **Excel 取込の退避先には使いません**（03 §8-2 を変更）。
  `trash` は `data` のトップレベル extra で、`ydocDiff` が変化のたびに配列まるごと置換するため、
  100 行退避すると 3 秒ごとの `qsheet_doc_yjs.state`（BYTEA・全体スナップショット）に丸ごと乗り、
  Yjs のトゥームストーンで**縮みません。**
- ⚠️ **復元時は `genId()` で id を採り直す。** `makeTrashItem` は payload を
  **`id` ごと deep copy** するので、同じ id の行が別経路で復活していると
  `sections` に同じ id が2つ並び、`keyById` が片方を握りつぶして差分が壊れます。
- 保持件数に上限を置く（既定 100 件・超えたら古いものから落とす）。

### 5-2. 「テンプレとして保存」— 要確認

現状 **`sectionTemplates` は保存しかできず、読み手が実装に0件**です
（適用側の grep 0）。しかも `CueTable.tsx:762` は rows を **id ごと deep copy** するので、
**「テンプレから挿入」を作った瞬間に同一 row id が2つ生まれます。**

**どちらかを選んでください（§10-2）:**

- (a) **作り込む**: 「テンプレから挿入」を作る。
  **保存時に id を落とし、適用時に `genId()` で採り直す**（両方やる）。
- (b) **やめる**: 保存ボタンごと落とす（使われていない機能を残さない）。

**放置は選べません。** 放置すると、次に誰かが挿入側を作った日に地雷を踏みます。

## 6. 印刷／PDF は `PreviewModal` を正にする

### 6-1. 現状（実装を読んで確認した事実）

| 経路 | 実体 | 使われているか |
| --- | --- | --- |
| `PreviewModal.tsx`(791行) | **ブラウザ印刷**。A4/A3 縦横・文字サイズ・余白・白黒・列の取捨・改ページ方式（`flow`/`role`・`qs_print_pagemode`）・ページ番号 | **これが実際に使われている** |
| `server/.../routes/pdf.routes.ts:84` | pdfkit で PDF を生成 | **クライアントから1度も呼ばれていない。** しかも `stage_diagram` と `slide` を出力から外している（`:168`） |

02 §10-4 は「Qシート側は pdfkit で PDF を出しています」と書いていましたが、**事実ではありません**
（02 側も訂正済み）。

### 6-2. 決め

**`PreviewModal` を正とし、`pdf.routes.ts` は廃止します**（別 PR・1リリース回してから）。

- 理由: 03 が「書き出しが2本あって出力が違う」を構造的に潰したのに、
  **印刷で同じ問題を残す理由がありません。**
- `PreviewModal` の設定（用紙・文字サイズ・余白・白黒・列の取捨・改ページ方式）は
  **1つも落としません**（`qs_print_pagemode` の localStorage 保存も含む）。
- 11型のうち `stage_diagram` と `slide` は**印刷に出す**（`pdf.routes.ts` が外していたのは
  pdfkit で描けなかったからで、ブラウザ印刷なら描けます）。

**サーバー PDF を正にしたい場合**（メール添付・バッチ生成が要る等）は、
`PreviewModal` の全機能を移す必要があるので**別の設計になります**。→ §10-3。

## 10. 利用者に確認すべきこと

1. ⚠️ **`slide`（スライド）は v4 で編集できるようにしますか。**
   現状は**枠を描くだけで書き込めません**。設計では**作る**前提です（§3）。
   作らない場合、「11型のうち `slide` は表示のみ」という状態が続きます。
2. **「テンプレとして保存」（ロールのひな形）は使っていますか。**
   保存はできますが**呼び出す画面がありません**。(a) 呼び出しを作る／(b) 機能ごとやめる（§5-2）。
3. **印刷は今のブラウザ印刷（`PreviewModal`）のままでよいですか。**
   サーバーで PDF ファイルを作る必要（メール添付・自動生成など）がありますか（§6）。
4. **ゴミ箱に何件まで残しますか**（既定 100 件）。また、**何日で自動的に消えてよいですか。**
5. **CSV 取込を今も使っている業務がありますか。**
   新しい Excel 経路が1リリース回ったら**旧 CSV 取込を消す**予定です（03 §11-2 #9）。
6. **モバイルで台本を編集していますか。**
   していた場合、**PC と違う形で保存されていたセルが自動で PC の形に寄ります**（00 §2）。
   見た目が変わる可能性があるので、事前にお知らせすべき方がいれば教えてください。
