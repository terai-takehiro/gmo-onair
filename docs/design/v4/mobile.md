## 2. 決めごと 8つ（`spRules` の逐語）

**「やってはいけない例」が各項目に付いています。** そこが要点です。

| 決めごと | やってはいけない例 |
| --- | --- |
| **主操作は下半分に置く** — 押すものは画面の下から 400px 以内。上半分は読むだけ | 右上だけにある確定ボタン |
| **終わらせるのはシートで** — 一覧の行から画面遷移させない。下から出るシートで確定し、終わったら次の1件へ | 行タップ→別画面→戻ると先頭に戻る |
| **1画面に1つのことだけ** — PC の2〜3カラムを縦に積まない。優先度の低い列は畳む | PC の右カラムをそのまま下に流す |
| **セーフエリアを空ける** — 下タブの下に 22px、上は 48px 以上 | 画面の最下端に貼り付けたボタン |
| **入力は端末に任せる** — 金額は数字キーパッド、日付は端末のピッカー、音声はキーボードのマイク。期限は「明日18:00／3日後18:00／日時を選ぶ」を先に出す | 自作の録音UI・自作の日付ホイール |
| **電波が弱い前提で作る** — 現場の記録は端末に溜めて後で送る。送信中も操作を止めない | 1件ごとに通信して失敗で止まる |
| **本番中は画面を消さない** — 役割URLの間は自動ロックを止める。暗い配色で「いま／つぎ」の2枚だけ大きく | 切れているのに緑のまま |
| **スワイプに意味を持たせない** — 横スワイプで完了・削除を割り当てない（手袋と片手では誤爆する） | スワイプでしか出せない操作 |

## 5. 作る順番（案）

**下から出るシート（`Sheet`）が無いと ⑧ も ④ も作れない**ので、先に部品を作ります。

| 段 | 中身 | なぜこの順 |
| --- | --- | --- |
| **M0** | 共通部品: **下から出るシート**・段（`2 / 3`）・期限プリセット（明日18:00…） | ⑧④⑤⑦ が全部これを使う。無いと「行→別画面→戻ると先頭」になる |
| **M1** | ⑧ やること ／ ① トップ | 毎日開く2枚。M0 の実証を兼ねる |
| **M2** | ⑦ 受付（貼って送るだけ）／ ⑤ 打合せを録音 | 外で使う2枚。既存の取込・Whisper をそのまま呼ぶ |
| **M3** | ⑩ 今日の現場 ／ ⑬ 今日の予約 ／ ⑫ 入金の確認 | 「今日ぶんだけ」の3枚。読む専用なので軽い |
| **M4** | ② ③ ⑥ 案件まわり ／ ⑪ 探すの残り | 数が多いので最後 |
| **M5** | ⑨ 機材（別バンドル・オフライン溜め込み） | 唯一 `client-equipment` 側。設計判断が要る |

**⑨ だけ先に決めることがあります**: 「端末に溜めて後で送る」は
`localStorage` に積んで送信を再試行する仕組みで、**二重登録をどう防ぐか**
（同じ機材を2回読んだとき）を決めてから作ります。

## 6. 実装のときに守ること

- **PC 用の画面に `sm:hidden` を足して分岐させない。** 1つのファイルが
  2つの情報設計を持つと、どちらを直しているのか分からなくなります。
  **スマホ専用の画面はルートを分ける**（例 `/m/today`）か、
  画面の中で**別の部品**に切り替えます
- **下端固定は自分で書かない。** `<PageHeader primaryAction>` に渡せば
  シェルが下タブの上に置きます（`shell/primaryAction.ts`）
- **44px・13px は部品側で効いています**（`tokens-v4.css` の `@media (max-width:1023px)`）。
  画面ごとに `min-h-tap` を書き足す必要はありません
- **測ってから出す。** 375px の実測は `scripts/` に残していません
  （毎回書き捨て）。横はみ出し・44px 未満・13px 未満・JS エラーの4つを数えます
