## 2. 決めごと 8つ（`spRules` の逐語）

**「やってはいけない例」が各項目に付いています。** そこが要点です。

| 決めごと | やってはいけない例 |
| --- | --- |
| **主操作は下半分に置く** — 押すものは画面の下から 400px 以内。上半分は読むだけ | 右上だけにある確定ボタン |
| **終わらせるのはシートで** — 一覧の行から画面遷移させない。下から出るシートで確定し、終わったら次の1件へ | 行タップ→別画面→戻ると先頭に戻る |
| **1画面に1つのことだけ** — PC の2〜3カラムを縦に積まない。優先度の低い列は畳む | PC の右カラムをそのまま下に流す |
| **セーフエリアを空ける** — 下タブの下に 22px、上は 48px 以上 | 画面の最下端に貼り付けたボタン |
| **入力は端末に任せる** — 金額は数字キーパッド、日付は端末のピッカー、音声はキーボードのマイク。期限は「明日18:00／3日後18:00／日時を選ぶ」を先に出す | 自作の録音UI・自作の日付ホイール |
| **電波が弱い前提で作る** — 現場の記録は端末に溜めて後で送る。送信中も操作を止めない | 1件ごとに通信して失敗で止まる |
| **本番中は画面を消さない** — 役割URLの間は自動ロックを止める。暗い配色で「いま／つぎ」の2枚だけ大きく | 切れているのに緑のまま |
| **スワイプに意味を持たせない** — 横スワイプで完了・削除を割り当てない（手袋と片手では誤爆する） | スワイプでしか出せない操作 |

  （出庫予定 `status=planned` ＋ 返却期限 `due_date`。実装は `rooms/MobileToday.tsx`）
- **`equipment` の権限がある人にだけ出します。** 無い人に空の枠を出すと
  「今日は出庫が無い」と読めますが、実際は見えていないだけです
- **出庫の行に時刻を書きません。** `planned_out_date` / `due_date` は日付だけの値で、
  時刻の列に混ぜると「0:00 に出庫」と読めてしまいます
- **`今日 / 明日 / 今週` のタブは前/次の日にしました。** 「今週」は
  7日ぶんの予約を1画面に積むことになり、現場で目的の日に着くまでスクロールが要ります

### ⑪ 探す（⌘K のスマホ版） ✅ **作った（M4 で全部そろえた）**
やること（やり取りを記録／機材QR／予定を入れる／案件をつくる）／
場所（お客様・お金・機材・Qシート・ふりかえり・設定）／最近見たもの
- 行き先と必要な権限は `platform/pages/search/shortcuts.ts` の表に置きました。
  画面に直接並べると、**権限の書き忘れがそのまま「押すと 403」**になります
- **モックとの違い3つ**（理由はファイルの冒頭に書いてあります）:
  やり取りを記録 → **2つに分けた**（打合せを録音 ⑤ ／ 電話・その他を貼る ⑦）／
  予定を入れる → **「自分の予定を入れる」**（スタジオ予約を作るのは PC）／
  Qシート → **「制作資料」**（v4 の呼び名）
- **最近見たものは端末の中だけ**（`client-v4/recent.ts` ・ 8件まで）。
  サーバーに表を作ると**案件を開くたびに1行 INSERT** することになり、
  しかも「見た」は業務の記録ではないので消えても誰も困りません。
  **別の端末では出ないことを画面に書いて**います
- **積むのは画面ごとではなくシェルの中の1か所**（`platform/RecentTracker.tsx`）。
  画面に1行ずつ足すと書き忘れが起き、しかも
  「最近見たものに出ない」という**気づけない壊れ方**をします。
  **読めてから積みます** — URL だけで積むと 404 の行が残ります

### ⑫ 入金の確認（財務管理） ✅ **作った**
金額の縦並び・入金の記録
- 実装は `finance/pages/closing/MobileCollect.tsx`（`/budget/billing` の幅で切り替え）
- **できるのは「入金があったことの記録」1つだけ。** モックの
  「スマホに置かないもの」に**お金（表が横に伸びる）**が挙がっているのに ⑫ だけ端末枠が
  あるのは、置かないのが**台帳の表**で、**片づく1つの仕事**は置くという切り分けだからです
- **並びは支払期日の近い順**（過ぎたものが先頭）。入金の確認は遅れているものを拾う作業です
- **取り消しは置きません。** 経理の訂正は記録が残る場所（PC）でやるべきで、
  スマホで戻せると誰がいつ戻したのか分からなくなります
- **入金日は今日で入ります**（別の日は PC から）。そう画面に書いてあります

### ⑬ 今日の予約（カレンダー）＋ ⑩ 今日の現場 ✅ **作った**
時刻の縦並び ／`空きを押さえる`（下端固定）
- 実装は `production/pages/rooms/MobileToday.tsx`（`/studio/calendar` の幅で切り替え）
- **`空きを押さえる` は「部屋の空きを見る」にしました。** 予約を作るのは
  部屋・時間・案件・用途を決める作業で、PC のダイアログは入力欄が十数個あります。
  **押しても何も起きないボタンは置きません**
- **終日を先頭に**、そのあと開始時刻順。終日は時間の幅を持たないので並べられません
- **前の日から続いている予約は「今日の開始時刻」で書きません**（`〜終了時刻` と出す）
- **下限は日付だけで問い合わせます。** 終日の予約は日付だけで保存されるので、
  `T00:00` を付けるとその日の終日がまるごと落ちます（② 部屋の空きと同じ理由）

## 6. 実装のときに守ること

- **PC 用の画面に `sm:hidden` を足して分岐させない。** 1つのファイルが
  2つの情報設計を持つと、どちらを直しているのか分からなくなります。
  **スマホ専用の画面はルートを分ける**（例 `/m/today`）か、
  画面の中で**別の部品**に切り替えます
- **下端固定は自分で書かない。** `<PageHeader primaryAction>` に渡せば
  シェルが下タブの上に置きます（`shell/primaryAction.ts`）
- **44px・13px は部品側で効いています**（`tokens-v4.css` の `@media (max-width:1023px)`）。
  画面ごとに `min-h-tap` を書き足す必要はありません
- **測ってから出す。** 375px の実測は `scripts/` に残していません
  （毎回書き捨て）。横はみ出し・44px 未満・13px 未満・JS エラーの4つを数えます
