## About the Design Files
**同梱の HTML は design reference（デザイン参照物）です。プロダクションコードとしてコピーするものではありません。**

意図した見た目と挙動を示すプロトタイプなので、実装は **既存コードベース（React + TypeScript + Tailwind / `client`, `client-equipment`, `client-daily`, `client-qsheet` ほか）の確立されたパターンとライブラリで作り直してください**。HTML をそのまま埋め込まないこと。

各 HTML は「Design Component」という自作形式（`.dc.html`）で、テンプレート＋ロジッククラスの2部構成です。ブラウザで直接開けます。実装時に読むべきは以下の3点だけです。

1. **テンプレート部分のインラインスタイル** — 寸法・色・字送りの正解
2. **ロジッククラスの配列定義**（`PARTNERS`, `CUES`, `SP_RECV` など） — 画面が扱うデータ構造と現実的なサンプル値
3. **`onair-data.js`** — 全アプリで共有しているサンプルデータ層

## Fidelity
**High-fidelity（ハイファイ）**です。色・タイポグラフィ・余白・状態変化はすべて確定値です。ピクセル単位で再現してください。ただし DOM 構造とクラス設計は既存コードベースの流儀に合わせて構いません。

## 前提となる設計方針（実装前に必ず読む）

この設計は次の方針に沿っています。実装で崩さないでください。

### 1. 縦の整列
一覧・テーブル・工程行など「同じ意味の要素が縦に並ぶ」ところは、必ず桁と端をそろえます。

- バッジ・チップは**固定幅の枠**に入れ、文字数で幅を変えない。値がない行も同じ幅の空きスロットを置いて列を保つ
- 数値・日付は `font-variant-numeric: tabular-nums` で右揃え、または固定幅スロットで左揃え
- 期間は「開始日」「〜」「終了日」を**別要素**に分け、それぞれ固定幅（`05/12〜05/31` を1文字列で右揃えにしない）
- 列幅は固定＋`flex-shrink: 0`。伸縮させるのは名称列だけ。名称列は `min-width: 0` ＋ `text-overflow: ellipsis`
- アイコン・チェックボックス・アバターも固定サイズの枠に入れる

### 2. 金額表記
**￥を左端・数字を右端**にそろえます。縦に並んだとき桁が一直線になること。

```
[￥の枠 12px, flex-shrink:0] [数字の枠 flex:1, min-width:0, text-align:right, tabular-nums]
```

- `¥1,234,567` のような1文字列にしない
- 金額のない行も同じ枠を置く（￥だけ薄字で残すか、空の枠）
- マイナス記号や補助記号は￥の左に固定幅スロットで置く

### 3. スマホUI
スマホは「手触り」が最優先。PCの情報をそのまま縮小して載せません。

- **出す情報を絞る。** その画面で今すぐ判断・操作することだけ。参照系の詳細はPCに任せ「PCで見る」導線だけ置く
- **1画面1目的。** タスクを消化する／状態を確認する／1つ選ぶ、のいずれか1つ
- **表・多列レイアウトは使わない。** 縦積みのカードにし、2行目に補足をまとめる
- **タップ対象は最低44px、実質48〜56pxを標準に。** 主要アクションは画面下部に固定した大きなボタン
- **編集・設定系はPC。** マスタ／テンプレート編集はスマホに置かず案内のみ
- 本文13px以上、見出し15px以上

### 4. ネーミング
業務システムとして自然な用語を使います（標準工程／個別タスク／未確認事項／活動履歴／持ち帰り事項 など）。幼稚・過度に平易な言い回しは避けます。ボタンは動作を書く（「直す」「足す」「戻す」「押さえる」）。

## Interactions & Behavior

### 共通
- **hover**: 行 = 背景を `#f7f8fa` / `#fbfcfd` に。ボタン = 背景 `#f2f4f7` または罫線をアクセント色へ。アイコンボタン = 24–26px の角丸に背景
- **選択状態**: 背景 `#f4faff`（案件管理系）/ `#fff7ed`（制作資料系）＋ 左ドット＋ウェイト 800
- **画面遷移**: `screenIn` アニメーション（.34s）
- **未実装操作**: トーストで「〜はこれから作ります」。実装時は削除すること
- **確認の必要な操作**（削除・メンバー外し・休業日削除）: 即実行せず「〜する前に、〜を確認します」と条件を出す

### 状態の4分類
どの画面でも状態は次の4つに寄せています。バッジの色は Design Tokens の対応色を使います。
1. 完了・在籍・取引中 → 緑
2. 進行中・待ち・招待中・与信確認 → 橙
3. 超過・未着・停止 → 赤（停止・休職は灰）
4. 未着手・なし → 灰

### フォーム
- 値引き上限超過は**保存を止めず**承認待ちにする
- 金額の同時編集は 409 で止める（他の項目は同時編集可）
- 読み取れなかった項目は空欄のまま残し、赤で「読み取れませんでした」と出す（勝手に埋めない）

## State Management

各画面の状態は「画面ごとに1キー」でまとめる方針です（モック側の `renderVals()` も同じ形）。

```
{ screen, site, role, pkind, ngroup, tpl, tplOff, cue, ... }
```

実装では画面単位のフックまたはストアスライスに分けてください。モック側で個別キーを大量に増やしたら描画が止まった実績があります（1画面 = 1キー）。

必要なデータ取得:
- 全アプリ共通: 現在ユーザーと権限（役割）、通知件数、アプリ一覧
- 案件管理: 案件、ネタ、タスク、見積・明細、料金表マスタ、請求、BOX フォルダ

## Assets
- `logo-onair.svg` — GMO ONAiR ロゴ（上辺バー左）
- `logo-box.svg` — BOX ロゴ（書類タブ）
- アイコンは **lucide**（`data-lucide` 属性で指定）。実装では `lucide-react` を使うこと
- 写真素材は使っていません

### 注意（lucide）
モックでは `<i data-lucide>` を `<svg>` に差し替える方式のため、再描画でアイコンが増殖する問題がありました。React 実装では `lucide-react` のコンポーネントを直接使えばこの問題は起きません。
