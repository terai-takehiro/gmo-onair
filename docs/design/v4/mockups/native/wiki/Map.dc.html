Wiki ── 考え方の地図

Markdown で書いた文章を、木に並べて、探せて、AI が読める道具。Notion の全部は作らない。
「会社の決めごと」を古びない形で置き、AI が答えられなかった質問をページを書く種に変える。

新しいブロックアプリ ／ 設計（判断待ち） /wiki ・ 権限の区画 wiki ・ docs/design/v4/wiki.md
1 書く PC・スマホ ・ 各分野の担当
##見出し目次は自動
- [ ]チェックリスト閲覧でも押せる
|表スマホでは縦のカード
> [!]注意書きGitHub と同じ書き方
[ ]( )ONAiR カード案件・機材へのただのリンク

まず手入力。 記号や `/` を覚えなくても書け、「AI で整える」で手順書の形の Markdown になる（いま／整えたあと を並べて見せる）。Markdown で書けないブロックは作らない。

2 検索・読む PC・スマホ ・ 全員
検索
タイトル×3・見出し×2・本文×1 で点数。拡張なしで始め、遅くなったら pg_trgm。
AI に聞く
読めるスペースの公開ページを根拠に、出典つきで答える。出典が無ければ答えず「足りないページ」に登録する。評価は3値（役に立った／言い直して／的外れ）。
外から読む・書く
REST GET …/pages/:id.md ・ MCP 5本（search / get / list / create / update）・ スペースまるごと .md の zip。書き込みは必ず下書き。

スマホでも書ける。手入力してから「AI で整える」で Markdown の形に（道具の帯は5つ）。

3 育てる 月1回 ・ スペースの担当
見直し期限
公開から 12か月（既定）。過ぎると札が付き、担当に通知。「見直した」で伸びる。Notion に無い、この道具の中核。
足りないページ
AI が答えられなかった質問（回数順）。「ページを書く」→ AI が会話と ONAiR のデータから下書き → 人が直して公開 → 次からは答えられる。
AI の直され方
下書きの無修正率・よく直される点・回答の評価。ai_outputs／ai_corrections から導出。助言として次の下書きに載る。

「AIを使い捨てにしない」5条件は設計書 §7-3 の表。使うほど賢くなるのは足りないページを書く経路。

利用者に見せる語は6つ
スペース分野ごとの棚。閲覧範囲の単位（全員／指定メンバー）
ページMarkdown 1本。木に並ぶ
ブロック段落・見出し・表・画像・注意書き。`/` で追加
テンプレート手順書・議事メモ・障害報告・機材の使い方 の型
履歴保存のたびに残る版。2つの版の違い・戻す
見直し期限担当が次に見直す日。過ぎたら札と通知

使わない語: プロパティ・データベース・ワークスペース・フロントマター・アーカイブ（→ 一覧から隠す）。

Markdown ネイティブ ── 3つの約束
1
本文の正は Markdown の文字列（DB の列 body_md）。画面はそれを描いて書き戻すだけ。HTML や独自 JSON を正にしない
2
Markdown で書けないブロックは作らない。 GFM ＋ 注意書き・折りたたみ・ONAiR カード（ただのリンク）だけ。データベースは作らない
3
外から同じものが読める・書ける。 REST の .md・MCP 5本・スペースまるごとの書き出し（.md の木＋YAML の見出し）と取り込み

「ファイルを正にする」は採らない ── 権限・検索・履歴・バックアップ・同時編集を自前で作ることになる（設計書 §5-2）。
