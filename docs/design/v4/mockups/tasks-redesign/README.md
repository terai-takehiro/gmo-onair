# タスク・依頼 — 再設計モック（2026-09）

`/daily/tasks`（日常業務アプリの「タスク・依頼」）をモックから設計し直したもの。
4枚のアートボード（`.dc.html`）と配置（`canvas.json`）で、
[`../v4-mockup-dailyops.dc.html`](../v4-mockup-dailyops.dc.html) にこの画面の節が無かった穴を埋める。

要件の正は [docs/archive/2026/2026-07-25-collaboration-and-personal-agent.md](../../../../archive/2026/2026-07-25-collaboration-and-personal-agent.md)
の D2（重要度 × 緊急度）／ D3（依頼）／ D8（画面）／ D9（期限）。
**この文書は要件を置き換えない。** 要件で決まっている 4 タブ・9 マス・
「今日やること 3 件」・期限必須はすべて残したうえで、**画面の作りだけ**を直す。

| ファイル | 内容 |
| --- | --- |
| `Delegations.dc.html` | PC・依頼タブ（一覧 ＋ 選んだ1件の詳細）。**今回の芯** |
| `Request.dc.html` | 「依頼する」ダイアログと、受け手側の返答（相談・辞退の理由入力） |
| `MyTasks.dc.html` | PC・マイタスクタブ（優先度順の一覧） |
| `Mobile.dc.html` | スマートフォン 390px（依頼タブの一覧とシート） |

## 何が成立していなかったか（現行実装）

**① 依頼タブから依頼を出せない。**
依頼タブ（`pages/tasks/DelegationsTab.tsx`）は「受けた依頼」「出した依頼」を読むだけの画面で、
**依頼を作る操作が1つも無い**。手で1件出す唯一の道は マイタスク タブの `追加` を開き、
担当者を自分以外に変えることで、**選ぶまでそれが依頼になると分からない**。
投入口を AI（案件管理トップの入力欄・要件 D4）に寄せた結果、
**手で出す動線が画面から消えていた**。依頼の画面の主操作は「依頼する」でなければならない。

**② 1件が縦長カードで、全行にコメント欄が付いている。**
1行が バッジ4種 ＋ 題名 ＋ 相手 ＋ 期限 ＋ 本文 ＋ 操作ボタン3つ ＋ コメント欄の折りたたみ
で構成され、5件並ぶと画面が操作ボタンで埋まる。**どれが自分の番なのかが読めない。**

**③ 承諾した依頼を、依頼タブで完了にできない。**
承諾のあと片づける操作がこのタブに無く、マイタスクへ移らないと対応済にできなかった。

**④ 絞り込みが「対応済の依頼も表示」の1つだけ。**
未返答だけを見る・差し戻しだけを見る、ができない。件数も出ない。

**⑤ 色が直書き。** `violet` / `amber` / `sky` / `rose` を素の Tailwind 値で書いており、
v4 の状態トークン（`--warning` / `--destructive` / `--success` / `--info`）に乗っていない。
バッジの幅も可変なので、縦に並べたとき右端がそろわない（`_rules.md` 1「縦の整列」）。

**⑥ ページ幅がこの画面だけ違う。**
`mx-auto max-w-5xl p-4 sm:p-6`。日常業務アプリの他の11画面はすべて
`flex flex-col gap-4 p-3 lg:gap-5 lg:p-6`（全幅）で、この画面だけ中央に寄って狭い。

## 変更点

1. **依頼タブの主操作を「依頼する」にする。**
   `PageHeader` の `primaryAction` を**タブごとに変える**（マイタスク＝タスクを追加／
   依頼＝依頼する）。PC は右上・スマホは下端固定に共通シェルが置く。
   ダイアログは汎用のタスク追加とは別に作り、**相手が先・期限が必須**の形で並べる
   （`_form-order.md` 2-1「依存する欄は依存される欄より下」＝ 相手 → 期限）。

2. **一覧と詳細を分ける（master-detail）。**
   一覧は1行（状態 96px ／ 内容 ／ 相手・案件 ／ 期限 128px）に揃え、
   **選んだ1件だけ**を右のパネルで開く。本文・やり取り（コメント）・操作はパネルの中。
   同じアプリのセキュリティカード（`pages/SecurityCardsPage.tsx`）と同じ形。
   スマホは一覧をカードにし、選んだ1件をシートで開く。

3. **「あなたの番」を先頭に1行で出す。**
   受けた未返答 ＋ 出したが差し戻された件数。押すとその絞り込みに入る。
   0 件のときは帯そのものを出さない（空の帯は場所だけ取る）。

4. **状態の絞り込みを受けた／出したで同じ5つにする。**
   すべて／未返答／承諾／差し戻し／完了。件数つき（`FilterChips`）。
   **押す前に 0 件だと分かる**（`filterChips.tsx` の設計理由と同じ）。

5. **承諾した依頼を、このタブで対応済にできるようにする。**
   受け手が承諾済の依頼を開くと詳細パネルに `対応済にする` が出る。
   サーバーは `is_completed=true` で `delegation_status='done'` に落とす（既存の挙動）。

6. **滞留と期限超過を行に出す。**
   3 日反応が無い依頼は行に印を付ける（要件 D3）。期限超過は `--destructive` の帯。

7. **マイタスクも同じ規律に寄せる。**
   絞り込みを `FilterChips`（すべて／期限超過／本日／期限未設定／完了）にし、
   一覧を `Row` / `RowSlot` に置き換える。警告帯は2本を1本に畳む
   （「重要 高 × 緊急 低が 0 件」と「やらない候補が 5 件以上」は同じ**棚卸しの促し**）。
   「今日やること 3 件」（要件 D8）と 9 マスボード（要件 D2）は残す。

8. **ページ幅を他の画面に合わせる。**

## 用語

[docs/wording.md](../../../../wording.md) のルール6〜9 に従う。

| 使う語 | 使わない語 | 理由 |
| --- | --- | --- |
| 依頼する | 依頼を出す・お願いする | ルール8（動詞は1組に固定） |
| 未返答 / 承諾 / 差し戻し / 完了 | 未承諾・保留・却下 | 既存の `DELEGATION_LABELS` に合わせる |
| あなたの番 | ボールを持っている・自分ごと | ルール9（比喩を作らない）。「番」は口頭で言える基本語 |
| 対応済にする | 片づける・消化する | ルール9（口語・比喩） |
| メモ履歴 | 投入ログ・書き留めたもの | ルール5（技術用語を画面に出さない）・ルール9（「〜もの」で名詞を作らない） |
