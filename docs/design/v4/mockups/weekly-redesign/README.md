# ウィークリー活動報告 — 再設計モック（2026-09）

`/daily/weekly` を**モックから作り直した**もの。5枚のアートボード（`.dc.html`）＋ 配置
（`canvas.json`）で、[`../v4-mockup-dailyops.dc.html`](../v4-mockup-dailyops.dc.html) の
ウィークリー活動報告の節を置き換える提案です。

| ファイル | 中身 |
| --- | --- |
| `Main.dc.html` | PC・読む（確定済みの週） |
| `Draft.dc.html` | PC・書く（下書き／週を作った直後。詳しい内訳を開いた状態） |
| `Before.dc.html` | いまの実装の画面（同じ週・同じ状態）。比較用 |
| `WeekMenu.dc.html` | 週を選ぶ・足す・消す（ポップオーバーと削除の確認） |
| `Mobile.dc.html` | スマホ 390px |

## 何を変えたか（設計の要点）

1. **並びを「AIの製造工程」から「読む人の順」へ。** 自動集計 → AIの要約 → 人のトピック、
   ではなく **要点 → 数字 → 出来事 → 詳しい内訳**。見出しは「AI の要約」ではなく
   **「今週の要点」**で、AI は本文の下の**署名**（AIが下書き → 誰が直したか）に降ろす。
2. **主役を「週」にした。** 画面見出しが週そのもの（`◀ 8月31日 〜 9月6日 ▶` ＋ 今週／先週の印）。
   最初の1週の日付に以後が引きずられる状態（検証環境が 7/6 スタートのまま止まっていた件）が、
   画面の側からも解消する。
3. **状態の印を1つに畳んだ。** 「下書き／確定済み（+ 確定した人と時刻）」の1本。
   「確認済み／未確認」は自分の既読なので右上の`読んだ`に、「AI作成」は署名行に統合。
4. **空のときは言い訳ではなく最初の一手。** 空の箱を3つ並べず、数字は出したうえで
   「AIに下書きを作らせる／自分で書く」の2択だけを出す。
5. **詳しい内訳（パイプライン・活動の内訳・イベント・来週）は畳む。** 読む人には要らず、
   書く人には材料なので、下書きの画面では開いておく。
6. **週の追加・削除をきちんと作る。** 日付入力の直置きをやめ、月のカレンダーから
   「週の行」を選ぶ（作成済みの週はその場で分かる）。削除は行の `⋯` の中で、
   確定済みの週は選べず理由を出す（サーバーの断り方と同じ）。
