# このプロジェクトの方針

## スマホUIの共通ポリシー
スマホは「手触り」が最優先。PCの情報をそのまま縮小して載せない。

- **出す情報を絞る。** その画面でユーザーが今すぐ判断・操作することだけを出す。参照系の詳細情報はPCに任せ、必要なら「PCで見る」導線だけ置く。
- **1画面1目的。** タスクを消化する／状態を確認する／1つ選ぶ、のいずれか1つに絞る。
- **表・多列レイアウトは使わない。** 縦積みのカードにし、2行目に補足をまとめる。
- **タップ対象は最低44px、実質48〜56pxを標準に。** 主要アクションは画面下部に固定した大きなボタンで。
- **スクロールは短く。** 折りたたみ・段階表示を使い、初期表示は「今やる分」だけ開く。
- **編集・設定系はPC。** マスタ／テンプレート編集などはスマホに置かず案内のみ。
- 文字サイズは本文13px以上、見出し15px以上。数字は大きく。

## 縦の整列ポリシー（必須）
一覧・テーブル・工程行など「同じ意味の要素が縦に並ぶ」ところは、必ず桁と端をそろえる。今後つくるものだけでなく、既存も見つけ次第直す。

- **バッジ・チップは固定幅の枠に入れる。** 件数バッジ・状態バッジ（完了／進行中／待ち／未着手 など）は文字数で幅を変えず、列ごとに固定幅＋中央寄せ。値がない行も同じ幅の空きスロットを置いて列を保つ。
- **数値・日付は等幅（tabular-nums）で右揃え、または固定幅スロットで左揃え。** 期間は「開始日」「〜」「終了日」を別要素に分け、それぞれ固定幅にする（`05/12〜05/31` を1つの文字列で右揃えにしない）。
- **列幅は固定＋`flex-shrink:0`。** 伸縮させるのは名称列だけ。名称列は `min-width:0` で省略する。
- **アイコン・チェックボックス・アバターも固定サイズの枠に入れる。** 有無で行がずれないようにする。
- 行の区切り線・行高は左右で分かれたレイアウト（固定列＋スクロール列）でも同じ値を使う。

## フリーズ再発防止ポリシー（v4モックアップ／必須）
v4モックアップは1ファイルが巨大なため、次のどれかを超えると**画面が固まって操作不能になる**。実際に固まった原因は「1画面ぶんの値を細かいキーで大量に足したこと」と「同じ枠組みのマークアップを画面ごとに丸ごとコピーしたこと」だった。以後は必ず守る。

- **画面を1つ足すごとに値のキーは1つ。** `renderVals()` に `gpTkRows` `gpTkFilters` … と個別キーを並べない。画面ごとに `gpTk: { rows, filters, count, add }` の形で**1キーにまとめ**、テンプレート側は `{{ gpTk.rows }}` のようにドットで読む。
- **同じ枠組みは共通部品にする。** 上辺バー・左メニューのように画面ごとに同じマークアップが並ぶものは、必ず `AppTopbar.dc.html` / `AppSideMenu.dc.html` のような子コンポーネントに寄せ、`dc-import` で使う。コピーして増やさない。
- **測って書き戻す処理を入れない。** `clientWidth`／`scrollWidth` を測って `transform` を書き戻す「長体フィット」のような処理は、再測定と再描画が連鎖して固まる。長い文字列は `overflow:hidden` ＋ `text-overflow:ellipsis` で収める。
- **画面を足したら必ずその場で表示確認する。** ファイルを書いたら、追加した画面を開いて描画とクリックを確かめる。固まった場合は「新しく足した値のキー」から先に疑う。
- **1回の作業で足す画面は1つずつ。** 2画面を同時に足して固まると原因の切り分けに時間がかかる。

## 金額表記ポリシー（必須）
金額は**￥を左端・数字を右端**にそろえる。縦に並んだときに桁が一直線になっていること。

- 1つの金額は「￥の枠」と「数字の枠」の2要素で組む。`display:flex` の枠に入れ、￥は `flex-shrink:0`、数字は `flex:1; min-width:0; text-align:right`。
- 数字は必ず `class="num"`（等幅・桁区切り）。`¥1,234,567` のような1つの文字列にしない。
- 金額のない行も同じ枠を置き、列がずれないようにする（￥だけ薄字で残すか、空の枠を置く）。
- 合計・小計・粗利など、まわりに枠幅がない場所は枠に `min-width` を与えてから右揃えする。
- マイナス記号や補助記号は￥の左に固定幅スロットで置く。

## アイコン増殖の防止（必須）
lucide は `<i data-lucide>` を `<svg>` に置き換えるが、React が再描画で `<i>` を戻すため、前回の `<svg>` が残って**チェックマークなどが増殖する**。

- アイコンを描き直す前に、必ず「同じ親に `<i data-lucide>` が復活している `svg.lucide`」と「同じ親に2つ以上ある `svg.lucide`」を捨ててから `createIcons()` を呼ぶ。各ファイルの `icons()` がこの処理を持つこと。
- 画面を足したら、その画面を何度か行き来してアイコンが増えないか確認する。

## モックアップのファイル構成（必須）
1ファイルが大きくなると描画が止まる。アプリ単位でファイルを分ける。

- `v4-mockup-main.dc.html`（トップ・ナビ・案件管理・設定・スマホ・設計メモ）と `v4-mockup-project.dc.html`（プロジェクト管理）。共通部品は `AppTopbar.dc.html` / `AppSideMenu.dc.html`。
- アプリ間の移動は `<a href>` とページ遷移で行う。1つのファイルに別アプリの画面を `dc-import` で抱えない（読み込み時に合算され、結局止まる）。
- **ファイル名は半角英数字とハイフンだけ**にする。日本語名のファイルは一度読み込んだあと固まる事象が起きた。
- 目安として1ファイル 25万文字を超えたら、その時点でアプリ単位に割る。

## ネーミング
業務システムとして自然な用語を使う（標準工程／個別タスク／未確認事項／活動履歴 など）。幼稚・過度に平易な言い回しは避ける。
