## 1. 結論（先に答え）

**テロップCG は「番組で出すテロップを、台本の順に並べておき、本番でボタンひとつで出す」道具。**
それ以外の何かに見えた瞬間が負け。

利用者に見せる語は **4つ** だけにする。

| 語 | 意味 | 旧実装の語 |
| --- | --- | --- |
| **テロップ** | 画面に出す1枚（種類＋文言＋見た目） | ページ |
| **種類** | ネーム／題字／一覧／ティッカー／カウントダウン／スコア／投票／ランキング／速報／サイド | 部品 |
| **出す順** | この番組の送出リスト。コーナーで区切れる。進行台本と同期できる | 送出リスト・呼出番号・sortOrder |
| **見た目** | 番組ごとの配色・書体・ロゴ | テーマ＋テンプレートの一部 |

画面は **PC 4枚・スマホ 2枚・出力 1枚**。いまの 9 ルートから減らす。

```
ハブ（JourneyPage）の「テロップCG」タイル
 └ ① テロップ一覧（準備）      /techops/graphics/:ownerKey            ← ホーム。出す順＋右に編集
     ├ ② 本番モード            /techops/graphics/:ownerKey/live       ← 暗い全画面。OA / NEXT / TAKE / CLEAR
     ├ ③ テロップを作る・直す   ①の右パネル（種類を選ぶ → 入力 → プレビュー）
     ├ ④ 設定（4タブ）         /techops/graphics/:ownerKey/settings   ← 出力URL／見た目／同時に出せないもの／連携
     ├ ⑤ 依頼（スマホ）        /techops/graphics/:ownerKey/request    ← ディレクターが文言だけ書く
     └ ⑥ 一覧（スマホ・閲覧＋緊急CLEAR）  /techops/graphics/:ownerKey  ← 同じURL。見るだけ＋いま出ているもの＋緊急時は消せる（§12-4）
 出力（OBS）                      /techops/graphics/output/:projectId    ← 変更なし
```

本番の動詞は **3つ**（TAKE＝出す／CLEAR＝消す／進める）。旧アプリの実績ある「NEXT → TAKE → CLEAR、
TAKE すると NEXT が自動で次へ」に戻す（§8）。

## 2. いまの何が問題か（実装を読んだ証拠）

「UI/UX が最悪・何をしたいのか分からない・導線が分かりにくい」を、原因のレベルまで分解した。

| # | 症状 | 原因（実装上の事実） |
| --- | --- | --- |
| 1 | 開いた画面が何の道具か読めない | ハブの上段に**操作が7個平積み**（テーマ Select・部品ライブラリ・送出コンソールへ・発注フォーム・名簿から一括生成・旧CGから移行・ページを作る）。主・従・年1回の管理操作が同じボタン形で並び、その下に統計バー・自動退出ルールの編集表・未作画の発注・ページ表・出力URLカードが縦に積まれる。**設定と準備と本番の入口が1画面に混ざっている** |
| 2 | 覚える語が多すぎる | 利用者に見える概念が **17**: CGプロジェクト・ページ・呼出番号・スロット（6種）・部品（10種）・テンプレート・テーマ・校正（3段）・発注（3状態）・名簿・退出ルール・演出SE・外部連携・PGM/PVW・5動詞・オールクリア・続き。プロ用送出機（Viz Trio／Chyron）の語彙をそのまま画面に出した |
| 3 | 導線が分からない | 左メニューにテロップCGのサブ項目が**無い**（`nav.ts` の `GRAPHICS_RE` は ownerKey を拾うだけ）。設定系（演出SE・外部連携）は**ハブ → 部品ライブラリ → テンプレート管理 → 当該**の3階層下に埋まり、`/techops/top` からは5クリック。しかも `GRAPHICS_RE` が `sounds`・`interactive-link` を含まず、その2画面ではサイドバーが「トップ」1項目に崩れる（バグ） |
| 4 | 戻る先がばらばら | 戻りリンクの文言が画面ごとに「テロップCG ハブへ戻る」「テロップCGへ戻る」「ページと送出リスト」の3種類。移行ツールだけヘッダーの作りが違い `navigate(-1)` で戻る |
| 5 | 本番画面が重い | 送出コンソールに PGM／PVW／操作卓（番号呼出＋5動詞）／スコア±／ランキング操作／スロットレーン／ページ一覧の**7区画**。「TAKE できるのは PVW だけ」の規律のため、1枚出すのに「行を PVW へ → TAKE」の2操作。旧アプリは「NEXT → TAKE」で TAKE 連打で回っていた |
| 6 | 死んだ・嘘の UI | 部品ライブラリの「新しい部品をリクエスト」はトーストを出すだけ。カードの「24番組」「11番組」「4 フィールド」はモックの固定文字列で実データと無関係。`ranking` 部品はカタログに存在しない（10種中9枚） |
| 7 | 名前の揺れ | 「題字＋肩書」（カタログ）と「題字」（正式ラベル）、「スコアボード」と「スコア」、「サイド」と「サイドスーパー」が同居 |
| 8 | スマホで文脈を失う | PC 専用 7 画面の逃げ先が全部 `/techops/top`。番組のハブへ戻さない |
| 9 | 発注の一覧が二重 | ハブの「未作画の発注」と発注フォーム画面の「自分が出した発注」が別画面・別クエリで並存 |
| 10 | 出力画面が孤島 | 出力URLカードからしか到達できず、逆に戻る手段も無い（認証なしは正しいが、配り方が設定にまとまっていない） |

根っこは1つ: **「テンプレート → ページ → 送出リスト」「PGM/PVW・5動詞」というプロ送出機の型を、
2〜3人で回す GMO のスタジオにそのまま持ち込んだ**こと。型の知識は正しいが、画面に出す語と操作の数を
現場の規模に合わせて畳んでいなかった。

## 3. 使う人と3つの場面

| 場面 | 誰が | どこで | やること |
| --- | --- | --- | --- |
| **準備**（本番の数日前〜直前） | ディレクター／AD | スマホ・PC | 出したい文言を決める（依頼）。台本に書いたテロップをそのまま出す順にする |
|  | 技術（作画・送出担当） | PC | 種類を選んで文言を入れ、見た目を当て、確認済みにする。OBS に出力URLを貼る |
| **本番** | 送出担当（技術 or AD） | PC・配信卓の横 | NEXT を確かめて TAKE。終わったら CLEAR。スコア・投票・ランキングは行の中で進める |
| **出力** | OBS／スイッチャー | ブラウザソース | 公開URL・1920×1080・透過。人は触らない |

GMO の現場は**専任の CG オペレーターがいない**（技術か AD が兼ねる）。だから本番画面は
「読めば分かる」より「**見れば分かる**」を優先し、覚える操作を3つに絞る。

## 4. 概念モデル

### 4-1. 利用者に見せる4語（§1）と、隠す語

| 隠す語 | どうするか |
| --- | --- |
| CGプロジェクト | 番組を開いた時点で自動に作る。画面に出さない（いまも `resolve` が自動作成している） |
| スロット（フルスクリーン／下部／サイド／ティッカー／時計／速報） | **種類が位置を決める**ので利用者は選ばない。内部の排他制御（1枠1枚・自動で下ろす）はそのまま。本番画面の帯では「いま出ているもの」として、位置名ではなく**サムネイルと文言**で見せる |
| テンプレート（部品の初期値＋公開フィールド） | 利用者の語からは外す。**「複製」と「前の番組から見た目と種類をコピー」**に姿を変える（DB の `graphics_templates` はそのまま流用できる）。ディレクターが文言だけ触れる＝依頼フォームが担う |
| 校正（未完成／未確認／確認済） | **「確認済み」のチェック1つ**にする。「未完成」は必須の文言が空なら自動でバッジが付く（人が3段を手で回さない） |
| 呼出番号 | 出す順の番号（1, 2, 3…）を作成時に一度だけ自動で振る。テンキー呼出はそのまま使える（§8）。**並べ替えても番号は変わらない**（§12-3。口頭で番号を呼ぶ運用と事故なく両立させるため） |
| 部品ライブラリ（カタログ画面） | 廃止。**「種類を選ぶ」ステップ**（③）がその役目。使用番組数などの固定文字列は出さない |
| 発注（テロ原） | 「依頼」と呼ぶ。一覧は1か所（①の「依頼 N件」）に統一 |
| 退出ルール | 設定の「同時に出せないもの」表に畳む。種類ごとの既定を持たせ、普段は触らない |
| PGM／PVW | **OA／NEXT**（旧アプリの用語辞典どおり。TAKE／CLEAR は現場語として残す — [terminology-review §5](../../reviews/2026-09-05-terminology-review.md)） |

### 4-2. 「部品をパッケージ化して組み合わせる」思想はどこへ行くか

graphics.md §2 の思想（部品＝描画＋フィールド＋アニメ＋専用操作＋データの口を1袋に）は**実装の構造として残す**。
変えるのは見せ方だけ:

- 利用者が触るのは「種類」。1種類＝1部品パッケージ。**種類を足す＝部品を開発する**（社内 Web 開発者の仕事）
- 「この番組のテロップシステム」＝**見た目（テーマ）＋使う種類の既定値**。これを「前の番組からコピー」できることが
  「次の番組の立ち上げが速くなる」の実体。部品の組み合わせキャンバスは作らない（`layers` の重ね合わせは
  ランキングなど必要な種類の内部実装に留める）

## 5. 画面と導線

### ① テロップ一覧（準備）＝ホーム `/techops/graphics/:ownerKey`

**この画面を開いた瞬間に「番組名・出す順・次にやること」の3つが読めること**が要件。

- 上段: 番組名（GLS・回・日付）。右に **「本番モード」**（主ボタン・赤系ではなく通常の主ボタン）、
  **「＋ テロップ」**、**「設定」**。それ以外のボタンは置かない
- その下に1行の**状態帯**: 「12件 ／ 確認済み 10 ／ 未確認 2 ／ 依頼 2件」。未確認・依頼は押すと絞り込む。
  右端に**「台本に追従」の切替**（既定 OFF・§9-3・§12-2）を置く。台本から取り込んだ番組だけに出す
- 左（主）: **出す順**。コーナー見出し（オープニング／ゲストトーク／…）で区切り、行＝
  `番号｜種類アイコン｜サムネイル（96×54）｜文言（1行目）＋補足（2行目）｜確認チェック｜⋯`。
  ドラッグで並べ替え（**番号は変わらない**・§12-3）。行を押すと右パネルに開く（**別ページに飛ばない**）
- 右（従・幅 420）: 選んだテロップの**本物のプレビュー**（出力と同じ描画・16:9）＋入力欄（種類のフィールドから自動生成・
  文字数上限つき・英語欄は「英語も出す」を開いたときだけ）＋「確認済み」トグル＋複製・削除
- 取り込みの入口は上段の「＋ テロップ」のメニューにまとめる:
  **台本から取り込む**（§9）／**名簿から作る**（Excel）／**依頼から作る**／空から作る
- 最下段に折りたたみの「OBS に貼る URL」（設定④と同じカードの縮約。ここで済む人が多い）
- スマホで開いたときは ⑥（閲覧）になる。「PC で編集」の案内だけ置き、`/techops/top` へは飛ばさない

### ② 本番モード `/techops/graphics/:ownerKey/live`（PC 専用・暗い配色・全画面）

§8 に詳述。**同じ「出す順」を、操作の形を変えて見せる**だけ。準備画面と別のリストを持たない。

### ③ テロップを作る・直す（①の右パネル）

1. **種類を選ぶ**: 10 種のカード（絵つき・位置のピクトグラム・一言）。ここが旧「部品ライブラリ」
2. **入力**: 種類のフィールド（`pageFields.ts` から自動生成）。プレビューは打つたびに更新し、
   選択中の欄を絵の上でハイライト（Viz Trio 方式・graphics.md §3 のまま）
3. **どこに入れるか**: 「いま選んでいる行の次」が既定。コーナーを選べる
4. 保存 → 行が増え、右パネルはそのまま次の入力に使える

### ④ 設定 `/techops/graphics/:ownerKey/settings`（PC 専用・タブ4つ・1画面）

| タブ | 中身 | 旧実装 |
| --- | --- | --- |
| 出力URL | メイン合成（透過）／確認用（黒背景）／英語版。コピー・QR・「OBS での貼り方」3手順 | `OutputUrlCard` |
| 見た目 | テーマ4種のプレビュー付き選択、ロゴ、**前の番組からコピー** | `ThemePicker`＋`graphics_templates` |
| 同時に出せないもの | 「◯◯が出たら △△ を自動で消す」の表。種類ごとの既定入り | `SlotExitRulesEditor` |
| 連携 | インタラクティブ（別VPS）の接続、演出SE、**旧リアルタイムCGから移す**（system_admin だけに出す） | `InteractiveLinkSettingsPanel`・`RankingSoundsPanel`・`AwardsMigrationPage` |

### ⑤ 依頼（スマホ）`/techops/graphics/:ownerKey/request`

いまの `RequestFormPage` の構造を保ち、欄を3つに絞る: **文言**（必須）／**出すタイミング**（自由記述に加えて
**台本の項目から選ぶ**）／**種類**（任意・分からなければ空）。送ると①の「依頼 N件」に入る。
自分の依頼と状態（一覧に入った／却下）はこの画面の下に出す（一覧の二重化をやめる）。

### ⑥ 一覧（スマホ・閲覧＋緊急CLEAR）

①と同じ URL。出す順と確認状態、本番中は**いま出ているもの**（OA）が上に出る。編集（文言・並べ替え）はしない。
**「いま出ているもの」の各行にだけ「消す」ボタンを置く**（§12-4・確認なしの1タップ）。
スマホから本番の並びを組んだり NEXT を送ったりはできない——できるのは「消す」ことだけ
（本番の運転は PC の②が主。スマホは PC が触れない・見えない場面での最終手段）。

### 左メニュー（`nav.ts`）

テロップCG の文脈にいるときは、サイドバーの「テロップCG」の下に **一覧／本番モード／設定** の3つを出す
（いまは何も出ない）。`GRAPHICS_RE` を `settings|live|request` に合わせ、戻りリンクの文言は
「**テロップ一覧**」の1種類に統一する。

| 旧CG（awards）からの移行ツール | **残す（隠す）** | 設定「連携」タブの中・system_admin だけ。API の GET も manager 以上に締める（棚卸し指摘） | `AwardsMigrationPage` |

## 8. 本番モードの運転モデル

旧アプリ（`client-awards`）のコックピットは **NEXT → TAKE → CLEAR** の3語で、TAKE すると NEXT が自動で
次へ進み「TAKE 連打で1本回せた」（旧マニュアルの用語辞典・`CgCockpitPage`）。現行の5動詞よりこちらが
現場に合っていた。戻す。

```
[OA いま出ている（合成・本物の描画）]   [NEXT 次に出す（本物の描画）]  [ TAKE 出す (Space) ]
                                                                        [ CLEAR 消す      ]
──── いま出ているもの ────────────────────────────────────────────────────────────
  ▣ 4 ネーム 高梨 一郎  01:12   [消す]    ▣ 7 サイド 実験映像：東都大学提供  03:40 [消す]
──── 出す順 ─────────────────────────────────────────────────────────────────────
  オープニング
   1 ✓ 題字 …            出した 13:02
   …
  ゲストトーク
   4 ✓ ネーム 高梨 一郎            ● OA
 ▶ 5 △ ネーム 小野 美咲            NEXT   ← 行を押すと NEXT。未確認は△で警告
   6 ✓ 一覧 今日のテーマ
   8 ✓ 投票 Q. 火星の1日は…        [出題 → 締切 → 開票]   ← OA 中だけ行の中に出る
  10 ✓ ランキング TOP5              [次の順位を発表]         ← 同上
```

- **TAKE** = NEXT を OA へ。同じ位置に出ているものは自動で下りる（1枠1枚・退出ルールは内部で効く）。
  TAKE 後、NEXT は**出す順の次の行**へ自動で進む（末尾で止まる）
- **CLEAR** = 最後に出したものを消す（Backspace）。「いま出ているもの」の帯からは1枚ずつ消せる。
  全部消すは上辺の別ボタンで確認つき
- **進める** = OA 中の行の中に、その種類の操作として出る（投票: 出題→締切→開票、ランキング: 次の順位、
  一覧・スコア: 次の項目）。別パネルは作らない
- **行を押す** = NEXT にする。テンキーで番号 → Enter も同じ（口頭「5番出して」の運用）
- **安全装置**（構造で守る・注意力に頼らない）: ①TAKE できるのは NEXT に**見えている**ものだけ
  ②未確認は NEXT に立てた時点で△と理由を出し、TAKE は通す（止めない。止めると本番で詰む）
  ③文言が空のものは NEXT に立てられない ④本番中は並べ替えできない（準備に戻る）
  ⑤文言の急な直しは行の「直す」→小さなシート→「反映」で確定（自由記入の即時反映はしない。
  スコア・票数だけ即時）
- **配色**: `<html class="dark">` の v4 ダークトークン（`tokens-v4.css` の `.dark`。進行・ランダウンと同じ）。
  CG の絵そのものは v4 トークンの対象外（graphics.md §5 のまま）
- **キーボード**: Space=TAKE／Esc=（何もしない・誤爆防止）／↑↓=NEXT 移動／数字+Enter=番号呼出。
  旧アプリは「ショートカット無し」を選んでいた（誤爆事故）。本モックは Space だけを主にし、他は補助

## 9. 進行台本との連携（新規・この道具の存在理由）

進行台本（Qシート）には既に**「テロップ」列**（`shared/src/qsheet/blockTypes.ts` の `telop`・各行の
`entries` に文言とメモ）があり、ディレクターは台本を書く時点でテロップの文言を書いている。
いまのテロップCGはそれを**もう一度手で打ち直させている**。

1. **台本から取り込む**（①の「＋ テロップ」メニュー）: 台本を選ぶ → テロップ列の文言が行になる。
   項目（台本の行）の並びがそのままコーナーと出す順になる。種類は文言から推定（「／」入りはネーム、
   短文は題字…）し、あとから直せる
2. **紐づけを持つ**: 取り込んだ行は台本の項目 ID を覚える（`graphics_pages.qsheet_row_id`）。
   台本側の文言が変わったら①に「台本と違います」バッジを出し、押すと差分を取り込める
3. **本番で追従する**（**既定 OFF・番組ごとに①の状態帯から ON にできる**・§12-2で確定）:
   進行（OnAir）画面で現在行が進むと、本番モードの NEXT がその項目のテロップへ自動で移る。
   TAKE は人が押す（自動送出はしない）。トークが前後する番組では OFF のままにする
4. 依頼（⑤）の「出すタイミング」も台本の項目から選べる

これは graphics.md §2 の「送出リストは台本の項目から自動生成できる（順序の正は台本側）」の最小実装で、
段5に予定されていながら未着手だったもの。

## 12. 決まったこと（2026-09-06 ユーザー回答）

1. **本番モードの「未確認」の扱い → TAKE 可能（△警告のみ・止めない）。** モックのまま確定。
   ダイアログでの二度確認は本番の邪魔になるため付けない
2. **台本に追従（§9 3）→ 既定 OFF・番組ごとに ON にできる。** 提案どおり確定。
   ON/OFF の切替は①テロップ一覧のヘッダー付近に置く（§5 に追記）
3. **番号の振り直し → 「よくわからない」との回答を受け、こちらで決めた: 番号は固定にする。**
   出す順（並べ替え）は自由に変えられるが、**呼出番号は作成時に一度振ったら変わらない**
   （旧 `call_no` 方式・Viz Trio/Chyron のコールアップ番号と同じ考え方）。
   理由: このアプリは「口頭で番号を呼ぶ」運用（§8「5番出して」）を前提にしており、
   生放送中に並べ替えで番号が変わると、口頭指示と画面の番号がずれて事故る。
   §9・§10・§6 の「番号は自動」という記述はこの決定に合わせて「番号は固定」に直した
4. **スマホの本番中の権限 → 緊急の CLEAR（消す）を許可する。** ⑥一覧（スマホ）の
   「いま出ているもの」の各行に「消す」ボタンを追加した（確認なしの1タップ。
   本番中に急いで消す場面を想定しており、PC の CLEAR と同じ「最後に出したもの」ではなく
   **行ごとに指定して消す**——スマホは PGM/NEXT の全体像を見ていないことが多いため）
5. **旧リアルタイムCGの畳み込み → 畳んでよいと承認を得た。** ただし**段A〜E（このモックの
   実装）がまだ影も形もない**状態で先に `client-awards` の配信を止めると、利用者は
   「醜いと言われた画面」も「使い慣れたアワード送出」もどちらも使えなくなる。
   そのため実行順はもとの提案どおり据え置く: **段A〜E を実装し検証環境で1本通してから畳む**。
   この承認は記録済みなので、段F（畳み込み）の実行時に改めて確認を取り直す必要はない
   （[§13](#13-旧アプリ移行中の扱い)・[段F](#11-実装の段取りモック確定後段ごとに別-pr)参照）

## 13. 旧アプリ（移行中）の扱い

- `client-awards/` は「移行中」。URL・API・配信は生かし、新しい機能は足さない
- アワード固有の演出（段階発表・Final Pitch・Celebration・演出SE・外部投票）は既にこのエンジンの
  `ranking`／`vote` 種類へ移植済み（[migration-plan](graphics-awards-migration-plan.md) 段6-5〜6-7）。
  本再設計はそれらの**置き場と操作**を変えるだけで、演出の実装には触らない
- 過去実績データの移行ツールは設定「連携」タブの管理者項目として残す。実行の判断はユーザー
- **畳み込み（「移行中」→「廃止」）は§12-5でユーザーの承認を取得済み。** 「移行中」という状態は
  期限のない待機ではなく、**段A〜E の実装が終わり検証環境で確認できた時点で畳む、と決まっている**
  終着駅つきの状態——実装が追いつくのを待っているだけで、判断待ちではない
