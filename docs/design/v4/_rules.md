# v4 で守る4つの規律

**この4つが v4 の中核です。** 見た目を新しくすることではなく、
**同じ意味のものが縦に並んだとき桁と端がそろっていること**が目的です。

破ると後から全画面を直すことになるので、**部品で強制**し、**機械で検査**します。

---

## 1. 縦の整列

一覧・テーブル・工程行など「同じ意味の要素が縦に並ぶ」ところは、必ず桁と端をそろえます。

| やること | 使う部品 |
| --- | --- |
| **バッジ・チップは固定幅の枠に入れる。** 文字数で幅を変えない。値がない行も同じ幅の空きスロットを置いて列を保つ | `<TableBadge w={n}>` |
| **数値・日付は等幅（tabular-nums）で右揃え**、または固定幅スロットで左揃え | `<Num>` `<Money>` |
| **期間は「開始日」「〜」「終了日」を別要素に分ける。** それぞれ固定幅 | `<DateRange start end />` |
| **列幅は固定 ＋ `flex-shrink: 0`。伸縮させるのは名称列だけ。** 名称列は `min-width: 0` ＋ 省略記号 | `<Row>` `<RowSlot w={n}>` `<RowMain>` |
| **アイコン・チェックボックス・アバターも固定サイズの枠に入れる。** 有無で行がずれない | `<RowSlot>` |
| 行の区切り線・行高は、左右に分かれたレイアウト（固定列 ＋ スクロール列）でも同じ値を使う | `<Row>` |

**なぜ部品にするか**: 73画面で同じ整列コードを書くと必ずどこかで崩れます。
`<RowMain>` が「`min-w-0` ＋ `flex-1` ＋ 省略記号を内包する唯一の伸びる子」なので、
**「伸びるのは名前列だけ」が構造として破れなくなります**。
`<RowSlot w={...}>` は決まった段（56/72/96/128/160/200/240px）しか受けないので、
120px のような一回限りの幅が入り込みません。
段の定義は `shared/src/client/ui/row.tsx` の `SlotWidth` **1か所だけ**で、
`<MoneyCell width>` も `<TableBadge w>` もそこを読みます。

**スマホは `<Row stackOnMobile>`。** 固定列を全部横に並べると 375px には入りません
（種別 56 + ステータス 96 + 金額 128 + 隙間 = 292px ＞ 実効幅 279px）。
`stackOnMobile` を付けると `<RowMain>` が行を独占し、固定列はその上下に折り返します
（`<RowMain>` 側に何も書かなくてよい ＝ 書き忘れが起きない）。
落としてよい列は `<RowSlot hideOnMobile>`。**幅を狭めるのではなく消す**のが方針です。

**機械の検査**: `verify-ui.mjs` が実ブラウザで**バッジの左端の座標を列ごとに集めて
1種類しか無いこと**を確かめます。これは静的な文字列検査では測れません。

## 2. 金額表記

**￥を左端・数字を右端**にそろえます。縦に並んだとき桁が一直線になること。

```
[￥の枠 12px, flex-shrink:0] [数字の枠 flex:1, min-width:0, text-align:right, tabular-nums]
```

- **`¥1,234,567` のような1つの文字列にしない。** `<Money value={n} />` を使う
- 金額のない行も同じ枠を置く（￥だけ薄字で残すか、空の枠）
- マイナス記号や補助記号は￥の**左**に固定幅スロットで置く
- 合計・小計・粗利など周りに枠幅がない場所は、枠に `min-width` を与えてから右揃え
- 万円の丸めは `manYen(n)` を使う（`Math.round` と `toFixed` は負の数で結果が違い、
  いま4通りに実装されていて食い違っている）

**機械の検査**: `check-ui-tokens.mjs` が `¥` の直後に `{` が来る書き方（手組み）を止め、
`verify-ui.mjs` が**金額の右端が ±0.5px で揃っているか**を実測します。

## 3. スマホ

**手触りが最優先。PC の情報をそのまま縮小して載せません。**

- **出す情報を絞る。** その画面で今すぐ判断・操作することだけ。
  参照系の詳細は PC に任せ「PCで見る」導線だけ置く
- **1画面1目的。** タスクを消化する／状態を確認する／1つ選ぶ、のいずれか1つ
- **表・多列レイアウトは使わない。** 縦積みのカードにし、2行目に補足をまとめる
- **タップ対象は最低44px、実質48〜56px を標準に。** 主要アクションは**画面下部に固定した大きなボタン**
- **スクロールは短く。** 折りたたみ・段階表示を使い、初期表示は「今やる分」だけ開く
- **編集・設定系は PC。** マスタ／テンプレート編集はスマホに置かず案内のみ
- 本文 13px 以上、見出し 15px 以上。数字は大きく
- 下タブは3つ: ホーム / やること / 検索

**下部固定の主アクションは共通シェルが置きます**（`<PageHeader primaryAction={...}>` を
宣言すると、PC では右上・スマホでは下端固定に配置される）。
**73画面が個別に `fixed bottom-0` を書かないこと。**

## 4. ネーミング

業務システムとして自然な用語を使います。**幼稚・過度に平易な言い回しは避けます。**

- 使う: 標準工程 / 個別タスク / 未確認事項 / 活動履歴 / 持ち帰り事項
- ボタンは**動作**を書く: 「直す」「足す」「戻す」「押さえる」
- 用語の決めごとは [`../../wording.md`](../../wording.md) にあります

---

## 状態は4つに寄せる

どの画面でも状態はこの4分類にします。色は [`_tokens.md`](_tokens.md) の対応色を使います。

| # | 意味 | 色 |
| --- | --- | --- |
| 1 | 完了・在籍・取引中 | 緑（`success`） |
| 2 | 進行中・待ち・招待中・与信確認 | 橙（`warning`） |
| 3 | 超過・未着 | 赤（`destructive`）／ 停止・休職は灰 |
| 4 | 未着手・なし | 灰（`muted-foreground`） |

---

## 操作したときの決めごと

- **hover**: 行 = 背景を `#f7f8fa` / `#fbfcfd` に。ボタン = 背景 `#f2f4f7` または罫線をアクセント色へ。
  アイコンボタン = 24–26px の角丸に背景。**`transform` は使わない**
- **選択状態**: 背景 `#f4faff`（案件管理系）/ `#fff7ed`（制作資料系）＋ 左ドット ＋ ウェイト 800
- **確認の必要な操作**（削除・メンバー外し・休業日削除）: 即実行せず
  「〜する前に、〜を確認します」と**条件を出す**（`confirmAction`）
- **知らせる**: トーストではなく**消えないお知らせ帯**（`notifySuccess` / `notifyApiError`）。
  見ていない瞬間に消えるのは「フローをストックに変える」方針に反する
- **読み取れなかった項目は空欄のまま残し、赤で「読み取れませんでした」と出す**（勝手に埋めない）

## フォームの決めごと

- **値引き上限の超過は保存を止めず「承認待ち」にする**（送付だけ止まる）
- **金額の同時編集は 409 で止める**（他の項目は同時編集可）
- 粗利率が 30% を切ると赤くなるが**保存は止めない**
