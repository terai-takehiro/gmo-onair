# 入力フォームの並び順の決めごと

> **なぜ要るか**: 機能追加のたびに欄を**フォームの一番下へ足す**のがいちばん安全で速い。
> その結果、どのフォームも「作られた順」に並び、**使う人が考える順**とはずれていく。
> 実際に v4 の全アプリのフォームを監査したところ、
> 「後で決まること」が「先に決まること」より上にある、
> 「親を選ばないと子の選択肢が出ないのに子が上にある」といった破綻が多数見つかった。
>
> 見た目（[_rules.md](_rules.md) の5つの規律）とは別の軸なので、ここに分けて置く。

---

## 1. 6つの段（この順に上から並べる）

フォームの欄は、次の6つの段のどれかに属する。**段の順序は動かさない。**

| # | 段 | 中身 | 例 |
| --- | --- | --- | --- |
| 1 | **どれに付けるか（文脈）** | これから作るものが**何にぶら下がるか**。選び直すと下の欄の選択肢が変わるもの | 案件・回・フェーズ・部屋・機材・顧客 |
| 2 | **何か（同定）** | それを**一意に呼ぶ名前**。一覧に出る見出しになる欄 | 件名・タスク名・機材名・予定のタイトル |
| 3 | **いつ（日程）** | 日付・時刻。**開始 → 終了**の順。終日・繰り返しは日時の**直後** | 開始日・終了日・開始時刻・終了時刻 |
| 4 | **誰が（人）** | 担当者・参加者・貸出先・取引先 | 担当・参加者・営業担当 |
| 5 | **いくら・いくつ（数量と金額）** | 単価 → 数量 → 税 → 合計（**自動計算は必ず手入力の下**） | 金額・数量・税区分 |
| 6 | **補足（任意）** | 無くても保存できるもの。**必ず最後にまとめる** | 備考・メモ・添付・タグ・色 |

**業務上どうしても外れるときは、その理由をコードのコメントに1行書くこと。**
書かずに外れているものは、監査で「継ぎ接ぎ」と判定する。

---

## 2. 破ってはいけない3つ

### 2-1. 依存する欄は、依存される欄より**下**に置く

選択肢が他の欄の値で絞り込まれる欄（`disabled={!projectId}` や
「案件を選んでください」を出す欄）は、**必ずその親の欄より下**に置く。
上にあると、使う人は「押せない欄」を先に触ってから戻ることになる。

### 2-2. 必須の欄の**間に**任意の欄を挟まない

必須 → 必須 → …と一気に埋めきってから、任意の段（6）に入る。
必須の間に備考や添付が挟まると、そこで手が止まる。

### 2-3. 期間は**開始 → 終了**、自動計算は**入力の下**

- 開始日より上に終了日がある、開始時刻より上に終了時刻がある、は無条件で誤り
- 合計・粗利・粗利率・残額のような**計算結果は、材料になる欄より下**に置く

---

## 3. 欄を足すときの手順

1. その欄が上の6段のどれかを決める
2. **その段の末尾**に足す（フォームの末尾ではない）
3. 段をまたぐ移動が要るなら、`useState` の宣言順や `register` の順ではなく
   **JSX の並び順**を動かす（DOM 順がそのまま Tab 順になる）
4. 2カラム（`formGrid2`）に入れるときは、**対で読む欄同士**だけを組にする
   （開始日と終了日、単価と数量）。関係のない欄を横に並べると Tab が横に飛ぶ

## 4. その他の摩擦（並び順と同時に直す）

- **初期フォーカス**: **画面ごとに書かない。** 共通シェル（`shared/src/client-v4/sheet.tsx`）が
  「PC は本文の最初の入力欄・スマホは何も当てない（ソフトキーボードでシートが潰れるため）」を
  引き受ける。最初の入力欄が意味のある先頭でない画面だけ、その欄に `autoFocus` を書く
- **Enter で保存**: `<FormDialog onSubmit>` を使い、保存ボタンは `type="submit"`
  （`onClick` と併用すると二重送信になる。[formDialog.tsx](../../../shared/src/client-v4/formDialog.tsx) 参照）
  - ⚠️ **`onSubmit` を渡したファイルでは、すべてのボタンに `type` を書く。**
    `<form>` の中では `type` を省いたボタンは**送信ボタン**なので、書き忘れると
    「キャンセル」「削除」「1行足す」が押した瞬間に保存を走らせる。
    `scripts/check-form-submit.mjs`（`npm run lint`）が止める
  - **明細行など繰り返し入力を持つフォーム・「押す前に確かめる」フォームには入れない**
    （明細を打っている途中の Enter が誤送信になる）
- **日本語入力**: 変換確定の Enter で送信しないこと（`isComposing` を見る。
  検査は `npm run verify:ime`）
