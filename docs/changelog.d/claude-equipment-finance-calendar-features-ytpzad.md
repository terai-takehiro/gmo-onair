**機材メンテナンスの記録項目を追加し、財務・カレンダー・案件台帳の要望に対応した**。

①機材管理＞メンテナンス＞メンテナンスの記録の「種類」に、リセット・再起動など運用上
クリティカルではないが再現・頻発する際はメンテナンス対応が必要な機材の履歴を残す
「記録」を追加した（`MAINTENANCE_TYPE` に `log` を追加。DBの `CHECK` 制約も
migration 294 で追随）。②同じくメンテナンスの記録に「修理引取／発送日」「修理受取／
返送日」の2項目を追加した（`maintenance_records` に `repair_sent_at`／
`repair_returned_at` を追加。記録を追加するダイアログに入力欄、一覧・カードに表示を
足した。狭い画面で商品名が消えないよう、2列は `HIDE_UNTIL_WIDE` で1024px以上まで
出さない）。

③財務ダッシュボード・各種明細（売上・仕入台帳、財務ダッシュボードの内訳）で、
案件に紐づく行のコード（GLS番号等）テキストを押すと、その案件の案件管理＞案件概要
（`/sales/projects/:id`）へ飛ぶようにした。行クリック（明細を開く・台帳へ遷移）とは
別のリンクとして扱い、既存の「押せるものを増やさない」設計（内訳の行は
button-in-button を避けるため、コードを件名ボタンの外に兄弟として置く）を踏襲した。
販管費は案件に紐づかないため対象外。

④財務管理＞仕入れ／販管費の登録フォームで、精算番号・申請URL欄のプレースホルダーに
残っていた「（任意）」表記を削除した。

⑤カレンダー＞予定を入れるの「自分の予定」「パートナーの予定」は、まだ利用できない
機能であることが分かるよう、選択肢のラベルに「（未使用）」を追記した。

⑥案件台帳のヨミステータスが「D 仮押さえ」の案件でも、新しい番組としてGLS発番が
できるようにした。境界（`GLS_BLOCKED_STAGES`）を「ネタ・仮押さえ」から「ネタのみ」に
変更し、画面側（`client/src/contexts/sales/glsIssue.ts`）とサーバー側
（`project.service.ts`）の両方を直した（2026-09-02 に一度「C 見積提案から」に
前倒ししていたが、D でも発番できず編集不能に見えるという指摘を受けさらに前倒しした）。

`node scripts/check-links.mjs`・`node scripts/check-mobile-declared.mjs` いずれも通過。
