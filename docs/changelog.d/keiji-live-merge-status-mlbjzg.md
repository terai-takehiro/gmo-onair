**計時LIVEを制作技術支援のミニアプリにする設計を作り直した**（コード変更なし）。09文書（`09-live-timer.md`）のPR7（ミニアプリとしての導線追加・改称）は、実装時に「バンドルが別で切替のたびに全画面リロードになる」「制作技術支援自身がまだ共通シェル未移行」等の理由でスコープを絞り、`frozen`を落とすだけに留まっていた（`impl/09-live-timer-impl.md`§12-11）。見送り理由の1つ（制作技術支援自身の共通シェル未移行）はその後解消済みであることを確認した上で、3つの設計案（完全統合・軽量統合・段階案）を作り、2名の判定者の評価を踏まえて「段階統合」を採用する最終設計書`docs/design/v4/qsheet-v4-coding/12-live-timer-decision.md`をまとめた。フェーズ1（レジストリ登録・ハブ導線・改称。バンドル分離のまま・DB migrationゼロ）はすぐ着手可能、フェーズ2（バンドル統合）はフェーズ1のリリース後に運用観測してから着手可否をあらためて判断する。
