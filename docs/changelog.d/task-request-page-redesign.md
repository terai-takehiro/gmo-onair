**「タスク・依頼」（`/daily/tasks`）をモックから設計し直した**（設計の正は [docs/design/v4/mockups/tasks-redesign/](../design/v4/mockups/tasks-redesign/)）。①**依頼タブから依頼を出せるようにした** — この画面は受けた／出した依頼を読むだけで、依頼を作る操作が1つも無く、手で1件出す唯一の道はマイタスクの「追加」で担当者を自分以外に変えること（選ぶまでそれが依頼になると分からない）だった。投入口を AI（案件管理トップの入力欄・要件 D4）に寄せた結果、手で出す動線が画面から消えていた。主操作をタブごとに変え、依頼タブは「依頼する」（相手 → 内容 → 補足 → 期限 → 重要度・緊急度の順・期限必須）にした。②**一覧と詳細を分けた** — 1件が縦長カードで全行にコメント欄の折りたたみが付いており、5件並ぶと画面が操作ボタンで埋まってどれが自分の番か読めなかった。一覧は1行（状態96px／内容／期限128px）に揃え、本文・やり取り・操作は選んだ1件のパネル（スマホはシート）にだけ出す。③**「あなたの番」を先頭に出した**（受けたのに返していない ＋ 出したが差し戻されて決めていない）。タブの見出しにも同じ件数を出す。④**状態で絞り込めるようにした**（すべて／未返答／承諾／差し戻し／完了・件数つき）。以前は「対応済の依頼も表示」のトグル1つだけだった。⑤**承諾した依頼をこのタブで対応済にできるようにした**（以前はマイタスクへ移らないと片づけられなかった）。⑥マイタスクも絞り込みを件数つきのチップ（すべて／期限超過／本日／期限未設定／完了）にし、一覧を `Row` に載せ、警告帯2本を1本に畳んだ。チームは行から「依頼する」を開けるようにした。⑦**ページ幅を他の画面に合わせた** — `mx-auto max-w-5xl p-4 sm:p-6` はこのアプリでこの画面だけで、他11画面はすべて全幅だった。⑧`violet` / `amber` / `sky` / `rose` / `slate` の直書きと `text-[10px]` 等の直書きをやめ、状態トークン・型スケールにそろえた。⑨あわせてモックとの食い違いを詰めた — 依頼の行に**やり取りの件数**を出し（差し戻しの理由はコメントとして残るので、印が無いと「なぜ返ってきたのか」に気づく手がかりが行に1つも無かった。サーバーの `SELECT_MY_TASK` に `comment_count` を足した。migration 240 の `idx_task_comments_task` が効くので索引だけで数えられる）、詳細パネルの「優先度」に一覧・9マスと同じ点数バッジを添え、「あなたの番」の帯のボタンを件数入り（`3 件だけ表示`）にした。⑩Codexレビュー指摘4件を直した — **(P1)** `listMyTasks` は `LIMIT 200` を掛けるのに完了かどうかを見ずに優先度順で並べていたため、完了ぶんまで取る呼び方（画面が件数を数えるために必要）と組み合わせると**優先度の高い完了済みが未完了を上限から押し出し、動いている仕事が画面から黙って消えていた**（実測: 完了250件＋低優先の未完了5件で、未完了は 0/5 件しか返らなかった）。`ORDER_BY_PRIORITY` の先頭に `is_completed ASC` を足し、切られるのは必ず完了ぶんからにした（同条件で 5/5 件）。**(P2)** マイタスクで「完了」を選んだままボードに切り替えると9マスすべてが0件になり1件も開けなかったのを直した（ボードに渡す前にもう一度未完了で絞っていた）。**(P2)** メモ履歴の行は全体を `<button>` で包んでいるため `stackOnMobile` が効かず、375px で固定列が316pxを使い切って本文に1pxしか残っていなかった（実測）。スマホは縦積みのカードに組み直した（本文の幅 325px）。**(P2)** チームの自分の行から「依頼する」を押すと、選択欄は空に見えるのに自分のidが入ったまま送信でき、依頼ではなく自分あての個人タスクが黙って1件できていた。自分の行にはボタンを出さず、ダイアログ側も一覧に無い相手は「選んでいない」扱いにした。要件（4タブ・9マス・今日やること3件・期限必須）は変えていない。検証: `npx tsc -b client client-daily server`・`npm run lint`・`npm run test` 通過。
