「案件詳細・案件を直すページが通常遷移だとリロードしないと最新値が出ない」報告を
マルチエージェントで再究明した。⚠️ **前回のコミット(9ba8343)は `['project', id]` という
1つの鍵にしか `staleTime:0`/`refetchOnMount:'always'` を入れておらず、案件詳細の各タブが
持つ自前の `useQuery`（タスク/タスク列・メンバー・見積(2箇所)・議事録・活動ログ・当日資料・
回一覧(2箇所)）は共通の `staleTime:60_000` のままだった**。60秒以内の通常遷移では
古いキャッシュがそのまま出て、ハードリロード（QueryClientごと作り直し）だけ正しくなる、
という報告どおりの症状を再現する経路だったため、該当する9箇所すべてに同じオプションを
追加した。あわせて「案件を直す」（`ProjectFormRoute.tsx`）が `key={id}` で案件ごとに
ページを作り直すのに対し案件詳細側は素の `ProjectDetailPage` のままだった非対称も
`ProjectDetailRoute.tsx` を新設して揃え（防御的・現状は未露出）、`DetailHeader.tsx` が
同じ `['project', id]` をオプション違いでもう一度 `useQuery` していた二重観測も
props 渡しに直した。検証: SPA内でタブを行き来するだけで外部から加えたメンバー・
活動ログが（リロード無しで）反映されることを実機で確認。
⚠️ 検証中に見つけた独立した実害バグも直した — `project.service.ts` の `update()` が
「渡さなければ今の値を保つ」の解決値 `targetCustomer` を計算していたのに、実際の
UPDATE 文2箇所は未解決の生の `customer_id`（省略時は undefined）をバインドしており、
`customer_id` を省略した PUT が NOT NULL 制約違反で 500 になっていた。

共通部品 `Label`（`shared/src/client/ui/label.tsx`）が `leading-none`（行間ゼロ）だったため、
「回を足す」ダイアログの「回の単価（任意・確定売上）」のような長いラベルが、狭い画面幅・
