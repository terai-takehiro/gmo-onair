**案件台帳のGLS分類プルダウンに「旧GLS（決算取込）」を足し、案件の削除を押せるようにした。**
①旧GLS決算取込画面（`/sales/gls-import`）はすでに案件台帳へ統合済みだったが、
統合時に「取込が終わった今は使う理由が無い」と判断して、決算取込の行だけを絞り込む
手段（サーバーには前から `source=kessan` として残っていた）を画面に持ち込んでいなかった。
取込済みの行を後から探したいという要望を受け、案件台帳のGLS分類プルダウンを
GLS-A／GLS-B／旧GLS（決算取込）／どちらも の4択にした。決算取込の行にもGLS-A／GLS-Bは
付く（migration 203でバックフィル済）ため、見た目は1つのプルダウンでも中身は
`glsCategory`と`source`という別の2軸として持ち、選ぶたびに両方をまとめて書き換える
（`nextFiltersForCategorySelect`）。片方だけ前の値が残ると「旧GLSのはずが0件」になる
事故を防ぐため。あわせて既存のGLS-A／GLS-Bの選択肢名から冗長な注記
（「（スタジオ）」「（プロジェクト）」）を外した。
②案件の削除（`DELETE /projects/:id`）はサーバーには前からあった（`sales`の`manager`権限）が、
呼び出す画面がどこにも無く、案件を削除する手段が実質存在しなかった。案件を直す画面
（`/sales/projects/:id/edit`）のヘッダーに、GLS操作と同じ並びで削除ボタンを足した
（`manager`未満には出さない）。論理削除（`deleted_at`を立てるだけ）で、ひもづく見積・
タスク・売上・仕入の記録そのものは消えず、財務の台帳などでは今までどおり参照できる
ことを確認ダイアログに明記した。
