**「役務提供完了日」を Excel・CSV・MCP から扱えるようにした**（棚卸し ⑧）。この列だけ書き出しにも取り込みにも入っておらず、**Excel から仕入を取り込むと必ず空**になっていた。⚠️ **この列だけ `DATE` 型**（他の日付列は TEXT）なので、素で SELECT すると CSV には `Mon Aug 31 2026 00:00:00 GMT+0000 (...)` という日付ですらない文字列が、Excel には `2026-08-31 00:00:00` が入る。SQL 側で `TO_CHAR` して文字列で取り出す形にした（**時間帯にも型パーサーの有無にも依存しない**）。⚠️ **Excel の書き出しの SQL は2か所ある** — 絞り込みなしの `exportQuery` と、画面の絞り込みを効かせる `buildExportQuery`。**実際に使われるのは後者**なので、前者だけ直すと画面からの書き出しに列が出ない（テストで両方に入っていることを固定した）。⚠️ **入力ガイドに「取り込みは常に新規追加です」と明記した** — 仕入の取り込みは重複を見ておらず毎回すべての行を足すので、**書き出したファイルをそのまま戻すと原価が二重に計上される**（実測で再現した）。列を足したことで「書き出す→埋める→取り込む」を自然に思いつく形になったため、この断り書きは機能の一部。⚠️ **古い Excel（この列が無いもの）を取り込んでも既存の値は消えません** — 仕入の取り込みは INSERT だけで、既存の行を更新する経路が無いことを実装で確認したうえ、実際に列を消した Excel を取り込んで「警告が出て、その列だけ飛ばし、既存の行は無傷」を確認した。検証: 実 Postgres で CSV に `2026-08-31` が出ること、Excel の書き出しに `役務提供完了日` 列が出ること、書き出した Excel を取り込むと値が入ること、列が無い Excel では警告が出て既存が無傷なことを確認。列・プレースホルダ・値の数が揃っているかのテストも足し、`$19` を `$18` に戻すと実際に落ちることを確認済み。
