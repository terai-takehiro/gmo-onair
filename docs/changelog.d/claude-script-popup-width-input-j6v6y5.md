**新規台本作成が入力しても作成できない不具合を直し、案件から自動で埋まるようにした。** 「収録日を設定」トグルが初期ONのまま日付が空だと「台本を作成」が押せなくなっていた（画面上は必須の印が無く、理由も表示されないため気づけない）ので、収録日を任意に戻し、収録日・リハーサル日にラベルを付け、未入力の必須項目名をボタンの手前に出すようにした。あわせて GLS案件を選ぶと番組名が、エピソードを選ぶと収録日が自動で入るようにし（手で打った値は上書きしない・自動で入れた欄には注記を出す）、ダイアログの幅を 448px から 672px に広げてスマホでは日付が縦に積まれるようにした。

**案件の情報を他アプリから引くための取得口を追加した。** 制作技術支援などの利用者は案件管理の権限を持たないため、案件一覧やスタジオ予約の API を叩けず、会場・本番日・リハーサル日を手で打ち直すしかなかった。案件を1件選んだときだけ叩く `GET /lookup/:projectId/context` を足し、番組名・顧客名・実施日・会場・本番日・リハーサル日だけを返すようにした（見込額や商談段階などの営業情報は返さない）。一覧側には足していないので、案件を選ぶセレクタが重くなることはない。

**ポップアップの幅の段を共通化し、既定を広げた。** 幅の上限が旧ダイアログ（512px 固定）と v4 のシート（560px と 760px の2段だけ）で別々に持たれていて、どちらも狭く、呼び出し側が画面ごとに最大幅を書き足して散らかっていた。段の名前と幅を1か所（sm 420 / md 640 / lg 840 / xl 1080 / full）にまとめて両方から読むようにし、既定を 640px に広げた。取引先の登録フォームのように幅を動かす口が無かったものにも `size` を渡せるようにした。従来の `wide` は `lg` の別名として今までどおり動く。

**案件管理・財務管理の登録フォームを広げ、スマホで潰れる入力欄を直した。** 仕入・販管費・タスク・活動記録・体制・予定など、入力が6個以上あったり日付と時刻のような横並びの組を含むフォーム14件を 560px から 840px に広げた。売上登録と案件明細で画面ごとに手書きしていた最大幅は共通の段に寄せた（幅は同じ）。あわせて、375px 幅で入力欄が2列に潰れていた4か所（グループ売上・グループ仕入の税区分、活動記録の次回アクション、控室の利用者と用途）を、狭い画面では縦に積むように直した。

**新規台本作成で、撮影場所・放送日・リハーサル日も案件から自動で入るようにした。** GLS案件を選ぶと、案件に登録済みのスタジオ（外現場を含む）・本番日・リハーサル日を取りに行って空いている欄に入れる。手で打った値は上書きせず、自動で入れた欄には出どころの注記を出し、手で直せば注記は消える。エピソードを選んだときはそちらの日付が優先される。取りに行くのに失敗しても、これまでどおり手入力で作成できる。

**機材管理・日常業務・計時・制作技術支援のポップアップも広げ、スマホで潰れる入力欄を直した。** 入力25個ある機材編集を 1080px に、保管場所・メーカー・メンテナンス・問い合わせ・スケジュール項目・共有設定などを 840px にした。表示画面URLのように長いURLを 320px の枠に入れていたものも広げた。あわせて、狭い画面で選択欄や日付欄が2列に潰れていた12か所を縦に積むようにした。削除の確認やQRコードだけのものは、意図して狭いまま残している。

**新規台本作成の自動入力の仕組みを別ファイルに分け、幅の説明が古いままだった箇所を直した。** 自動入力を足したことで新規台本作成の画面が400行を超え、1か所直すのに全部読む形になっていたので、どの欄をいつ埋めてよいかの規則をひとまとまりにして切り出した。振る舞いは変えていない。あわせて、幅の段を入れたことで既定と `wide` の幅が変わったのに古い数字のまま残っていた説明を実態に合わせた。

**案件の取得口の日付と会場の組み立てに検査を足した。** 幅の段の写しはテストで固定した一方、同じ枝で足した案件の取得口には検査が1本も無く扱いが割れていたので、日付の埋め方（多日程の中日を埋める・飛び日は埋めない・自由入力のラベルは混ざらない）と会場の組み立てを検査で固定した。会場の組み立ては案件詳細の実装の写しなので、両者が1文字も違わないことも突き合わせている。あわせて、実施日だけ他の日付と書式の検査が揃っていなかったのを揃えた。
