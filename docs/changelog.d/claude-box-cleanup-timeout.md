**失注案件の BOX フォルダの一括片づけが、本番で 504 になって1件も進まなかったのを直した**（ユーザー報告「Request failed with status code 504・0 件まで進みました」）。原因は**1リクエストで20件を処理していたこと**。フォルダ1件につき BOX を「読む→中身を数える→動かす」で十数回叩くため、20件だと**200〜300回**の呼び出しになり、**Nginx の 60 秒で切られていた**。しかも切られたのは応答だけで**サーバー側は動き続ける**ので、押した人には何件進んだのか分からない状態だった。⚠️ **件数で区切るのをやめ、時間（20秒）で区切る**形にした — BOX の応答時間はこちらでは決められないので、件数を小さくしても「遅い日は落ちる」が残るため。時間で切れば、BOX が遅い日でも必ず応答が返り、進んだぶんは記録に残る（続きは押し直せば進む）。あわせて①**名寄せ（BOX を調べて案件に結び付け直す）を片づけとは別の往復に分けた**（504 になったときは「名寄せ＋20件の片づけ」を1リクエストでやっていた）②画面側の1往復あたりの上限も 20 → 5 件に下げた（保険）③**時間切れで切り上げたときはループを続ける**ようにした — 「1件も進まなかったら止める」だけだと、BOX が遅い日に**1件も片づかないまま終わる**ため、`timedOut` を返して区別する。検証: `npm run typecheck:all` 緑、`npm run test` 1721件緑（この機能は38→41件）、`npm run lint` 緑。⚠️ **実際の BOX に対しては相変わらず未検証**（この環境も検証DBも `BOX_CONFIG_JSON` を持たない）。時間で区切る決めごと・名寄せを別の往復にすること・時間切れなら続けることの3つはテストで固定した。
