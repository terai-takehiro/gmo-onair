**「サーバー側で処理が止まりました」が、混み合っているのか壊れたのか分かるようにした**（財務の絞り込みで頻発していた件の切り分け）。⚠️ **画面は HTTP コードもサーバーのメッセージも出さない方針**なので、**混み合っている(429)・時間内に終わらない(504)・壊れた(500)が全部同じ一言**になっており、利用者も開発者も原因に辿り着けなかった。①nginx のレート制限が返す番号を**既定の 503 から 429 に変えた** — 503 のままだと「上流が詰まったときの 503」と区別できない（実測: `limit_req_status 429` で 429 が返り、無制限の場所は変わらないことを確認）。②`/api/` に**時間制限を明示した**（65秒）。書いていないと既定の 60 秒で切れて素の 504 になり、**何が遅かったのか誰にも分からない**。アプリ側の `statement_timeout` が 60 秒なので、**アプリが自分で「時間切れ」を返しきれる余地**を残す形にした。⚠️ **これは「60秒まで待ってよい」という意味ではない**（長い処理は先に 202 を返す形のまま）。③画面の文言を3つに分けた（`humanizeError`）。検証: 実物の `nginx/gmo-onair.conf` を `nginx -t` で構文検査、レート制限は実際に nginx を起動して 429 を実測。
