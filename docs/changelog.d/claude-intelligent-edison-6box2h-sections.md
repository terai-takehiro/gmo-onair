**やり取りの AI 整形で、社内メモ（予定表・シフト・体制案）の中身がほとんど落ちていたのを直した**（利用者からのご指摘「要約があまりに適当すぎる」・27時間テレビの体制想定のメモ）。①整形の形が「取引先との会話の往復」だけだったので、会話ではないメモは要約の1〜3文と短い事実8件に押し込まれ、拠点ごとのシフトの中身・技術構成の人数と機材がほとんど残っていなかった。②本文の構造（`body_struct`）に**節（見出し＋行）**を足し、AI には原文の見出しごとに**時刻・人数・機材名を原文のまま1行ずつ**置かせるようにした（プロンプト `activity-v5`。節の無い古い記録もそのまま読める）。長いメモでも途中で切れないよう、出力の上限を原文の1.5倍まで取るようにした。③画面は節を見出しと行で描き、本文を手で編集するときも節の行を1つも落とさない。既にある記録は、記録の「整え直す」を押すと新しい形で作り直せる。検証: `npm run test`（shared に節の試験を追加）・型検査・通信を差し替えた呼び出しで構造化出力のスキーマに `sections` が入ることを確認・実ブラウザ（1440px・375px）で節の表示と横はみ出し 0 を確認。
