**決算取込で新規作成した案件が、番号の履歴（`project_numbers`）に1行も残っていなかったのを直した**（Codexレビュー指摘。terai-takehiro/gmo-onair#714 のマージ後に届いた5件目の指摘で、マージが先に成立したため追加PRで対応）。決算取込（CLI版・Web版とも）が新規作成する案件は `projects.gls_number` に番号を書くだけで `project_numbers` には何も残しておらず、後日その案件を改番すると「退役させる現役の番号」が見つからず旧番号が跡形もなく消え、以後どこからも引けなくなる不具合があった。同じPR（#714）内で足した `project_numbers` 経由の検索（改番済み旧番号でも引けるようにする対応）が効いていた前提そのものが崩れていたため、新規作成の直後に `entity_code=NULL`・`scheme='gls'`（`org_transition` が 'off' の間の `issueGls()` と同じ表記）で1行残すよう `kessan-import.service.ts`・`import-kessan-dev.mjs` の両方を直した。検証用Postgres上で、決算取込で新規案件を作成→改番と同じ操作（旧番号retire・新番号発番）を実行→旧番号を含む元帳を再度取り込んでも重複案件を作らず改番後の案件に正しく紐づくことを確認した。
