**配った音声サポートの公開URLを取り消せるようにした**。公開URL（`/qsheet/audio/…`）は
**資料IDを知っていれば誰でも開けて、配ったあとに止める手段が1つもありませんでした**
（失効の列は migration 209 で消えており、それを読むコードも1行も残っていなかった）。
本番当日にQRで配るものなので、番組が終わってからも開き続けられる状態でした。
`qsheet_audio_shares` テーブルを新設し、編集画面の共有ダイアログから**再発行と失効**を
できるようにした。失効した URL は **410** を返す（404 だと「URLを打ち間違えた」に見えて
現場が本番中に探し続けるため）。URL のパス（資料ID）は1文字も変えず、トークンは
`?token=` のクエリとして追加しただけ — 公開画面は URL の値をそのまま Socket.IO の
room 名に使っているため、パスをトークンに差し替えると誰もいない room に入り cue 同期が
黙って止まる事故を避けた。**配布済みの旧URL（トークン無し）は当面そのまま開けます** —
いつ止めるかを決める材料が無かったので、まず「旧URLで開かれた」ことをログに記録する
だけにした。あわせて、公開URLから見えていた個人名を**その台本のマイク香盤に実際に
出てくる名前だけ**に絞り、Socket.IO の room を cue 用（`doc:<id>`・匿名含む全員）と
members 用（`doc:<id>:members`・アクセス権のある人だけ）に分けて、**台本の編集差分
（yjs:update）と在席者の氏名（presence:sync）が公開URLの持ち主に届いていたのを止めた**
（`cue:*` の中継は1文字も変えていない）。
検証: `npm run typecheck` / `npm run lint` / `npm run test` OK。
