**Wiki に検索・お気に入り・`.md` の出入口を足した（段D）。** 段C までは「書いて並べる」だけで、**貯めた文章を探す手段が無かった**（設計 §9 は段D を段E の土台と決めている）。①**検索の API** `GET /wiki/search`（語・スペース・タグ・担当・更新日で絞る）、②**検索の画面** `/search`（左に絞り込み・右に当たり。当たった見出しと前後の文を抜き出して**語を太字で示す**）、③**どの画面からでも開く小窓**（`Ctrl`／`⌘`＋`K`。語を入れる前は「最近見たもの」が並ぶ）、④**お気に入り**（`POST`／`DELETE /wiki/pages/:id/favorite`。ホームの区画は段A から在り、押して入れられるようになった）、⑤**`.md` の口**（`GET /wiki/pages/:id.md` は YAML の見出し付きで1枚、`GET /wiki/export?space=` はスペースまるごと zip、`POST /wiki/import` は Obsidian・Notion・ONAiR の書き出しを取り込む）を足した。⑤は設計 §5-2 の**約束3「外から読めて書ける」**の REST 側2本で、MCP（段E）は同じ組み立てを呼ぶ。

**検索は拡張を1本も入れずに始めた**（判断6）。`title`／`headings`／`body_md` に `ILIKE` を当て、**点数付けは Node 側**（`wiki-search-score.ts`）に置いた — 重みを直すたびに migration を書かずに済む。遅くなったら `pg_trgm` の GIN 索引を足す。点数の付け方は `shared/src/wiki/search.ts` と**同じ答えを出す複製**で、一致は `shared/tests/wikiSearchParity.test.ts` が固定している（サーバーは `shared` を import できないため。段C の `isValidPropValue` と同じ作法）。本文ごと持ってくるので候補は**更新の新しい順に300件**で止める。⚠️ **読めないスペースのページも、下書きも検索に出さない**（§8「存在ごと見えない」・§7-5）。出すのは `status='published'` だけ。

**「AI に聞く」の入口は、まだ出していない。** 検索の画面にも小窓にも置いていない — 画面は段E なので、いま出すと**押せるのに何も出ないボタン**になる（§9・段A から続けている決めごと）。

検証: `npm run typecheck:all`（0 errors）・`npm run lint`（0 errors・warning は着手前と同じ）・`npm run test`・`npx vitest run --root shared`・`npm run build -w client-wiki`。実ブラウザ（Chromium・検証用 Postgres・`x-user-id` を変えて3人）で、語を打つと当たりが出て**太字で示される**こと、**語を消した瞬間に案内へ戻る**こと（待つと消したのに前の結果が残って見える）、件数と絞り込みの列が**結果が届いてから**出ること（0件と「まだ届いていない」は別のこと）、`Ctrl`＋`K` がどの画面からでも開くこと、お気に入りが入れ外しできホームに出ること、`/pages/:id.md` が YAML の見出し付きで返ること、スペースの zip を**書き出して取り込み直すと同じ形になる**ことを確認。⚠️ **読めないスペースを持つ人で検索すると、そのスペースのページが1件も出ない**こと、**他人の下書きが検索に出ない**ことを実際に確かめた。1440px と 375px で横はみ出し 0・JS エラー 0、**ナビの列は1本のまま**。

**取り込みで、中身の無いフォルダがページになっていたのを直した。** 画像だけを入れた `files/`（書き出しが必ず作る）がそのまま「files」という空のページになり、書き出し→取り込みを繰り返すたびに1枚ずつ増えていた（検証で見つけた）。`.md` も `.csv` も子も無いフォルダはページにしない。

**実ブラウザで見つけて直したものが3つ。** ①**抜粋に Markdown の印がそのまま出ていた** — `![配置図](/api/v1/internal/wiki/files/wf-ba3a21bb)` の URL だけで1行の半分が埋まり、`> [!CAUTION]`・`| --- |`・`**` も並んでいて、当たった語の前後が読めなかった。抜粋を切り出す前に印だけを落とす `toPlainText` を足した（画像の代替文・リンクの文字・引用の中身は**残す**。下線 `snake_case` も消さない）。これも `shared` とサーバーの2か所にあるので、`shared/tests/wikiSearchParity.test.ts` に突き合わせと「印が残らない・文字が消えない」の試験を足した。②**スマホで同じ一文が2つ縦に並んでいた** — 「公開されているページだけが出ます（下書きは出ません）」が、絞り込みバーの添え書きと下の案内の両方に出ていた（検索したあとは件数の行にも出る）ので、添え書きをやめた。③**`MobileFilterBar` の「検索語を消去」（×）が入力欄の外・左下に出ていた**（375px で実測）— `shared/src/client/tokens-v4.css` の `:root .v4-tap { position: relative }` が Tailwind の `.absolute`（詳細度が低い）に勝ってしまい、絶対配置のつもりの札が普通に流れていた。`:not(.absolute):not(.fixed):not(.sticky)` を付けて、**すでに位置を決めてある要素には当てない**ようにした（`absolute` でも `::after` の基準になるので 44px の当たり判定はそのまま）。⚠️ **これは `shared` なので全アプリに効く**が、`v4-tap` と `absolute` を並べているのはこの1か所だけで、ほかの35か所は今までどおり。
