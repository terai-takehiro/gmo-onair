**プロジェクト管理（GPM）の MCP ツールを一式整備し、タスクの細かな編集も MCP から届くようにした**（ユーザー要望「プロジェクト管理アプリについて細かな編集も含めあらゆる MCP を整備してください」）。プロジェクト管理はこれまで MCP ツールが1本も無かった（HTTP 約45ルートが丸ごと未対応）。新設 `gpm.tools.ts` に24種（読み取り5: プロジェクト一覧[健全性つき]/詳細/タスク横断/未確認事項/標準工程テンプレート、書き込み19: プロジェクト・工程・タスク・未確認事項・体制・テンプレートの CRUD。プロジェクトとテンプレートの削除は confirm 2段階＋manager）を追加し、HTTP と同じ `gpm.service` を呼ぶ（GLS-A の行はサービス内の確認で触れない）。権限ゲートは HTTP と同じ `sales` editor/manager で全19種を登録。かんばん列（`task_columns`）も MCP から列の一覧・追加・変更・並べ替え・削除・テンプレート適用ができるようにし（7種。`move_task` が要求する `column_id` を解決する口が無かった）、`create_task`/`update_task`/`bulk_create_tasks` に `work_state`・`task_type`・`production_step`・`episode_id`・`parent_task_id`（子タスク）を追加した — ガントの細かい編集（開始日・進捗・マイルストーン・依存関係）は同じ `project_tasks` の行なので GLS-B のタスクにもそのまま効く。会社方針「AI を使い捨てにしない」に沿って `create_gpm_project`/`create_gpm_task` は `ai_outputs` に全文記録（kind: `gpm_project_draft`/`gpm_task_draft`・`prompt_version` 任意）し、人が画面/MCP から直した差分は新設 `gpm-ai-feedback.service` が update の中で自動記録（7日窓・AI 自身の直しは数えない）、`get_ai_feedback_digest` と月次の営業 AI レビュー（`SALES_REVIEW_KINDS`）にも載せた。ついでに GPM サービスの update 4本（プロジェクト・工程・未確認事項・テンプレート）が渡していない項目を黙って消す形だったのを「渡した項目だけ書き換える」に直した（画面は全項目を送るので挙動不変）。
