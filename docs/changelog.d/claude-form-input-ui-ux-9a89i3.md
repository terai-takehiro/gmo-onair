**全アプリの入力フォームを「使う人が考える順」に直した**（並列6エージェントで全フォームを監査し、151件の破綻を洗い出して high/medium を実装）。機能追加のたびに欄をフォームの末尾へ足してきた結果、どのフォームも「作られた順」に並び、使う人の手順とずれていた。判断基準を [docs/design/v4/_form-order.md](design/v4/_form-order.md) に決めごととして起こし（6つの段＝どれに付けるか→何か→いつ→誰が→いくら→補足、依存する欄は依存される欄より下、必須の間に任意を挟まない、期間は開始→終了、自動計算は材料の下）、全アプリを直した。①**共通シェル**: シートを開いた直後のフォーカスが常に「閉じる(×)」に乗っていた（見出しの Close が本文より先に DOM に出るため）——開いてすぐ打てず、Enter を押すと閉じていた。PC は本文の最初の入力欄・スマホは何も当てない（ソフトキーボードでシートが潰れる）に直し、70本超のフォーム全部に効かせた。②**カレンダー**: 「部屋を押さえる」でタイトルが最上段なのに案件と開始日から自動生成されており、手で考えた題名が下で案件を選んだ瞬間に書き換わっていた／予約状態（本予約・仮押さえ）がメモの下＝最下段なのに最上段の種別がそれを黙って書き換えていた／複数日トグルが、それが出し入れする終了日欄より下にあった。自分の予定・パートナーの予定は日時を「開始=日+時刻／終了=日+時刻」の境界ごとの組みにそろえた（スマホ1列で開始日の下が終了日になっていた）。実バグ2件も直した——**スマホの①予定が preset を毎レンダー作り直しており、背後のクエリが解決するたび入力中のフォームが白紙に戻っていた**（PC 側は対策済み・コメントに「実在バグ」と書かれていた）、**週表でなぞった時刻がパートナーの予定でだけ黙って捨てられていた**。③**財務**: 販管費で金額が下から4番目（税区分・発生年月・支払期日・精算方法・精算番号・申請URLの全部より下）／「仮」トグルが、それが入力不可にする精算番号より下／売上で税区分が金額より上／総額の金額欄が明細の下にあり明細を1行足すと消えていた／明細のスマホ表示で自動計算の金額が手入力の単価より上（2ファイルに複製）／書類引き渡しで税区分を変えても税抜が再計算されず8%・非課税が10%で割り戻されていた。④**案件管理・営業**: 案件作成のスマホで「最初のタスク／期限」が2段目と3段目に二重に出ていた／「いま必要な5つ」の並びが案内文・不足を知らせる帯・実際の欄で3通りだった／レギュラーの取り決めだけが、その親である「回のある案件か」の畳んだ枠の外に生えていた。⑤**設定・日常業務**: system_admin（すべての判定を素通り）の選択が「役割」より後ろ／休業日の影響範囲が最後（重なる予約の照会条件でもある）／値引き上限の「空欄＝上限なし・0 は1円も値引けない」の注意文が保存ボタンより後ろの DOM／カード貸出で唯一の必須「担当者」が任意の会社名の後ろ／依頼の振り直しで相手を選ぶ欄が押せないボタンより後ろ。⑥**機材・制作技術支援**: 貸出で必須の「借りる人」が案件検索ブロックの下／保管場所が折りたたみの中で場所なし機材が増えていた／登録画面にステータス・コンディションの欄が無く（送る値には元からあった）貸出対象にできなかった／新規台本作成でGLS案件が末尾にあり「空欄のときだけ入れる」自動入力が誰にも効いていなかった。⑦Enter で保存できるフォームを増やし（明細など繰り返し入力・確認を伴うものは除く）、`scripts/check-form-submit.mjs` を `npm run lint` に追加した——`<form>` の中では `type` を省いたボタンが送信ボタンになるため、書き忘れると「キャンセル」「削除」が押した瞬間に保存を走らせる。⑧理由コメントの追加で 400 行を超えた9ファイルは欄のまとまり・役割ごとに部品へ切り出した（JSX は変えずに移設）。検証: `npm run lint`（エラー0）、`typecheck:all`、`shared` の Vitest 1996件 全通過。**実ブラウザでの確認（375px・権限別・`verify:ui` / `verify:ime`）は未実施。**
