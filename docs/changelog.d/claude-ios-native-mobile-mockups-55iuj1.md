**iOSネイティブ風モックアップの探索を足したうえで、案件管理・財務の13画面を実際にスマホ対応した。**
前回（PR #269）の案件管理まわりに続き、財務管理のスマホ実画面「取引先」（仕入先／
パートナー一覧）を同じ調子で追加した。あわせて、PC専用と判断されている画面
（案件管理の「見積・請求」）をサイドバー・トップバー込みのデスクトップサイズで
再現する試作を始めた。⚠️ ユーザーから「PC専用画面もスマホ対応していく」という
方針転換の意向が示された（実装ポリシー `pcOnlyScreens.ts` 自体はまだ変更していない・
意向の記録のみ）。続けて、方針転換を受けた初期案として「見積・請求」のスマホ版試作
（BillingMobile・表をやめてカード化し、金額の桁の読み違えを防ぐ構成）も追加した
（実画面の再現ではなく確認前の叩き台であることを明記済み）。
1つのキャンバスに複数画面を詰め込むとスマホの Safari で繰り返しクラッシュしたため、
**最終的に「1モックアップ＝1キャンバス」へ分割した**（ユーザーからの明示の指示）。
あわせて、各キャンバスに置いていた付箋（アノテーション）も**すべて外した**
（邪魔になるとのご指摘）。実装との対応関係はこの文書の表にまとめてある。
続けて、財務の台帳3画面（売上・仕入・販管費）のスマホ版試作も同じ考え方
（表をやめてカード化）で追加した。⚠️ 試作中に GLS番号の書式の誤り（実装は
`GLS-A004` のようにハイフンなし・3桁だが、それより前のアートボードは
`GLS-A-00119` のようにハイフン入り・5桁で作っていた）を見つけ、**それより前に
作っていた案件管理・財務のスマホ実画面（トップ以外の案件管理6画面・共通部品の
Sheet）も含めて全アートボードでまとめて直した**（ユーザーの明示の指示）。
併せて販管費モックの支払先に紛れていた実在企業名も架空の名前に差し替えた。
**続けて、案件管理に残っていたPC専用画面9本（ガントチャート・案件台帳・案件を直す・

各画面のスマホ版試作は、その画面がPC専用とされている理由（`pcOnlyScreens.ts` の `why`）に
具体的に答える設計にしてある（例: 横長のガント→案件カード＋ミニバー、20列の案件台帳→

v4化されていないpre-v4画面であることを確認したうえで、PC版はpre-v4の見た目のまま
忠実に再現し、スマホ版だけ「v4化した後」を先取りした投機にしてある（PC版とスマホ版で
前提が違う唯一の画面）。詳細は
[`docs/design/v4/ios-native-mobile-mockups.md`](../docs/design/v4/ios-native-mobile-mockups.md)。

**続けて、モックアップ探索で叩き台を作った13画面ぶんを実際にスマホ対応した**
（ユーザーの明示指示「一旦ここまでを実装しましょう」→「セッション全体（13画面）」
「まとめて一気に実装する」）。対象は財務の台帳3画面（売上・仕入・販管費）・見積・請求・
今回の案件管理9画面（ガントチャート・案件台帳・案件を直す・標準工程テンプレート・
料金表・費用を分け合うグループ〔一覧・詳細〕・営業活動記録・お客様の詳細）。
実装は9つの並行エージェントに分担させ、判定ロジック・文言・並びは一切変えず
見た目とレイアウトだけを直した。主な内容:
- **見積・請求とガントチャートは実装がすでに近かった。** 見積・請求
  （`EstimateRows.tsx`/`InvoiceRows.tsx`）はすでに `Row stackOnMobile` で
  組まれておりほぼ無改修。ガントチャートは実装コードの中に `MobileGanttView`
  が既に作り込まれていたが、ルート自体がPC専用ゲートで止まっていて一度も
  画面に出たことが無かった（未検証のデッドコード）。到達させる配線を直す過程で、
  案件行のはみ出し・期限バッジの日付境界バグ（JST夜間に「今日が期限」まで
  赤くなる）も見つけて直した
- **財務の台帳3画面**は共有部品 `ledger/LedgerRows.tsx` の `stackOnMobile` 適用が
  不完全だった（状態バッジ列に `hideOnMobile` が抜けていた）のを直した
- **案件台帳・案件を直す・標準工程テンプレート・料金表・費用を分け合うグループ**は
  「閲覧はスマホで開放・取り消せない一括操作や複数案件を見比べる編集だけPC専用の
  ままにする」という一貫した切り分けで実装した（`MobileLedgerCards.tsx`・
  `MobileEditProject.tsx`・`MobileTemplateRail.tsx` 等を新設）
- **営業活動記録**は「記録」タブだけ開放し、分析3タブ（ファネル・失注分析・営業評価）は
  画面の中で `PcOnlyPanel` に差し替える、案件詳細の `MOBILE_TAB_KEYS` と同じ
  「タブだけ画面の中で判定する」型を踏襲した
- **お客様の詳細**はpre-v4のまま最小限のレスポンシブ対応（Tailwindのbreakpointクラス
  のみ）にとどめ、本格的なv4作り直しは別途とした
- `client/src/pcOnlyScreens.ts` から該当13エントリを `CLIENT_PC_ONLY` から外し
  `CLIENT_MOBILE_OK` へ移した（各エージェントは触らせず、全実装完了後にまとめて
  1箇所で更新し競合を避けた）
- ⚠️ 実装後に見つけた「1ファイル400行の上限」超過4本
  （`CustomerDetailPage.tsx`/`ProjectFormPage.tsx`/`ProjectLedgerPage.tsx`/
  `DashboardGanttView.tsx`）は、`ProjectFormPage.tsx` から共通ダイアログ群を
  `projectForm/FormDialogs.tsx` に切り出す等で基準まで戻した
- ⚠️ `shared/tests/reachPhone.test.ts` の「お客様の画面はPC専用のまま」という
  固定試験を、方針転換後の実態（スマホへ開放）に合わせて更新した
- **検証**: `npx tsc -b client --noEmit` / `npm run lint`（`check-mobile-declared.mjs`
  含む）/ `npm run test`（86ファイル・1142件）すべてOK。実ブラウザでの見た目確認は
  一部の画面（見積・請求・ガントチャート）のみ実施、他は型・lint・テストの確認に
  とどめた（時間の都合）
- **なお本番・検証環境へのデプロイは行っていない**（作業ブランチへのコミットのみ）
