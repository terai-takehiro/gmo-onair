**失注案件の空の BOX フォルダが1件も消せなかったのを直した**（ユーザー報告「こうなった／15 件 BOX が削除を断った」）。⚠️ **原因はこちらの実装で、v4.5.10 で理由を画面に出すようにして初めて見えた**。BOX の `DELETE /folders/:id` は**再帰を指定しないと中身が1つでもあれば断る**が、**「中身」はファイルだけでなくサブフォルダも含む**。案件フォルダは作った直後から `01_見積` などの**空のサブフォルダ**を持つため、「ファイルが1枚も無い＝空」と判定したあと根に1回だけ削除を投げる実装では、**BOX が必ず断っていた**（＝空フォルダを1件も消せない）。⚠️ **再帰削除を使う直し方は採らなかった** — 「数え間違いがあっても、中身があれば BOX 側が断ってくれる」という二重の守りを手放すことになるため（見積書・請求書の原本は BOX にしかない）。代わりに**下から順に1つずつ消す**ようにした（`isTreeEmpty` がたどったフォルダを幅優先の順で返し、`deleteEmptyTree` が逆順＝子から消す）。**どの段でも再帰を指定しない**ので、ファイルが1枚でもあればその段で BOX が断る＝守りはそのままで、空のサブフォルダだけが消える。あわせて**消せなかったときに現役の場所へ残さず「99_失注・見送り」へ移す**ようにした（断られたのは中身が増えたか権限不足で、どちらも現役の場所から外すのが正しい。以前はここで諦めて残していた）。検証: `npm run typecheck:all` 緑、`npm run test` 1748件緑（この機能は41→45件）、`npm run lint` 緑。⚠️ **実際の BOX に対しては未検証**（この環境も検証DBも `BOX_CONFIG_JSON` を持たない）。
