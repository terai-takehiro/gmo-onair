**案件一覧→案件詳細→編集とSPA遷移すると「案件分類が入っていないので、まだ保存できません」が必ず出る不具合を直した**（リロードすると直る、という報告どおりの症状。APIレスポンス自体には分類データが正しく入っており、データ欠落ではない）。原因は `useProjectForm.ts` の `['project', id]` クエリが案件詳細画面（`ProjectDetailPage.tsx`）と**同じキャッシュ鍵**を読んでいたこと。詳細→編集のSPA遷移では、編集画面が開いた瞬間から詳細画面が取得済みのキャッシュを持っているため、「読み込み中」の骨組みを飛ばして即座にフォーム本体が描画される。ところがサーバー値をフォームへ流し込む処理は `useEffect` の中（コミット後）にあるため、**その1フレームだけ**フォームが空の初期値（`useForm({ defaultValues: EMPTY_FORM })`）のまま「案件分類」`Select` などが描画され、コンソールに `Select is changing from uncontrolled to controlled` の警告が出ていた。フルリロードではキャッシュが無いため、データ到着までこの骨組み自体が出ず再現しない。「読み込み終わった」の判定を「データが来た」ではなく「**このIDの分、フォームへ `reset()` を掛け終えた**」に直し（`syncedProjectIdRef` を追加）、SPA遷移でキャッシュ済みデータがあっても、フォームが実データで初期化されるまで骨組みを見せ続けるようにした。検証: `client`/`server` の型チェック、`shared` の Vitest 1996件 全通過。
