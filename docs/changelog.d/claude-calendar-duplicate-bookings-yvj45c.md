**カレンダーの重複予約を、表記揺らぎごと拾えるようにした**（ユーザー報告「複数の経路からの予約により重複した内容のカレンダーが貼り付くことが多々あり、表記揺らぎがあったりするので工夫を」）。スタジオ予約は「案件ステージ移行での自動生成」「MCP（メール取込・チャットでの依頼）」「人の手入力」の複数経路から作られるが、後者2つには重複防止が無く、同じ枠を指す予約が題名の言い回しだけ違う形（「収録」/「本番」・語順違い・全角半角違い）で二重に入ることが多々あった。完全一致の突合では拾えないため、①題名を NFKC 正規化＋よくある同義語（本番=収録・リハ=リハーサル等）で寄せてトークン化し、Jaccard 類似度で近さを見る純粋関数（`server/src/shared/services/bookingDuplicate.ts`）を新設、②時間帯が重なり、かつ「同じ案件」または「部屋が重なって題名も似ている」組を重複疑いとして判定する（部屋も案件も手がかりが無い組は誤検知防止のため拾わない）。方針は営業時間外の印（`out_of_hours`）と同じ「止めない」— 予約作成・更新は失敗させず、`possible_duplicate` 系の列に印を残すだけ（migration 244）。作成時と、題名・時刻・部屋・案件のいずれかを直したときに再判定し、画面はダイアログ保存時のトースト（「重複の疑いがある予約です」）と、新設のカレンダー⑤「重複疑い」一覧（`/calendar/duplicates`・仮押さえ一覧と同型）の両方で気づける。一覧からは「別物として確認済みにする」（印だけ外す・予約は残る）と削除ができる。MCP `create_studio_booking` の説明にも、重複していても保存は止まらず `duplicate_check` に印が付くだけである旨を明記した。検証: `npm run typecheck`（server/client とも緑）、`npm run test`（新設 `shared/tests/bookingDuplicate.test.ts` 14件を含め全1497件緑・表記揺らぎ／語順違い／隣接時間帯の非重複／案件のみ一致・部屋のみ一致それぞれの分岐を固定）。
