前回の修正（スクレイパーのコンテナクラッシュ）で実クロールが動き出したところ、検証環境で
新たに3件の不具合が見つかったため直した。①TOCの機材画像が「URLは正しく取れているのに
表示されない」— 本体アプリの Content-Security-Policy (`server/src/app.ts`) の `imgSrc` に
対象2社の画像配信ドメイン（`ec.toc-net.jp`・`www.restargp.com`・`kuroco-img.app`）が
入っておらず、ブラウザが画像の読み込み自体をCSP違反としてブロックしていたことが原因。
許可リストに追加して直した。②TOCの価格が出ない — `toc_scraper.py` の価格取得ロジックに
2つの問題があった。(a) 「電話受付」「ネット受付」ラベルの祖父要素全体から最初の価格を拾う
実装だったため、ラベルがフラットな `<p>` 構造だと範囲が広すぎ、両方のラベルが同じ価格を
拾ってしまうバグがあった（`find_next` で「ラベルより後で最初に価格パターンに一致する
テキスト」だけを見るよう修正・回帰テスト追加）。(b) 実ページに「電話受付」「ネット受付」
ラベル自体が見当たらないケースが多く両方 `None` になっていたため、既に正しく動いている
テーブル抽出（`_extract_tables_as_dict`）の結果から「料金」「価格」を含む行を拾う
フォールバックを追加し、それでも取れなければログに警告を残すようにした。
③商品名・カテゴリ名の日本語部分だけ文字化けする（例: `Lightning－Digital AV変換アダプタ`
の日本語部分だけが欧文の記号・アクセント文字の羅列になる）— `fetch()` が
`resp.encoding = resp.apparent_encoding`（`chardet`/`charset_normalizer` によるバイト列
からの文字コード推定）でデコードしてから文字列を返す実装だったが、この推定は日本語ページで
必ずしも当たらない。`fetch()` がバイト列を返すよう変更し、文字コードの判定を
`BeautifulSoup` 自身の自動検出（HTML の `<meta charset>` 宣言を見る `UnicodeDammit`）に
委ねるようにした（Shift_JIS ページを実際にエンコードした回帰テストで確認済み）。

自体は「折り返すと一覧の開始位置が動く」という設計意図があり26以上の他画面で使われている
