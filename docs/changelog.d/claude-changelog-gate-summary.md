**版の下書きの門と、要約が全文を消す穴を塞いだ**（Codex のレビュー #173・#174。全7件・私が #173 で開けた穴）。
①⚠️ **`_summary.md` だけを足した PR が門を通り抜けます。** 門（`check-changelog.mjs`）は
`README.md` しか外しておらず「下書きあり」と数えて OK を出す一方、集める側（`collect-changelog.mjs`）
は要約なので集めません。**その PR は版の履歴に1行も載らず、しかも要約も使われずに黙って消えます。**
→ 判定を `isNoteFile` 1か所にし、門と集める側が同じ関数を読むようにしました
（**反証**: `_summary.md` だけを足すと直した版は exit 1・外し忘れた版は exit 0）。
②⚠️ **要約が全文より「長い」と、画面から全文が消えます。** 書き込む側の上限は**バイト**
（`CLAUDE.md` が毎ターン文脈に載る費用はバイトで効く）、画面が同じ版の2つを比べるのは**文字数**。
日本語ばかりの全文と英数字ばかりの要約では「バイトでは要約が小さいのに文字数では長い」を
作れ、**そうなると画面は要約を採ってアーカイブの全文を捨てます**。⚠️ **エラーは出ません。**
③この比較の実装に、**同じ関数へ6件連続でレビュー指摘**が付きました — バイトと文字数の
取り違え・版の行の前置きを外していない・本文が空のときの `|| body` を落とす・句点を2つ
落とすのを1つしか落とさない・歴史的な閉じ括弧（`stripOuterWrap`）を経由していない。
**どれも「画面と同じ数え方を手で一部だけ写す」ことの取りこぼし**でした。
④**写すのをやめました。** `generate-version-history.mjs` に**1行から version・title・
description を取り出す唯一の入口**（`parseVersionLine`）を新設し、`parseEntries` 自身も
それ経由にしたうえで、書き込む側（`descriptionLengthOf`）はそれを**そのまま呼ぶだけ**にしました。
数え方の実装は1つだけです。試験も**生成側の出力と直接突き合わせる**形にしたので、
生成側の切り出し方が変わっても写し忘れではなく自動で追従します。
