`shared/tests/changelogSummary.test.ts` は 12 → **17 項目**。
④⚠️ **もう1件（P2）— 要約が全文より「長い」と、画面から全文が消えます。**
書き込む側の上限は**バイト**（`CLAUDE.md` が毎ターン文脈に載る費用はバイトで効く）ですが、
画面が同じ版の2つを見比べるのは**文字数**です。日本語は 1文字 3バイトなので、
**全文が日本語ばかり・要約が英数字ばかり**だと「バイトでは要約が小さいのに、
文字数では要約のほうが長い」を作れます。そうなると画面は**要約を本文に採り、
アーカイブの全文を捨てます**。⚠️ **エラーは出ません**（版は1件出るし、要約も正しい文章です）。
→ **生成側と同じ数え方**（`descriptionLengthOf`）で確かめて止めます。
**反証（実測）**: 英数字 11,100 文字の要約は **11,109 バイト＝上限内**なので
**バイトの検査だけでは通り**ますが、文字数では **要約 11,115 ＞ 全文 11,016** で
**exit 1**・**何も書き換えません**（`CLAUDE.md` も下書きも無傷）。
⑤⚠️ **④の直しの中にも間違いがあり、レビューで見つかりました**（同じ PR で3件目）。
比べるときに渡していたのは**版の行**（`vX.Y.Z — …`）なので、前置きがあって `**見出し**` に
当たらず、**行まるごとの長さ**を比べていました。⚠️ **全文の見出しだけが長いと逆転します** —
**本文では要約のほうが長いのに、行の長さでは全文のほうが長い**組み合わせが作れ、
**素通りして全文が画面から消えます**。前置きを外して数えるようにしました
（**反証**: 見出し 300 文字＋本文 1,000 文字の全文と、見出し1文字＋本文 1,100 文字の要約で、
**行では要約が短いのに本文では要約が長い**）。**実データでも 行 11,484 ／ 本文 11,412 と
差が出る**ことを確認（前置きと見出しが外れている証拠）。
