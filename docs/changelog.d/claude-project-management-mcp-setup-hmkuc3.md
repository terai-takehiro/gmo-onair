**プロジェクト管理（GPM）の MCP ツールを一式整備し、タスクの細かな編集も MCP から届くようにした**（ユーザー要望「プロジェクト管理アプリについて細かな編集も含めあらゆる MCP を整備してください」「並び替えも欲しい・ありとあらゆることが MCP でできるのが理想」）。プロジェクト管理はこれまで MCP ツールが1本も無かった（HTTP 約45ルートが丸ごと未対応）。新設 `gpm.tools.ts` に40種（読み取り12: プロジェクト一覧[健全性つき]/詳細/タスク横断/未確認事項/標準工程テンプレート/見積[一覧・詳細・サマリー]/議事録[一覧・詳細]/BOXフォルダ[構成プレビュー・書類一覧]、書き込み28: プロジェクト・工程・タスク・未確認事項・体制[並び替え含む]・テンプレート・見積[作成/明細更新/承認/アーカイブ]・議事録[更新・確定・削除]・BOXフォルダ作成の CRUD。プロジェクト・テンプレート削除は confirm 2段階＋manager、議事録削除は manager）を追加し、HTTP と同じ `gpm.service`／見積は案件と共用の `estimateService`／議事録は `minutes.service`／BOXフォルダは `gpm-box-folder.service` を再利用（GLS-A の行や案件の見積・議事録には触れないよう `gls_category` を確認）。体制（組織図）の並び替えは HTTP にも無かったため `memberService.reorder` を新設し、HTTP側 (`PATCH /gpm/projects/:id/members/reorder`) にも対で追加した（MCPだけの機能にしないため）。権限ゲートは HTTP と同じ `sales` editor/manager で書き込み全89種（今回追加分は28種）を登録。かんばん列（`task_columns`）も MCP から列の一覧・追加・変更・並べ替え・削除・テンプレート適用ができるようにし（7種。`move_task` が要求する `column_id` を解決する口が無かった）、`create_task`/`update_task`/`bulk_create_tasks` に `work_state`・`task_type`・`production_step`・`episode_id`・`parent_task_id`（子タスク）を追加した — ガントの細かい編集（開始日・進捗・マイルストーン・依存関係）は同じ `project_tasks` の行なので GLS-B のタスクにもそのまま効く。会社方針「AI を使い捨てにしない」に沿って `create_gpm_project`/`create_gpm_task` は `ai_outputs` に全文記録（kind: `gpm_project_draft`/`gpm_task_draft`・`prompt_version` 任意）し、人が画面/MCP から直した差分は新設 `gpm-ai-feedback.service` が update の中で自動記録（7日窓・AI 自身の直しは数えない・GLS-B のタスクを触る `update_task`（案件タスク側）経由の修正も同じ経路で記録）、成果（プロジェクトは stage×確定売上、タスクは期限内完了率）を導出して `get_ai_feedback_digest`・月次の営業 AI レビュー（`SALES_REVIEW_KINDS`）・AI活動ページのラベルにも載せた。見積 PDF 発行・議事録の音声アップロード・BOX へのファイルアップロードはバイナリ/multipart のため MCP には持ち込まず画面専用のままにした。ついでに GPM サービスの update 4本（プロジェクト・工程・未確認事項・テンプレート）が渡していない項目を黙って消す形だったのを「渡した項目だけ書き換える」に直し、`due_date: null` が旧 `due_date` 列に残り期限が消えない不具合と、`parent_task_id`/`episode_id` が他案件へ越境できる穴も塞いだ。検証: 検証用Postgres＋実サーバーで新設ツールを含む全40種をcurlで実測し、`typecheck:all`・`lint`・`test`（1519件）緑。
