**営業活動記録（PR #727）で残していた宿題5件に着手した**（利用者のご指示「宿題に全て着手」）。①**絞り込みチップの数字が案件数だった** — `GET /activity-logs/by-project` の返りに `summary`（次のアクションの件数と案件の数）を足し、5回投げていた問い合わせを一覧の1回に畳んだ。チップは大きい数字が件数、小さい数字が案件数。②**`?due=` が効かず、担当者で絞れなかった** — 期限の区分と担当者を URL 引数（`?due=` / `?user=`）にし、担当者の欄を案件別・時系列の両方に出した。担当者は活動を記録した人で、時系列の一覧・MCP と同じ意味に揃えた。人の一覧は、本番で 400 を返していた `GET /auth/users` をやめて `GET /users` にした（営業評価の目標設定の人の一覧も同じ穴だった）。`?sort=next_action` から入ると「案件別」を押しても切り替わらなかった不具合も直した。③**期限の口語が残っていた** — 「あとN日」「今日が期限」「今日まで」「本日返却」「N日 超過」「N日前」を全アプリで「残りN日／本日／明日／N日超過」に置き換え、`scripts/check-ui-tokens.mjs` の `overdue-wording` で止めるようにした（言い換えは `docs/wording.md`）。「期限なし」と「過ぎた／過ぎている」系は範囲が広いので次に回した。④**通知のひな形に「過ぎています」が残っていた** — migration 306 で3行を置き換えた。適用済みの migration 177 は書き換えず、177 の元の本文と完全に一致する行だけを更新するので、「知らせと文面」で人が書き換えた本文は上書きしない。⑤**閲覧権限の人に押すと 403 になるボタンが出ていた** — 営業活動記録の「完了」「延期」、やり取りタブの書く枠、お客様詳細の「完了」「延期」を編集権限の人にだけ出し、案件詳細のステージの帯は閲覧権限の人には押せなくして理由を添えた。6種類の利用者で API と実ブラウザを測った。記録は `docs/reviews/codex-findings-v4.md` の #727 の段落。検証: `npm run typecheck:all`・`npm run lint`・`npm run test`・`npm run build:changed`・`npm run verify:ui`。あわせて、統合後の差分を読み直して見つけた3点も同じ回で直した: ①**「過ぎた／過ぎている」系の画面文言が十数か所残っていた**（「期限を過ぎたもの」「返事の期限が過ぎているもの」ほか。検査が「過ぎています」「過ぎてます」しか見ていなかったため）ので、15か所を「期限超過」「期日超過」「超過している」に置き換え、`overdue-wording` を「期限・期日・予定日など ＋ を／が ＋ 過ぎ」の型まで広げた（「言い過ぎ」「多過ぎ」には当たらないことを実測）。②絞り込みの見出しが「担当者」なのに**中身は活動を記録した人で絞っていた**ので、見出しを「記録者」に揃えた（営業担当が「担当者」と読むと案件の担当を思い、「自分の案件なのに出ない」になる）。③営業活動記録の「完了」「延期」のボタンが32pxでタップ領域44pxに届いていなかったのを直し、延期の取り消しを「×」から「キャンセル」にした。
