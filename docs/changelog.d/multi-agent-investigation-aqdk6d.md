**見積作成時、グループ内案件などの定価差から値引き項目行を自動生成できるようにした**。
これまでカタログ選択時の定価と実額の差（`list_unit_price` > `unit_price`）は
画面のカテゴリ小計・見積書PDFだけがその場で動的に合成する「表示専用のゴースト値引き」で、
`estimate_items` には実体を持たなかったため、**見積を受注して売上に変換すると
（`revenue_items` に定価列が無く）値引きがどこにも残らず、請求書・検収書には
定価差の値引きが一切出ていなかった**。既存の「カテゴリに値引き行を追加」ボタン
（`EstimateItems.tsx` の `addCategoryDiscount`。中身は新設の
`estimateCategoryDiscount.ts` に切り出し）を拡張し、押した時点でそのカテゴリの
定価差合計を自動計算して単価に入れ、説明欄を「グループ価格による値引き」で埋める。
**同時に、差額のもとになった行の単価を定価まで引き上げる**（値引きは単価を
下げず別建て、という既存方針どおりに組み替えるだけで、カテゴリの合計・粗利は
1円も変わらない — 引き上げないと実額の行＋新しい値引き行で二重に値引いたことになる）。
生成後は他の行と全く同じ通常の明細行として保存されるので、既存の保存・見積PDF・
売上変換（`convertToRevenue`）・請求書/検収書PDFの経路がそのまま通り、金額・項目名も
自由に編集できる（サーバー側の変更は無し）。ボタンの文言に自動計算した金額を出し、
差が無いカテゴリでは従来どおり空の値引き行（手入力用）にフォールバックする。
自動計算は押した瞬間の初期値の提案のみで、保存のたびに再計算はしない（編集・削除した
値引き行が復活しない）。⚠️ **実装中にテストで見つけて直した実害**: 「押したら入る額」の
判定を画面のカテゴリ小計と同じ `categoryTotals()`（定価小計−実額小計）に頼ると、
一度自動生成した値引き行そのもの（単価マイナス）も実額側に混ざって同じ差額を
「まだ材料化していない」と誤認し、**ボタンを2回押すと値引き行がもう1本増えて
実質二重値引きになる**不具合があったため、`list_unit_price > unit_price` の行だけを
直接合算する専用の判定に直した（`shared/tests/estimateCategoryDiscount.test.ts` で固定）。
検証: `npx tsc -b client`・`npm run typecheck -w server`・`npm run test`（shared、
1971件）全通過。

**「案件を直す」で無関係な項目まで保存できないケースを直した**（継続区分など）。
保存ボタンの disabled 判定（`missingOf()`）は、客入れの有無・案件分類の
**片方だけ**入っている（古いデータ・他経路の書き込みなど）案件を開くと、
継続区分のような全く無関係な項目だけ直そうとしてもこの2項目を埋めない限り
常に押せないままだった。サーバー（`resolveClassification`）は2段が渡されな
ければ今の値を保つだけで、渡された側だけでは導けず旧 `project_type` から
毎回導き直す設計のため、触っていない古い分類を送らずに他の項目だけ保存して
も壊れない。`missingOf()` に `touchedClassification` を追加し、
react-hook-form の `dirtyFields` から「このセッションで実際に触ったか」を
渡すようにした。触っていなければ片方だけの状態でも通し、触ったときは今まで
どおり両方を要求する。第3引数の既定は `true`（今までどおり常に見る）なので
案件作成画面・既存呼び出しの挙動は変えていない。

**GLS発番の番組種別に「リアルイベント」を追加した**。配信・収録を伴わない
リアルだけのイベント向けに `BroadcastType` へ `real` を追加。
`projects.broadcast_type` は CHECK制約の無い TEXT列（カンマ結合の複数選択）
のため migration は不要。`shared/src/enums.ts` と `client/src/types/index.ts`
の両方に追加した（GLS発番ダイアログ・案件フォームの番組種別トグルは
`BroadcastTypeLabels` を動的展開しているため、ラベル追加だけで選択肢が
自動的に出る）。`real` は生放送判定（`broadcastTypeIncludes(...,'live')`）
の対象外のため、回（エピソード）の放送日は既存の「収録」相当の計算
（収録日+オフセット日数）に流れる——リアルイベントの放送日の扱いは別途の
仕様判断が必要なため、今回は番組種別への追加のみに留めた。

**財務ダッシュボードの仕入・販管費の内訳行から、そのまま編集できるようにした**。
以前は行を押すと台帳（明細一覧）へ遷移するだけで、そこから改めて対象の行を
探して編集する必要があった。ダッシュボードに編集フォームを作り直すのではなく、
遷移先の URL に `?edit=<id>` を足し、**台帳側の既存の編集ダイアログを開いた
状態**で着地するようにした（`ledgerOpenQuery` に `editId` 引数を追加）。
`SgaListPage` は元々 PDF取込レビュー画面用にこの仕組みを持っていたため
そのまま乗り、`PurchaseListPage` には同じ形で `?edit=` ハンドラを新設した。
「行＝台帳へ遷移」という直前の決定（仕様変更 #4）はそのまま保ち、遷移した
先で即座に編集できるようにしただけなので、売上・仕入・販管費で挙動が
また食い違う、という後戻りは起きていない（売上は編集要望が無いため対象外）。
