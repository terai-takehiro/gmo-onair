**⑥ 案件詳細（OverviewTab・TasksTab）のスマホ対応を進めた**
（`docs/v4-native-ui-audit-2026-08-20.md`「⑥ 案件詳細」の指摘に対応）。

①概要タブの「事実の帯」に**スマホ専用のカード積みレイアウト**を新設した
（`overviewParts.tsx` の `Fact` に `mobile` 分岐）。監査時点はPC/スマホ共通の
1実装で、モックの「2段組・区切り線つきの帯」を375pxでもそのまま描いていた。
実際には**2列グリッド＋列の区切り線（`border-l`）という組み合わせが、2枚目の
行の左端にも区切り線を出してしまう**バグを内包していた（`first:border-l-0` は
DOM上の最初の1枚にしか効かないため）。スマホでは1枚ずつ枠で囲むカードに、
PCは従来どおり2段組・区切り線に描き分けた。中身（出す項目・値の作り方）は
変えていない。`useIsMobile()` は親（`ProjectDetailPage.tsx`）で1回だけ呼び、
`mobile` propとして渡す形にした。

②タスクタブは、既存のかんばん／リスト／ガントを作り直さない前提のもと、
**スマホでは常にリスト表示にし、表示切替（`ViewToggle`）ごとPC専用にした**
（案件一覧が「ボードはスマホに出さない」とした前例と同じ判断）。
`TaskListView`は元から縦1列のグループ表でスマホでも読めるが、かんばん・
ガントは横スクロール前提で375px向けの作り直しをしていないため。ガントの
`sm:hidden`フォールバック帯は、この変更でスマホからは二度と到達しなくなる
ため削除した（PC専用の描画パスだけが残る）。`ViewToggle.tsx`の旧トークン
（`rounded-md`等）はスマホに出さない判断をしたため、この回では載せ替えて
いない。

③「見積・書類・やり取りはPC専用」の案内文（`MobileTools.tsx`）を実装と
突き合わせたところ、**「やり取り」は`tabs.ts`の`MOBILE_TABS_BY_PHASE`で
「ふだん」「終わった案件」の2段階ではスマホのタブから普通に開けるように
なっており、PC専用ではなかった**（案内文はその変更より前のまま残っていた
古い文言）。案内から「やり取り」を外し「見積・書類」の2つだけにした。
あわせて`ProjectDetailPage.tsx`の`OffPhoneTab`の`why`マップにあった
`thread`エントリも削除した（`thread`は常にどこかの段階でモバイルタブに
含まれるため`offPhone`分岐には実際には到達しない死んだコードだった）。
見積・書類・ふりかえりタブを常にPC専用のまま（「それでもこのまま開く」で
PC向けの中身がそのまま出る）にしているのは、`client/CLAUDE.md`のM1節に
明記された既存の設計判断（先に理由を読ませてから選ばせる）と確認できたため、
そのままにした。

**見送ったもの**: やり取り／見積／書類／当日／ふりかえりの5タブ本体の
モバイル専用レイアウト新設は今回は見送った。七つのタブを持つ大きな画面で、
優先度の高いOverviewTab・TasksTabに絞る指示のため。

検証: `npx tsc -b client` / `npm run lint`

`client-daily/src/pages/TasksPage.tsx`の未コミット変更由来の指摘のみで、
自分の変更ファイルには指摘なし）/ `npm run test`（1144件）OK。
`npm run verify:up`は実施したが、実ブラウザ確認（375px）は自動化ツールが
無く未実施。
