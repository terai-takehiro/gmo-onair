**収録設定・配信設定を作り直した — モックアップが想定していた操作が実装に入っておらず、打ち込んだ設定が現地に届かない状態だった。** 利用者から「配信収録のUIがまるでダメ。モックアップが全然反映されてないし、初期設定の設定もできてないし、操作性最悪」との指摘を受け、4エージェントでモックアップ（`.dc.html`）とコードを1行ずつ突き合わせて監査した結果、**46件**（うち「使えない」14件）の実害を確認した。原因は4つ: ①`.dc.html` は下半分の `<script>` に状態・操作・判定が書かれているのに**実装は上半分の見た目だけを写した**（一括変更・呼び名・その場の警告が丸ごと落ちた）②実装設計書がファイルの置き場所しか決めておらず「モックのどの操作を作るか」の一覧が無かった ③**画面の入力とサーバーの保存済みが二重管理**（点検も書き出しも保存済みしか見ない）④検証が「画面が出るか」で止まり、モックの操作を1つずつなぞっていなかった。

**直したもの（サーバー）**: ⚠️**配信先の名前を変えて保存すると保存済みのストリームキーが黙って消えていた**（画面は「保存しました」と出る・実機で再現）— サーバーが前の鍵を `(ENC番号, セッション名)` で探しており、名前は利用者が自由に変える値だったため。行の安定した id（`destId`）で突き合わせる形にし、`streamKey` を3値（未指定＝残す／`''`＝消す／文字列＝新しい鍵）にした。保存の失敗に**どの行の何が悪いか**を載せた（以前は `issues[0].message` を返すだけで、画面はそれすら捨てて「保存に失敗しました」としか出さず、配信先が10件あるとどの行か分からなかった）。実施日の候補を返す `GET .../dates` を新設。点検（preflight）を画面側の判定と揃え、プロトコル未選択を RTMP 扱いにし（**未選択の配信先は鍵が空でも点検を素通りしていた**）、宛先URL・名前の重複・空の名前・HD Plus の SSD/8ch も見るようにした。

**直したもの（画面）**: **実施日を選べるようにした**（`ServiceDateBar` 新設 — 設計は「案件＋実施日で1セット」なのに選ぶ手段が無く、**案件につき事実上1日ぶんしか持てず過去日は二度と開けなかった**。既定値も UTC 基準で JST 0〜9時は前日になっていた）／**一括変更**（12台を埋めるのに96クリック要った）／**呼び名の表示と入力**（保存はされるのに入力欄が無く、唯一 label に触れるコードは値を消す処理だった）／**その場の警告**（間違いに気づけるのは書き出しダイアログを開いたときだけで、しかも未保存の編集は映らなかった）／**未保存の印と離脱の確認**（12台入力して画面を移ると黙って全部消えた）／**表を素の `<table>` から CSS grid へ**（控えの行だけ列数が1つ多く本線と桁が揃わなかった）／**「本線から写す」で機種が持てない値を落とす**（4K・DNxHR・SSD が控えにそのまま入り、**画面は空欄に見えるのに Excel には出て現地で弾かれた**）／**書き出しは未保存だと止める**（12台打ってそのまま書き出すと見出しだけの Excel が「書き出しました」と一緒に落ちてきた）／**「前回の設定を写す」を候補提示に**（GLS番号と日付の手入力を求めていた）／状態の帯を4カウントに／使っていない ENC を畳む／インスペクタを追従させる／鍵欄に伏せ字を入れない・「キーを消す」を明示／セッション名の規則と文字数を画面に出す／選択を配列 index から `destId` へ／スマホでも収録⇄配信を直接切り替え・下部バーを主アクション1つに。
