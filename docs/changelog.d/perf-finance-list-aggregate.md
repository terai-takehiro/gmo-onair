**販管費の一覧が、同じ表を5回走査していたのを2回にした**（棚卸し ④）。⚠️ **実測で「1リクエストあたり 5 本 → 2 本」**（発行された SQL を実際に数えています）。件数・合計・絞り込みチップの件数・科目ごとの件数は、**同じ FROM・同じ WHERE を何度も掛け直していただけ**だった。CTE を1本置いて `FILTER (WHERE …)` で数え分ければ走査は1回で済む。⚠️ **応答は1バイトも変えていません** — 実 Postgres に多様なデータ（削除済み・計上月なし・科目なしを含む6件）を入れ、**19 通りの絞り込み条件で変更前後の応答を突き合わせて完全一致**を確認した（件数・合計・チップ・科目ごとの件数・行の並び順まで）。⚠️ **チップの件数は「種別以外の絞り込みだけ」を掛けて数える**決めごとがあるので、CTE の WHERE にはチップ以外を入れ、チップは列として持たせて数え分けている。ここを混ぜると**チップの数字と押した先の行数がずれる**（どちらもそれらしい数字なので画面を見ても気づけない）。⚠️ **`buildSgaWhere` の返り値は1文字も変えていない**（Excel・MCP が使っているため）。⚠️ **`?` の並びが命** — DB 層は出現順に `$1..$n` へ置き換えるので、分けて作ったものを合成する順を間違えると静かに違う行が返る。テストで固定した。あわせて、集計と行は互いに依存しないので同時に投げるようにした（**3本以上にはしない** — 接続プールは20本で、財務ダッシュボードは1回の絞り込みで6つの API を同時に叩くため）。⚠️ **仕入・売上の一覧は同じ形にできるが、この PR には入れていない** — 売上は按分の join の扱いに判断が要り、まとめて出すとレビューできなくなるため。棚卸しに残した。
