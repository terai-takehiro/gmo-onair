**制作技術支援の収録設定・配信設定で、初回保存後に開けなくなる致命的な不具合を直した。** `device-settings.service.ts` の `resolveDate()` が Postgres の `DATE` 列を `String(row.service_date)` で文字列化していたため、`"Sat Aug 22 2026 00:00:00 GMT+0000 (...)"` という JS の `Date.toString()` 表記になり、これをそのまま次の SQL の `service_date = $N` に渡して `invalid input syntax for type date` で 500 エラーになっていた（`schedule.service.ts` が既に踏んで直していたのと同じ罠。`SELECT to_char(service_date, 'YYYY-MM-DD')` にして修正）。**この関数は `?date=` を省いた GET（ジャーニーのミニアプリタイルから開く通常の経路はまさにこの形）で必ず通るため、収録設定・配信設定は一度でも保存すると、以後ハブから開くたびに壊れて見える状態だった。** 検証用 Postgres で実際に PUT → GET を再現して確認・修正後は収録設定・配信設定・点検・Excel書き出し・前回の設定を写す、の一連が通ることを確認した。検証: `npx tsc -b server` / `npm run lint` / `npm run test` OK。
