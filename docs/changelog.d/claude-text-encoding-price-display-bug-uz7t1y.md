直前の修正（fetch()をバイト列で返しBeautifulSoup自身の自動検出＝UnicodeDammitに文字コード判定を
委ねた対処）後も文字化けが再発すると報告を受けた。
原因は「`<meta charset>` 宣言が実ページに無いと、UnicodeDammit も内部的には元の不具合と同じ
chardet系の統計的推定にフォールバックする」点で、統計的推定に頼っている根本原因自体は変わっていな
かった。`common_db.py` に `decode_html()` を追加し、宣言の有無に依存しない確定的な判定
（UTF-8厳密デコード→失敗ならCP932→EUC-JP→最後の保険としてUnicodeDammit、の順）を先に行うよう
変更し、`toc_scraper.py`/`restar_scraper.py` の全ての `BeautifulSoup(html, ...)` 呼び出しを
経由させた。あわせて、価格が取得できなかったときの診断ログに「ページ内で実際に見つかった
『◯◯円』形式の数値」を追加した（抽出には使わず、次に再発したときに実際のラベル・見出し名を
特定しやすくするための観測用。実サイトの構造はサンドボックスの制約で検証できていないため、
今回もログを見ないと価格側の当たりは絞れない）。
