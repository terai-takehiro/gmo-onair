**未請求の売上に入金を記録できてしまうのを止めた**（Codex のレビュー #152。**P1**）。①⚠️ **前の版が塞いだ穴を、同じ版が別の場所で開け直していました。** v4.0.31 で ⑤ 見積・請求に「未請求」チップを足したので、**請求書を出していない売上がこの表に並ぶ**ようになりました。ところが行の「入金前」ボタンは**全行で押せ**、`PATCH /billing/invoices/:id` も**発行済みかどうかを見ていません**でした。つまり**このチップから未請求の売上に入金日を入れられます** — ⑫ 入金の確認（スマホ）で塞いだ「請求していないのに入金済み」を、**PC 側で作れる**状態でした。②⚠️ **できあがる行は、どの絞り込みにも出てきません。**「入金待ち」は請求書を出したものだけ、「未請求」は入金前だけを見るので、**未請求 ＋ 入金済みの行はどちらにも並びません**。誰かが台帳と突き合わせるまで見つかりません。③**画面とサーバーの両方で止めます。** 画面で押せなくするだけでは**直接叩けば通ります**し、サーバーだけだと押してから 400 が返るので**どの行が悪いのか分かりません**。⚠️ **ボタンは消さずに押せなくして理由を出します**（消すと、なぜ入金を記録できないのかが画面から分からない）。④**通すものは通します。** **同じ回で `invoice_issued: true` を送るのは通す**（「出して入金も記録する」は普通の操作で、弾くと画面が2回叩くだけ＝片方だけ通った行ができる）。**取り消し（`null`）は止めません** — 止めると、間違って入った入金日をいちばん直したい行で消せなくなります。⑤**まとめての口（月次の締め）は落とさずに飛ばします。** 200 件の締めを1件のために全部止めると、経理は原因の行を探すところから始めることになります。⚠️ **飛ばしたことは必ず画面に出します**（`skipped_unissued`）— 「10件を記録しました」だけ出すと、押した人は**全部入ったと思って二度と見に来ません**。⑥**検証**: 実 Postgres ＋ 実サーバー ＋ 実ブラウザで — 未請求に入金日 → **400 で DB は不変**、発行済みに入金日 → 200、**同じ回で発行＋入金 → 200**、まとめて3件（発行済み1・未請求2）→ **`updated: 1` / `skipped_unissued: 2`** で DB も1件だけ、未請求だけ選ぶと **400**。⑤ の画面（1440px）は「未請求」チップで**入金前ボタン3個すべてが押せず理由が出る**、「入金待ち」では**押せる**、横はみ出し 0px・JS エラー 0。**反証: 守りを外すと 200 が返り `invoice_issued=f` のまま `paid_date` が入る**（実測）。`shared/tests/billingState.test.ts` に7項目、`npm run test` 954項目、`typecheck` exit 0、`lint` 0 errors / 63 warnings。⑦**DB 変更なし。`shared/src/` は触っていない**ので凍結4アプリの CSS は不変（足したのは `shared/tests/` だけ）。
