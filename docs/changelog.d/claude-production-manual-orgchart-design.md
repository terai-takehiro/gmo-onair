**運営マニュアルに「体制図」ブロックを足す設計とモックアップを書いた**（実装はまだ。ご依頼「プロジェクト管理で作れる組織図を運営マニュアルの機能としてコピーしたい」）。①プロジェクト管理（`/gpm`）の「体制」タブにある箱と線の組織図（`MembersTab.tsx`・migration 169）を、運営マニュアルの紙面に置ける**自由ブロック**として作り直す設計を`docs/design/v4/production-manual-orgchart.md`に起こした。②いちばん大きい判断は**差し込みブロックにしないこと**。理由は4つの実測——冊子は案件にも番組にも紐づくが番組の冊子には案件が無く差し込み元が存在しない／段・箱・バッジを持つ表は`gpm_members`だけで編集画面はプロジェクト管理（GLS-B＝新`GMO-`）にしかなく制作案件（新`SCS-`/`GSS-`）の冊子では永久に空になる／`project_members`は段も箱も持たないため差し込んでも1列の並びにしかならない（それは既存の`project.team`そのもの）／紙に刷るのは当日の現場の体制で案件メンバー一覧とは一致しない。③代わりに冊子の中で作って冊子が持ち（`free.content`）、打ち直さずに済むよう右パネルから**1回かぎりの取り込み**（案件のメンバー／同じ案件のプロジェクト管理の体制）を用意する。足すのは型1つと API 1本（`GET /techops/manuals/:id/org-seed`）だけで、表も migration も増やさない。④GPM から変えた点: 箱を明示的に持ち（人がまだ決まっていない空の箱を紙に出せる）、段は3段固定にせず増減・改名でき、立場は色ではなく**線種**で分ける（白黒で刷っても読める・紙のインク規律 §6-6）、人の編集はダイアログを出さず紙面の上で直接行う（表ブロックと同じ作法）。⑤モックアップ`OrgChart.dc.html`を足してキャンバスを組み直し、同じ URL へ公開した（紙に出す項目と段のつながりの線が実際に紙面に効く）。検証: `node scripts/check-md-links.mjs`・`npm run lint`。
