**失注案件の BOX フォルダが「ほとんど片づかない」のを直した**（ユーザー報告「ほとんどのゴミ案件が処理できていないようです」）。原因は2つあり、どちらも**古い案件ほど当たる**ものだった。①**古い失注案件には `box_url_internal`/`box_url_external` が入っていない** — フォルダは BOX にあるのに、アプリはどれがその案件のものか知らないので、**片づけ待ちの件数にすら入っていなかった**（帯が「0件」に見えて出ない）。親フォルダの直下を一覧して**案件に結び付け直す**名寄せを足し、「まとめて片づける」の1回目に走らせるようにした（毎回やると親フォルダを丸ごと引き直すため2回目以降は走らせない）。⚠️ **突き合わせ方は「フォルダ名から番号を切り出す」ではなく「DB の値からこのアプリならこう名付けたはずを組み立てて照らす」**にした。番号の形を当てにすると**3種類が漏れる**ため: ①**プロジェクト管理（GLS-B）のフォルダは番号を持たない**（`createGpmFolderTree(projectName)` は案件名だけで作る）②**Excel 取込の旧番号は `GLS001`（ハイフン無し）**③**Excel 取込のコードは `PRJ-2026-001` のように `OPP` で始まらない`**。DB 由来なら形が今後増えても効く。名寄せは**空の側だけ**書き（人が直した値を上書きしない）、**同じ名前に2件以上ぶら下がるものは捨てる**（どちらのフォルダか決められないものを当てずっぽうで結び付けると別の案件のフォルダを消しにいく）。`00_DB_Backup`・`99_失注・見送り`・`11_awards_photo` は名前が偶然一致しても触らない。②**安全弁が「名前が `【社内】`/`【社外】` で始まること」を要求していた** — この頭が付いたのは 2026-08-25 の版なので、**それ以前に作られたフォルダは全部弾かれていた**。「**このアプリが付けたはずの名前と一致すること**（案件名を変えたあとリネームに失敗している場合に備え、番号を含むものも通す）」を見る形に変えた。番号を持たないプロジェクト管理のフォルダにも効く。これは古い名前に効くだけでなく**今より安全**で、以前は `box_url_*` を手で書き換えて**同じ親の下にある別の案件のフォルダ**を指させると4つの条件を全部素通りできた（頭はどの案件のフォルダにも付くため）。あわせて、帯が「片づけ待ち（URL のある側）」しか数えていなかったのを**未紐づけのぶんも候補に数える**ようにし、何件調べて何件つながったかを画面に出し、終わったら件数を引き直して押した数と減った数が食い違わないようにした。検証: `npm run typecheck:all` 緑、`npm run test` 1718件緑（この機能は21→38件）、`npm run lint` 緑。⚠️ **名寄せそのものは実際の BOX に対して未検証**（この環境も検証DBも `BOX_CONFIG_JSON` を持たない）。どのフォルダをどの案件のものと見なすかの判断は純関数にしてテストで固定した（番号あり／ハイフン無し／`PRJ-` 始まり／番号なしのプロジェクト管理／`00_DB_Backup` などが必ず対象外になること）。
