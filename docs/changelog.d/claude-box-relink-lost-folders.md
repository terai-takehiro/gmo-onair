**失注案件の BOX フォルダが「ほとんど片づかない」のを直した**（ユーザー報告「ほとんどのゴミ案件が処理できていないようです」）。原因は2つあり、どちらも**古い案件ほど当たる**ものだった。①**古い失注案件には `box_url_internal`/`box_url_external` が入っていない** — フォルダは BOX にあるのに、アプリはどれがその案件のものか知らないので、**片づけ待ちの件数にすら入っていなかった**（帯が「0件」に見えて出ない）。親フォルダの直下を一覧して**フォルダ名の番号（`GLS-A001` / `OPP-2026-0007`）で案件を引き、空いている側だけ URL を埋める**名寄せを足し、「まとめて片づける」の1回目に走らせるようにした（毎回やると親フォルダを丸ごと引き直すため2回目以降は走らせない）。名寄せは**空の側だけ**書き（人が直した値を上書きしない）、**番号で1件に決まらないものは触らない**。`00_DB_Backup`・`99_失注・見送り`・`11_awards_photo` のように番号の形をしていない名前は必ず対象外にする。②**安全弁が「名前が `【社内】`/`【社外】` で始まること」を要求していた** — この頭が付いたのは 2026-08-25 の版なので、**それ以前に作られたフォルダは全部弾かれていた**。「**その案件の番号が名前に入っていること**」を見る形に変えた。これは古い名前に効くだけでなく**今より安全**で、以前は `box_url_*` を手で書き換えて**同じ親の下にある別の案件のフォルダ**を指させると4つの条件を全部素通りできた（頭はどの案件のフォルダにも付くため）。あわせて、帯が「片づけ待ち（URL のある側）」しか数えていなかったのを**未紐づけのぶんも候補に数える**ようにし、何件調べて何件つながったかを画面に出し、終わったら件数を引き直して押した数と減った数が食い違わないようにした。検証: `npm run typecheck:all` 緑、`npm run test` 1715件緑（新規8件・計35件）、`npm run lint` 緑。⚠️ **名寄せそのものは実際の BOX に対して未検証**（この環境も検証DBも `BOX_CONFIG_JSON` を持たない）。フォルダ名から番号を切り出す判断は純関数にしてテストで固定した。
