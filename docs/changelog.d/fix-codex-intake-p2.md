**投入口が nginx の 60 秒を超えうるのと、一緒に登録したものが画面から消えるのを直した**（Codex のレビュー棚卸し #76。P2 2件）。①⚠️ **解析が最大 120 秒掛かりえて、60 秒で切られていました。** コードには「1回 30 秒だから nginx の 60 秒より十分手前」と書いてありましたが、**実際に掛かりうるのは 4 倍**です — SDK に `maxRetries: 1` を渡しているので**1回の呼び出しが 2 回**になり、さらに**軽いモデルで落ちたら上位モデルでやり直す**ので **30 × 2 × 2 = 120 秒**。nginx の `/api/` は `proxy_read_timeout` を書いていないので**既定の 60 秒で切れます**。切れると押した人には**「押しても何も起きない」**としか見えず、しかも**サーバー側では解析が続いていて費用は掛かっています**。②**やり直しまで含めた総枠（45 秒）を持たせました。** 1回ぶんの上限（20 秒）とは別に、**残り時間で1回ずつを絞り**、**残りが足りなければ上位モデルのやり直しをしません**（やり直しても切られるので、費用だけ掛かって結果が届かない）。**SDK には `maxRetries: 0`** を渡します — 黙って2回呼ばれると総枠が意味を失います。⚠️ **総枠の起点は「この仕事を始めた時刻」**にしました。担当者一覧・案件候補・過去の傾向を引く時間も押した人は待っているので、**AI の呼び出しだけを数えると前段が遅い日に超えます**。**実測: 最悪 120 秒 → 40 秒**（ふつうの回は 3 秒・やり直した回は 13 秒で変わりません）。③⚠️ **指摘は `minutes-ai` に付いていましたが、そちらは該当しませんでした** — 議事録の整形も文字起こしも**裏で走る**ので（リクエストの中で待たない）、60 秒とは無関係です。**代わりに、録りながらの下読みが「短く諦める」を守れていませんでした**: `timeoutMs: 20_000` と書いてあるのに `maxRetries` の既定が 1 なので**40 秒**になります。**待たせる経路だけ 0 にしました**（裏で走る長い文字起こしは 1 のまま — 一時的な 5xx で録音まるごとを捨てたくない）。④⚠️ **ネタ1件 ＋ タスク3件を登録すると、タスク3件がどこにも出ませんでした。** 「2件以上できたら遷移しない」を**ネタの数**で数えていたためで、この回は案件へ飛びます。「案件（ネタ） 1件・タスク 3件を登録しました」は**その画面の状態**なので、**飛んだ瞬間に消えます** — 投げた人は案件を1件作ったつもりのままです。**数えるのは「できたもの全部」**にして、1件だけのときしか飛ばないようにしました（飛ばないときは案件へのリンクを並べます）。⑤**検証**: 総枠の効き方を数字で固定（`shared/tests/intakeBudget.test.ts` 10項目・**最悪 40 秒 / 前の版は 120 秒**・前段が 20 秒掛かった日は**やり直しをやめる**）。`npm run test` 804項目、`typecheck` / `lint` とも exit 0。⑥**DB 変更なし。`shared/src/` は触っていない**ので凍結4アプリの CSS は不変。
