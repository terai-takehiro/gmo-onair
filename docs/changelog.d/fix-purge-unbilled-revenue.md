**請求前の「見込みの売上」だけが入っている失注案件も、台帳から外せるようにした**（ユーザー依頼「以前見送った失注になった案件の削除ですが、見積もりを入れているものも削除してほしい」）。見積そのもの（`estimates` 別テーブル）は最初から対象で、残っていたのは**請求書をまだ出していない売上**が入っている案件だった。営業が提案の段階で入れる見込みの金額で、**失注した以上その金額は動かない**ので、残す理由にならない。残すのは**請求書を出した売上（または入金のある売上）と、実際の仕入**だけにした。⚠️ **判定は `billing-state.ts` の言葉をそのまま使う**（`BILLING_STATE_SQL.issued` / `.paid`）— 同じ集合に2つ目の名前を作ると片方だけ直されて必ず食い違うため（同ファイル冒頭の実測: 同じ `unpaid` が口によって 40 件と 3 件を指していた）。⚠️ **按分の側にも同じ条件を掛ける** — グループ案件では子は `revenue_allocations` にしかいないので、直接の行だけ厳しくしても意味がない。⚠️ **仕入は見込みではないのでそのまま残す**（実際に払ったお金で、失注案件に付いていれば「動いて、そして負けた」費用の記録）。画面の文言も「売上・仕入が付いている」から「請求書を出した売上か仕入がある（見積や請求前の見込み売上だけなら消します）」に直した。検証: 実 Postgres で①請求前の見込み売上→消える側②請求書を出した→残る③入金だけ記録→残る④按分先が請求前→子も消える側⑤按分先を請求済み→親子とも残る、の5通りを確認。`npm run typecheck:all` 緑、`npm run test` 1756件緑（この機能は28→31件）、`npm run lint` 緑。
