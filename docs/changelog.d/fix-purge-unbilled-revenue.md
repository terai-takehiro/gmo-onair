**請求前の「見込みの売上」を落としたうえで、その失注案件を台帳から外せるようにした**（ユーザー依頼「以前見送った失注になった案件の削除ですが、見積もりを入れているものも削除してほしい」「見込み売上を落とした上で削除したい」）。見積そのもの（`estimates` 別テーブル）は最初から対象で、残っていたのは**請求書をまだ出していない売上**が入っている案件だった。営業が提案の段階で入れる見込みの金額で、**失注した以上その金額は動かない**ので残す理由にならない。①残す条件を**請求書を出した売上（または入金のある売上）と、実際の仕入**だけに絞り、②**その案件にぶら下がった見込み売上も一緒に論理削除する**ようにした（案件を外すだけでは、売上台帳と集計にその金額が残り続ける）。⚠️ **落とすのは案件を外す前**（外したあとだと、その売上はどの画面からも辿れないまま台帳に残る）。⚠️ **費用を分け合うグループで他の案件にも配っている売上は落とさない** — 落とすと**まだ生きている案件からお金が消える**ため、1件でも配分があれば手を付けない。⚠️ **判定は `billing-state.ts` の言葉をそのまま使う**（`BILLING_STATE_SQL.unissued` / `.issued` / `.paid`）— 同じ集合に2つ目の名前を作ると片方だけ直されて必ず食い違うため。⚠️ **何件落ちるかを押す前に画面へ出す**（お金の行が消えるのに、押したあとで初めて分かるのは取り返しの付かない驚きになる）。仕入は見込みではないのでそのまま残す。検証: 実 Postgres で①請求前の見込み売上→案件は消える側②請求書を出した→残る③入金だけ記録→残る④配分先が請求前→子も消える側⑤配分先が請求済み→親子とも残る⑥実行して**予告1件＝実際に落ちた1件が一致**し、生きている案件へ配っている売上は**落ちずに金額も無傷**、の6通りを確認。`npm run typecheck:all` 緑、`npm run test` 1762件緑（この機能は28→37件）、`npm run lint` 緑。
