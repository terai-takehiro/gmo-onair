**財務ダッシュボードの「総額」/「確度加味」切り替えを、画面全体の設定に見える場所へ引き上げた**（ご依頼）。①切り替えトグル（`forecastMode`）はこれまで「営業見通し（パイプライン）」カード（`PipelineForecast.tsx`）のローカル state に閉じていて、そのカードの中だけに出ていた——期間・案件を絞り込む `PeriodBar` とは別の場所にあり、「カード内の一設定」に見えて画面全体の見え方を切り替えているようには読めなかった。②`forecastMode` の state とトグルの見た目を画面レベル（`BudgetDashboardPage.tsx`）へ引き上げ、`PeriodBar` の直下に常に見える・操作できる共通エリア（`ForecastModeToggle.tsx`）として配置した。`PipelineForecast` は state もトグル UI も持たず、`forecastMode` を props で受け取るだけにした。③**集計対象は変えていない** — `forecastMode` を使うのは引き続き「営業見通し（パイプライン）」カードだけで、損益フロー（`ProfitFlow`）・内訳（`Breakdown`）・サマリーは従来どおり確定売上のみの実績を表示する（確度という概念を適用しない）。既定値（「確度加味」）・文言（「総額」「確度加味」）・レスポンシブ対応（375px幅）も既存のまま踏襲した。検証: `client`/`server` の型チェック、`shared` の Vitest 1996件 全通過。

**案件一覧の各列ヘッダーをクリックして並び替えられるようにした**（案件管理＞案件一覧 `/sales/projects`）。これまで並び替えはプルダウン（おすすめ順・見積金額が大きい順など）でしか操作できず、「案件／お客様」「ステージ」「実施日」「見積金額」「次のタスク」「最後の動き」の各列ヘッダーはただの `<div>` でクリックできなかった。案件台帳（`ProjectLedgerPage`／`LedgerTable.tsx`）が既に持っているヘッダークリック並べ替えと同じUIパターン（同じ列を押すと 昇順→降順→既定 の3段トグル・矢印は指を乗せたときだけ薄く表示・`aria-sort`）を踏襲し、`ProjectRows.tsx` の `ProjectRowsHeader` を押しボタン化した。ヘッダーとプルダウン（`FilterBar.tsx` の `SORT_OPTIONS`）は同じ `sort` state（`sort_by:sort_dir`）を共有するので、どちらを操作しても表示が連動する。サーバー側は既存の `GET /projects` の `sort_by`/`sort_dir`（`SORT_COLUMN_MAP`）をそのまま利用し、追加実装は不要だった。並べ替えを変えると既存の仕組みで1ページ目に戻る。モバイルのカード表示・ボード表示はヘッダー行を持たないため対象外。

**財務ダッシュボードの仕入入力で担当者を登録できるようにした**。①仕入は`purchases.assigned_to`列を元々持っていた（マイグレーション不要）が、サーバーの`POST /purchases`は常に作成者のIDで固定保存し、`PUT /purchases/:id`は担当者を更新するSQL自体を持っていなかったため、誰が仕入を担当したかを後から記録・修正する手段が無かった。POST・PUTともリクエストボディから`assigned_to`を受け取れるようにし（POSTは未指定時のみ従来どおり作成者に落とす・PUTは他の項目と同じ「渡さなければ今の値を保つ」部分更新契約に揃えた）。②画面側は販管費（SGA）の担当者選択と同じUI・挙動を踏襲した——`PurchaseDialog`に`SearchableSelect`の「担当者」欄を追加し、新規登録時はログインユーザーを初期選択、`usePurchaseDialogData`にユーザー一覧取得（`GET /users?limit=200`）を足して`PurchaseListPage`から配線した。検証: `server`/`client`の型チェック、`shared`のVitest 1996件全通過、`npm run verify:up`の検証DBに対し実際にAPI（POST/PUT）を叩いて担当者の保存・更新・部分更新時の保持・空文字によるクリアを確認。
