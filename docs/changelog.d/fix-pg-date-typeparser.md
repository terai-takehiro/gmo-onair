**日付の列が、コンテナの時間帯を設定した日に一斉に1日ずれる状態だったのを直した**（棚卸し ⑦）。⚠️ **いま合っているのは、たまたま UTC で動いているからです。** `pg` の既定では `DATE` 型が JS の `Date` になり、`2026-08-31` は「ローカル時刻の 0 時」として扱われるので、`TZ=Asia/Tokyo` を入れると JSON では `2026-08-30T15:00:00.000Z`＝**前日**になります。**実際にサーバーを `TZ=Asia/Tokyo` で起動して再現しました**（役務提供完了日が `2026-08-30` として返る）。DB 全体で DATE 列は **25 列**あるので、時間帯を設定した瞬間に全部ずれます。`DATE` を `YYYY-MM-DD` の文字列のまま返すようにして、TEXT の日付列と形を揃えました。⚠️ **25 列すべての消費側を洗ってから入れています** — `Date` のメソッドを直接呼んでいる箇所・`.split('T')` している箇所・`Date` と文字列を混ぜて比べている箇所はいずれも 0 件で、残りは `::text` / `to_char()` でキャスト済みか「先頭10文字を取る」形なのでどちらでも同じ結果になります。⚠️ **既にあるキャストは消していません**（冗長になるだけで無害だが、テストがその存在を検査しているため）。**むしろ既存の不具合3件が同時に直ります**: ①qsheet の放送日が `String(Date).slice(0,10)` で **`"Mon Aug 31"`** という日付ですらない文字列になっていた ②引き合いのストック見直し日が末尾アンカー付きの正規表現に当たらず**常に「今日が見直しの日です」**と出て日付入力も空だった ③進行台本の `broadcast_date`（TEXT 列）に時間帯付きの ISO 文字列が書き込まれていた。あわせて Excel 書き出しの日付が `2026-08-31 00:00:00` → `2026-08-31` に、MCP の JSON が `"2026-08-31T00:00:00.000Z"` → `"2026-08-31"` になります。
