**配信収録設定の Excel 出力を現地で取り込める形に直し、配信設定に YouTube プリセットを足した**（ユーザー報告「エクセル出力がうまくいっていない」「UIUXがAssistantアプリを全然反映しきれてない」）。現地の GMO ONAiR Assistant の取込実装・UI と突き合わせて洗い出した実バグ: ①**シートの並びが選択を無視して常に「収録 → 配信」固定**で、Assistant は1枚目しか読まないため、配信設定の画面から既定のまま書き出した Excel が現地でそのまま取り込めなかった（`?sheets=` の並び＝シートの並びにし、開いた画面のシートを既定で1枚目に）②収録先 `USB-C` が現地で解決されず行ごと弾かれていた（正規化すると `usbc` になり機器の `usb1` に一致しない。書き出し時に `SSD 1`→`ssd1` 等の機器の呼び名へ写す）③書き出しの失敗理由が権限でも日付違いでも常に「書き出しに失敗しました」だった（blob のエラー本文を読んで理由を出す）④「キーを入れて出す」を選んでも点検の見本はキー列が常に（空欄）だった（keyMode を見本に反映し、復号できない鍵は赤で止まってもらう — `ENCRYPTION_KEY` が変わるとキー空欄の Excel が黙って出来上がっていた）⑤収録と配信で実施日が違うと、選んだほうのシートが見出しだけで出た（シートごとに自分の実施日で引く）⑥書き出しが editor 限定で閲覧の人は 403 だった（書き出し自体は閲覧可・「キーを入れて出す」だけ editor）。UI は Assistant を反映: **配信先プリセット**（YouTube プライマリ / バックアップ / カスタム入力・Assistant の `presets.ts` と同じ中身と判断）を追加し、YouTube の配信先では**公式の日本語ローカライズ情報**（推奨ビットレート表・キーフレーム2秒・公開設定 / 遅延 / DVR 等 YouTube Studio 側の確認リスト。出どころは `docs/design/v4/qsheet-v4-coding/youtube-live-reference.md`）を畳んで出す。収録設定の実施日変更の生 `window.confirm` も配信設定と同じ確認ダイアログに揃えた。モック（`mockups/tech-settings/`）と契約文書（`docs/design/qsheet-recording-streaming.md` §3-3/§4-2）も同じ内容に更新。検証: `shared/tests/deviceExcelExport.test.ts`（12件・シート順 / 収録先の写像 / キー見本 / 復号チェック）と `streamPresets.test.ts`（10件・URL を1字も変えない）を新設。
