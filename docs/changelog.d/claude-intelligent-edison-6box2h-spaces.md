**Wiki にスペース管理の画面（`/wiki/spaces`）を作った。これで設計 §6-① の画面が全部そろい、左メニューに押せない項目は1つも無くなった。** これまでスペースの追加や「メンバーだけ」のスペースのメンバー変更は DB を直接触るしかなく、段F で作った毎月1日の見直しの通知も**スペースの担当宛て**なのに、その担当を画面で決められなかった。できることは、スペースの**追加・編集（名前・説明・閲覧範囲・担当）・削除**と、閲覧範囲が「メンバーだけ」のスペースの**メンバーの追加・削除**。区画 `wiki` の **manager** だけが使え（設計 §8）、**PC の画面**（`pcOnlyScreens.ts`）。

⚠️ **管理の画面でも、読めないスペースは出さない**（§8「存在ごと見えない」）。manager でも、入っていない「メンバーだけ」のスペースは一覧に出ず、直そうとしても 404。ここで例外を作ると「管理の画面を開ける人には全部見える」に変わってしまうため。system_admin はすべて直せる。⚠️ **担当は必ずメンバーに加える** — 「メンバーだけ」のスペースの担当にメンバーでない人を据えると、その人には見直しの通知もコメントの通知も届かない（#735 で送る時点で読めるかを見るようにしたため）。担当を決めたとき・「メンバーだけ」に切り替えたときはサーバーが担当と自分をメンバーに加え、**担当と自分はメンバーから外せない**（外した瞬間に通知が届かなくなる／自分から見えなくなって戻せなくなる）。⚠️ **URL に使う名前（`/wiki/s/:key`）はあとから変えられず、削除したスペースの名前も使い回せない**（貼られたリンクが切れる・別のスペースを指すのを防ぐ）。**ページが1件でも残っているスペースは削除できない**（下書きを含む。中のページがどこからも辿れなくなるため）。「全員」に戻してもメンバーの一覧は消さない（戻したときにそのまま使える）。

**打ってすぐ Enter を押しても名前が欠けないようにした。** 名前・説明の欄は日本語入力を壊さない `BufferedInput` で、値を外へ渡すのは打つのが止まって 500ms 後なので、state を読んで送ると最後の数文字が落ちる。送るときはフォームに見えている値（`FormData`）を読む。
