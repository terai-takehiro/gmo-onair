**カレンダーの旧3画面（スタジオ予約・パートナースケジュール・マイカレンダー）をFullCalendarから自前描画に載せ替えた。**
① 予定（統合カレンダー）は既に FullCalendar をやめて自前描画（`contexts/production/pages/calendar/`）に
作り直し済みだったが、予約を作る唯一の導線であるスタジオ予約・パートナースケジュール・
マイカレンダーの3画面だけが FullCalendar のまま残っていた（v4 着手時に「作り直し前の画面なので
同じ回で触らない」と意図的に先送りしたもの）。今回この3画面も①と同じ描画部品
（`CalToolbar`/`MonthGrid`/`TimeGrid`/`EventTable`）に載せ替え、月・週・日・一覧の見た目を
①予定と統一した。
②データの取り方・予約/予定の作成・編集ダイアログ・部屋管理・カレンダー連携（ICS/サイネージURL）・
香盤ビュー（部屋を縦に並べて空きを見る日表）はいずれも1行も変えていない — 変えたのは
マス目の描き方だけ。スタジオ予約の香盤（日表）だけは①予定の日表（重なりを横に割る形）に
寄せず、部屋ごとの縦並びのまま残した（見る目的が違うため）。
③クリック&ドラッグでの新規作成は①予定と同じ判断でやめ、「予約追加」「予定を登録」ボタン
（または香盤のマスを押す形）に統一した。案件作成画面の「カレンダーで空きを見る」から
スタジオ予約画面への持ち込み（`location.state`）は、v4でその導線が①予定（`/studio/calendar`）へ
張り替え済みのため対応するコードごと削除した（もう来ることのない state だった）。
④マイカレンダーだけは色分けを①予定より詳しいまま残した（Google/Outlook/ICS/共有予定を別色に
区別）。本人にとって一番大事な区別（自分で入れたか外部同期か）なので、①予定の3層モデル
（層ごとに1色）へ単純化するとここが崩れる。
⑤ついでに「直近7日の予定」カードが、表示中の月を送ると（今日を含まない範囲になり）
中身が崩れていた既存の挙動を直した。表示中の期間とは別に常に「今日から7日間」を引く
専用の問い合わせに切り離した。
⑥FullCalendarへの依存（`@fullcalendar/*` 6パッケージ）とそれ専用のCSS（`.studio-calendar .fc-*`
規則・`index.css`）を削除した。
検証: `npx tsc -b client` / `npm run lint` / `npm run test`（1139件）OK。実ブラウザ（Playwright）で
スタジオ予約（月/週/日=香盤/一覧・部屋フィルタ）・パートナースケジュール・マイカレンダーを
デスクトップ幅・375px幅の両方で確認済み。
