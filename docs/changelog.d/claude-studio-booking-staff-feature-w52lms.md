**スタジオ予約の担当者（PR #567）を、配ったカレンダー・MCP・マニュアル・検証データにも行き渡らせた**。担当者そのものは #567 で入ったが、**画面の外に出る経路が抜けていた**。①カレンダー連携（ics）の本文に `担当: …` を出すようにした——Google / Outlook に取り込んだ予定には担当者が出ず、「誰が持つ現場か」を見るのに ONAiR を開き直す必要があった。②MCP `list_studio_bookings` の返り値に `assignees` を足した（`create_studio_booking` の引数は #567 で対応済みだったが、**書けるのに読めない**状態だった）。③利用マニュアルに担当者の選び方を足し、あわせて「人で絞る」の説明を実装に合わせて直した（「人を持たないスタジオ予約が消えます」のままで、担当者で絞る挙動と食い違っていた）。控室の利用者・用途が社内の担当者とは別物であることも書き添えた。④検証環境のシードに担当者付きの予約を4件入れた（1件も無いと画面から確かめられない）。⑤データビューアの許可テーブルに `studio_booking_assignees` を足した。検証: `server`/`client` の型チェック、`npm run lint`、`shared` の Vitest 1996件、検証DBで ics フィードに `担当: 検証 フルアクセス、検証 管理者` が出ることをAPIで実地確認。
