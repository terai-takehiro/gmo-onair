**台帳の検索欄が、1文字打つごとにサーバーへ問い合わせていたのを直した**（棚卸し ③）。⚠️ **実測で「7文字打つと7リクエスト」→「1リクエスト」になりました**（実ブラウザ・本番ビルドで、直す前と後を両方測っています）。1リクエストはサーバー側で 4〜5 本の SQL を走らせるので、**打鍵のたびに 30 本前後の走査**が起きていたことになる。あわせて、絞り込みを変えたときに**前の通信を中断する**ようにした（`signal` をどこにも渡していなかったので、押した回数ぶんサーバーの接続を掴み続けていた）。⚠️ **中断は「失敗」ではないので、retry もエラー表示もしない**ようにしている — ここを外すと、中断された通信は HTTP の状態を持たないため retry 判定で 4xx に当たらず**2回リトライされたうえで「通信ができませんでした」**と出て、**絞り込むたびにエラーが出る画面**になる。⚠️ **`AbortController` は自分で作らない**（react-query が渡してくる `signal` だけを使う）。⚠️ **入力欄が読む値は遅らせず、遅らせるのは問い合わせの鍵だけ**（入力欄まで遅らせると打鍵が1テンポ遅れて見える）。⚠️ **「該当なし」の判定は遅らせた値で行う** — 即時の値だと、まだ問い合わせていない言葉で「該当なし」が一瞬出る。⚠️ **売上台帳は `useCrudPage` を使っていない**ので、フックを直すだけでは効かず個別に入れている（一番重い画面なので、ここを落とすと意味が半減する）。機材アプリにあった同じ実装は shared へ上げ直し、**既定の 400ms は変えずに**再エクスポートにした。
