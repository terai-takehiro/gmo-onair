**2026年10月の事業再編（社名変更・計上会社の2社化・案件番号の改番）P1の残作業のうち、`create_studio_booking` MCPツールの番号指定と `client-techops`（制作技術支援）の旧番号検索を実装した**（`docs/reorg-2026-10-plan.md` §4.10「検索」・§6 P1「まだのもの」）。①`server/src/contexts/mcp/tools/studio.tools.ts` の `create_studio_booking` に `gls_number` 引数を追加し、`project_id` が渡されず `gls_number` だけ渡された場合に、現行番号（`projects.gls_number`）と旧番号（`project_numbers.number`。改番後も履歴として残る）の両方から完全一致で案件idを解決するようにした（配線済みの他6箇所と同じ形をそのまま踏襲・共有ヘルパー化はしていない）。見つからなければ `NOT_FOUND` で番号を含む分かりやすいエラーを返す。②`client-techops` トップ（`GET /techops/top-items`）が返す各行に、改番で退役した旧番号の配列 `retired_numbers` を追加し、クライアント側 `matchesSearch()` がそれも検索対象に含めるようにした。③進行台本の新規作成ダイアログの案件選択（`GET /lookup/gls-options`）も同様に `retired_numbers` を返すようにしたが、こちらは自由文字列で絞り込めるコンポーネントではなく単純な shadcn/Radix `<Select>` だった（実装前に確認：Radixのキーボードタイプアヘッドは `textValue` の**前方一致**のみで、末尾に旧番号を混ぜても引っかからないため効果が無いことをソースで確認した）ため、選択肢のラベル自体に「(旧: GLS-A012)」のように旧番号を出し、人が一覧から目視で見つけられるようにする形にした（`CreateSheetDialog.tsx`）。両タスクとも `org_transition.state`・`entity_code` は一切見ない（旧番号→現在の案件、という解決だけの機能で切替状態に関わらず常に効く。P1の既存6箇所と同じ）。検証: `npx tsc -b server`・`npx tsc -b client-techops` 通過。検証DB（`npm run verify:up`）に改番のテストデータ（現行番号・退役した旧番号を持つ `project_numbers` 行）を作り、`create_studio_booking` の実ハンドラを直接呼んで旧番号解決による作成成功／存在しない番号での404エラーを確認、実サーバー（`createApp()`）を起動して `GET /techops/top-items`・`GET /lookup/gls-options` の両方が旧番号を `retired_numbers` として返すことを確認（10件のアサーション全通過）、検証後にテストデータは削除。
