**機材メンテナンスの修理日編集ダイアログで、保存中に状態を変えると片方が消える不具合を直した**（PR #645 マージ後にCodexレビューで見つかった追加指摘）。

修理引取／発送日・修理受取／返送日の編集ダイアログ（「修理日を編集」）は、保存ボタンを押すと
`update` mutation を投げた直後にダイアログを閉じていた。PUT が終わる前に背面の行の状態
（報告済／対応中／完了）の `<Select>` がまた押せる状態に戻るため、応答が返る前に状態を変えると、
あとから終わった方のPUTが行全体を書き直すため、もう一方の変更（日付または状態）が古い値で
上書きされて消えていた。

保存の成功後（`onSuccess`）にダイアログを閉じるようにし、保存中はダイアログ自体を
Esc・外側クリック・「キャンセル」でも閉じられないようにした。これで保存が終わるまで
背面の行を操作できず、競合が起きなくなる。

検証: `npx tsc -b client-equipment`・`npx eslint`（該当ファイル）・`npm run lint`
（warning数が着手前と同じ）・`npm run test`（shared Vitest 2269件）通過。
