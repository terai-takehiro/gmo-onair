**案件作成の受付が「決めても片づかない」のを直した — 自動取込案件の件数が実数と合わず、見送りにしても何も起きなかった**（ご指摘）。
①⚠️ **ダッシュボードの「自動取込案件を確認」は、押した先に並ぶものとは別の集合を数えていました。** バッジは受信箱の**4種類の合計**（`counts.total`＝期限超過・ネタ案件・問い合わせ・受け取った書類）で、押して開く案件作成が並べるのは**ネタ案件と問い合わせの2種類だけ**です（残り2つはそれぞれ別の画面が持っています）。**実測でバッジ 14 ／ レール 7。** 数え方を `intakeCountOf`（`INTAKE_KINDS` を足す1か所）に寄せ、PC・スマホの両方が同じ関数を通るようにしました。
②⚠️ **その件数は上限で頭打ちにもなっていました。** サーバーは一覧を `LIMIT 50`／`LIMIT 100` で切ったうえ、**件数をその配列の長さで返していた**ので、溜まるほどズレが広がります（**実測: 未確認の AI 起票 124 件 → 50、未仕分けの問い合わせ 132 件 → 100**）。件数は `COUNT(*)` で数え、**一覧と件数を同じ `FROM 〜 WHERE` から組む**ようにしました。並べきれなかった分は**レールに「ほかに N 件」と書きます**（黙って切り詰めない）。
③⚠️ **「見送りにする」を押しても、カードも数字も1つも動きませんでした。** 受付の一覧（`AI_INBOX_SQL`）は `ai_reviewed_at IS NULL` しか見ておらず、**ステージの条件が1つもありませんでした**。受付の3つの決め方のうち印を書いていたのは**「ネタのまま残す」だけ**で、**見送り・案件にする はステージを動かすだけ**だったため、**見送り・仮押さえ・受注・完了の4つとも受付に残り続けます**（実測）。DB は正しく `e_lost` になっているので**エラーも出ず、押した人には「壊れている」としか見えません**。→ **受付に出すのはネタ行きだけにしました**（ご判断）。段が1つでも進んでいれば誰かが動かした＝仕分け済みなので、見送り・受注・完了は**この1行で自動的に外れます** — **印が書かれていない古い行も片づきます**。あわせて、人がステージを動かしたら **AI 起票の未確認案件に「確認済み」の印を押します**（`markAiReviewedByStageDecision`）— こちらは案件一覧の「AI・未確認」の札と教師データが使います。⚠️ **AI が仮押さえ以降で起票したものは受付に出ません**（MCP の `create_project` は `d_hold` 以降も受ける）。案件一覧の AI 絞り込み（`ai_created` ＋ `ai_reviewed=unreviewed`）で拾えます。受付に出したいなら **`create_project` 側を `neta` に寄せる**こと — ここを緩めると「決めても消えない行」が戻ります。
④⚠️ **段が1つも動かないときの穴も塞ぎました。**「**ネタのまま残す**」はネタをネタのままにする操作なので**ステージが1つも動かず**、サーバー側の印も押されません。**印を残す場所を `saveExisting` の1か所に集め**、段が動くならサーバー・動かないなら画面が押します。**3つの決め方で扱いを分けません** — 分けた結果が今回の「ネタのまま残す だけ受付から消える」でした。
⑤**この直しは、止まっていた教師データも動かします**（会社方針「AI を使い捨てにしない」）。「案件にする」は印を書いていなかったので、**無修正で採用された回が1件も記録されていませんでした**（＝ AI がうまくいった回だけ数字に出ない）。⚠️ **見送りは「採用」に数えません** — 見送りは AI の**不採用**で、`recordIntakeDecision(…'dropped')` が拾いすぎの指標として残します。⚠️ **AI 自身がステージを動かしたときは印を押しません**（メール取込のスキルが毎日動かすので、押すと**誰も見ていないものが確認済みになって静かに消えます**）。印が**本当に付いたときだけ**（`RETURNING`）記録するので、AI 起票でない案件を動かしても受入率は水増しされません。
⑥**問い合わせの「見送りにする」「ネタのまま残す」が 403 になる人がいたのを直しました。** 受信箱は `dailyops` の **reader** にも問い合わせのカードを返すのに、行き先を動かす口（`POST /dailyops/inquiries/:id/state`）だけが `dailyops` の **editor** を要求していました。つまり **`sales:editor` ＋ `dailyops:reader`** の人には**レールにカードが出るのに、どちらのボタンも 403**（実測）。同じ表を読む `GET /inquiries/:id`・`POST /inquiries`・`link-project` は同じ理由ですでに `sales` でも通しており、**動かす口だけ狭いまま**でした。**権限が無い人は今までどおり弾きます**（権限なし・`budget` のみ で 403 を実測）。
⑦**検証**: 実 Postgres ＋ 実 API で、**段ちがいの AI 起票6件＋人が作ったネタ1件**を並べて**受付に出るのはネタ行きの1件だけ**であること、**ネタのまま残す → 3／見送り → 2／案件にする → 1／問い合わせの見送り → 0** と**押すたびにバッジが減り、レールの件数と毎回一致する**ことを実測（直す前は 14 のまま1つも動かず）。教師データも**見送りだけ `reject`・残り2つは `none` 18項目**を実測。`shared/tests/intakeInbox.test.ts` に 17 項目を固定し、**反証5本**（一覧の stage 条件を外す／印を押す呼び出しを外す／見送りも「採用」に数える／バッジを `counts.total` に戻す／段が動かないときの印を外す）が**それぞれ落ちること**を確かめてあります。`npm run test` / `typecheck:all` / `lint` / `build:all` ＋ `check:frozen` OK。**DB マイグレーションはありません。`shared/src/` も触っていません**（凍結4アプリの CSS は不変）。
