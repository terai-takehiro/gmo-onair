**検収書PDFの日付を発行日にし、トップページ「日常業務」フライアウトの漏れを直した**。
①案件管理から検収書としてPDFを発行すると、右上の日付が過去の日付（請求日・計上日）に
なっていた。検収書は「発行した日」を表す書類なのに、見積書・請求書と共通の日付算出ロジック
（請求日→計上日→今日、の優先順）をそのまま使っていたため。`pdf.service.ts` で検収書のときだけ
常に発行時点の日付を出すようにした。
②トップページの「日常業務」タイルにマウスを合わせたときのフライアウトメニューに、
新設済みの「フィードバックチケット」「タスク・依頼」が出ていなかった（`AppTiles.tsx` の
ハードコード配列に新機能追加時の追記が漏れていた）。左メニュー（`client-daily/src/components/layout/nav.ts`）
と揃うよう2項目を追加した。
③財務ダッシュボードの「総額／確度加味」切り替えを、営業見通し（パイプライン）カードだけに
効く設定から、絞り込み状態も含めた**画面全体**の見方の切り替えに作り直した。確度加味の
とき、サーバー（`monthly-summary.service.ts`）が売上・仕入（変動原価）を計上先の案件の
いまのフェーズの受注確度（%）で重みづけて合算し直し（固定原価・販管費は対象外）、内訳の
売上・仕入の各行にも同じ確度を掛けて表示するようにした（あくまでシミュレーション表示で、
`revenues`/`purchases` の実額は変えない）。役目が画面全体に吸収されたため、営業見通し
（パイプライン）カードと専用API（`GET /pipeline-forecast`）・専用集計
（`pipeline-forecast.service.ts`）は削除した。
検証: 新規マイグレーションなし。`server`/`client` の型チェック・`npm run lint`・`shared` の
Vitest 2240件、すべて通過。確度加味の重みづけ計算は検証用DBに実データ（確度50%のフェーズの
案件に売上¥1,000・仕入¥200を計上）を投入し、総額と確度加味の両方（全体集計・案件絞り込み
の両分岐）で期待値（¥500・¥100）と一致することを確認済み。
