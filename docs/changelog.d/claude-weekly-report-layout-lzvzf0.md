**隔週キープの資料（pptx）で、表の升が長い自由文で膨らんで箱をはみ出す不具合を直した**。
①ヨミ表・内覧会の来場者分類・進行表・手入力の表（`renderPipeline` / `renderCategoryTable` /
`renderSchedule` / `renderGenericTable`）は、PowerPoint が升の高さを「実際に折り返した行数」から
決め直す（`<a:tr h="0">` は目安に過ぎない）ことを踏まえずに作っており、長い案件名・お客様名・
分類名（実データで50字を超えるものもある）を切らずに置いていたため、1升が2〜3行に折り返って
表の下端がテンプレの箱をはみ出し、フッターに重なったりスライドの外に出たりする恐れがあった。
②文字数から幅を見積もって升を1行に収まる長さへ切る `truncateEm` と、行数の上限を件数の
固定値ではなく**箱の高さ**から逆算する `maxRowsForBox`、行ごとの高さを明示して PowerPoint に
高さを決め直させない `rowH`（配列）を `keep-pptx-chrome.service.ts` に足し、上記4つの表の
描画に適用した。ヨミ表は表示件数の上限も固定16件から箱の高さ・文字の大きさに応じた
動的な件数に変え、収まらない分は従来どおり「ほかN件（案件一覧を参照）」に retreat する。
検証: 検証環境から実データのパック（`get_keep_report_pack`）を取り、標準の構成
（`buildStandardPages`）で25ページの pptx を実際に出力し、生成された XML を解析して
①表の行の高さの合計が箱の高さちょうどに収まっていること ②50字超の案件名・分類名が
実際に「…」で1行に切られていること、を確認した（この環境は LibreOffice で pptx を絵に
起こせないため、`server`/`shared`のVitest 2237件全通過・型チェック・lint に加えてXMLの
実測で裏を取った）。

**②案件実施報告・案件ページ・③内覧会報告のデザインを刷新した**（モックアップでの確認を経て）。
罫線・色線・縁取りだけの四角枠で区切っていたのをやめ、面（塗り）とバッジで区切る方針に統一。
①帯（客先／イベント名／日付）は1行＋確度バッジに（`renderInfoBand`。案件ページの単独の確度の枠は
