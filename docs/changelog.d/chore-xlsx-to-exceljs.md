**Excel の読み書きを xlsx (SheetJS) から exceljs へ寄せ、修正版の出ない High 脆弱性を解消した**（リリース準備 R6-b）。xlsx には修正版が存在しない既知の脆弱性（High 2件・Prototype Pollution / ReDoS)があり、一方 qsheet の Excel 機能は既に exceljs を使っていて社内に2つの Excel ライブラリが並走していた。残っていた xlsx の利用3ファイル（`server/src/shared/utils/excel.ts` の共通ユーティリティ＝機材・ケーブル・コネクタ・売上・バックアップ等の取込と出力／決算取込の MoneyForward 形式パーサ／リアルタイムCG の Excel 取込）を exceljs ベースに書き直し、`xlsx` を依存から外した。exceljs は読み書きが非同期のため `buildExcelWorkbook` / `parseExcelBuffer` / `parseExcelHeaders` が async になり、呼び出し18か所に await を足した（すべて async ハンドラ内・挙動不変）。旧実装と新実装の等価性は、両ライブラリで組んだ Excel フィクスチャの突き合わせで検証した（ヘッダー・行・数値・真偽値・シート名の31文字切り詰め・列幅・空行スキップ・取込の列マッピングがすべて一致）。日付セルだけ意図して改善: 旧実装は「1/15/26」のような2桁年の表示形式だと日付を読めず計上月の1日に落ちていたが、新実装は形式によらず正しい日付を ISO で読む（決算取込で実証）。検証: `npm run typecheck:all` / `npm run test`（1452件）/ `npm run lint`（0 errors / 59 warnings・基準どおり）。あわせて ci.yml の npm audit の注記から xlsx を解消済みに更新した（残りは nodemailer のみ）。
