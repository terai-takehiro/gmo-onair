**customers/vendorsテーブル削除（PR #243・migration 205）を revert した**（検証環境の障害対応）。マージ後、検証環境（dev.gmo-onair.jp）でサーバー起動のたびに `DROP TABLE customers` が `cannot drop table customers because other objects depend on it` で失敗し、コンテナが再起動ループに入って502が続く障害が発生した。migration は失敗時にロールバックされるため `customers`/`vendors` テーブル自体・データは無事だったが、サービスが完全に停止していたため、原因調査より復旧を優先しPR #243の内容を丸ごと revert した。原因（何が customers/vendors に依存して残っていたか）は別PRで調査の上、migration 205を修正して再度提案する。
