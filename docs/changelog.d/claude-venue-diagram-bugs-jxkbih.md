**会場図面の不具合6件を直した**（利用開始後の指摘）。①左パネルのタブ名「置く」「並べる」は
アプリの他画面（運営マニュアルの「追加」「差し込む」など）と語がそろっていなかったので、
`docs/design/v4/venue-layout.md` の語彙にすでにある名詞形に寄せて「追加」「並べ方」に統一した
（並べ方の「格子に並べる」も他の並べ方（劇場形式など）と同じ「◯◯形式」に）。ボタン・文言も同じ動詞に
そろえた。②タブを切り替えると盤を含む3列レイアウトが揺れていたのは、CSS Grid の既知の落とし穴——
固定幅の列でも中身の `min-content` がそれより広いと列が広がってしまう——で、左右の `<aside>` に
`min-w-0` が無かったのが原因。付けて直した。③④カメラのクレーンは TK-53AL だけを残し、TK-53A と
その専用台車 TI-04B（「53A 台車」）は追加メニューから外した（カタログの行自体は残すので、既存の
図面に置いてあれば表示は変わらない）。⑤「並べ方」タブのプレビューは幅と高さの両方を固定の
220×140 に収めようとしていたため、行数の多い並べ方ほど二重に縮んで品目が見えなくなっていた。
幅だけで縮尺を決め、高さはプレビューの箱ごと伸ばすようにした（左パネルは元々スクロールする）。
⑥並べ方で作ったグループを盤に置いたあと、グループごとつかんで動かしたつもりが1脚だけ動いて
しまっていた——ダブルクリックでない限りグループ全体を動かす設計（`docs/design/v4/venue-layout.md`
§4-6）に対し、実装はどのクリックでも常に1個だけを動かしていた。グループの他のメンバーもドラッグ
中に同じ量だけ一緒にずれて見えるようにし、指を離したときは全メンバーへ確定するようにした
（ダブルクリックで1個だけをつかんだ場合は今までどおりグループから外れる）。

①〜⑥と同じ「グループが結局1個ずつ扱われる」系統のバグをほかにも探して3件見つけて直した。
⑦グループを選んだ状態で Ctrl+D 複製すると、複製した側は全部グループが外れてバラバラになって
いた（複製後も2個以上そろって複製されたときだけ新しいグループとしてまとめ直すように）。
⑧グループ全体を選ぶと、メンバー全員ぶんの回転つまみが品目の数だけ重なって出ていた（50脚の
グループなら50個）。回転・伸ばすつまみは1個だけを選んでいるとき（ダブルクリックで選び直した
とき）だけ出すようにした。⑨設計書（§6②操作表・§4-6）にある「Ctrl+G で任意の複数選択もグループ
にできる」がキーに割り当てられておらず、対応する純関数 `groupItems` も呼ばれないまま残っていた。
キー割り当てを足し、右パネルの複数選択にも「グループ化」ボタンを添えた——ここで、Ctrl+G で
できた「並べ方の情報を持たないグループ」を選ぶと、右パネルの「並べ直す」がそのグループを
どこかの並べ方（既定は劇場形式）の既定レイアウトへ丸ごと置き換えてしまうところだったので、
並べ方の情報（`arrange`）を持つグループにだけ「並べ直す」を出すよう分けた。

**会場図面に削除する機能が無かったのも直した**。サーバーの `DELETE /venue-layouts/:id` と
クライアントの `deleteVenueLayout()` はすでにあったが、どの画面からも呼ばれていなかった——
一覧の「その他」ボタンは「削除…は編集画面から」と案内していたのに、編集画面（資料の帯）にも
削除ボタンが無く、実際にはどこからも削除できなかった。運営マニュアル（`ManualDetailPage.tsx`・
`DeleteManualDialog.tsx`）と同じ形で、編集画面に確認ダイアログ付きの削除ボタンを追加した
（確定済みは削除できない仕様のまま。確定を解いてから削除する）。
