**制作技術支援に新しいミニアプリ「運営マニュアル」の設計とモックアップを起こした**（実装はまだ1行も書いていない）。①制作技術支援には当日の香盤（スケジュール表）・尺と担当（進行台本）・デッキ（収録設定）・配信先（配信設定）・借りる機材（レンタル機材検索）・体制と連絡先（案件管理）が**もう全部入っている**のに、現場に配る A4横の運営マニュアルは毎回 PowerPoint で一から打ち直していた。元の資料を直しても冊子は直らないため、当日、手元の紙と画面が食い違う。冊子の見た目（表紙・柱・章立て）も人ごとにバラバラで前の案件から持ってこられず、配信のストリームキーや会議のパスコードを気づかずに紙へ写してしまう経路もあった。②各ミニアプリの情報を「差し込みブロック」としてA4横のページに置き、1冊に組んで PDF で配るミニアプリを設計した。利用者に見せる語は4つ（冊子・ページ・ブロック・ひな形）、動詞は3つ（差し込む・置く・書き出す）。画面は PC 4枚＋スマホ 1枚で、編集の手つきは PowerPoint に合わせる（つかんで動かす・8方向のつまみ・矢印キー 1mm・Alt 複製・Ctrl+Z・すいつき・整列）。文字の意匠は Web の自由度をそのまま使い、袋文字（`-webkit-text-stroke`）・影・グラデーション文字（`background-clip:text`）・縦書き・長体まで出せる。差し込んだブロックは生きていて、元が変わると「元が変わりました」で知らせ、**確定すると全ブロックがその時の中身のまま凍る**（配った紙と画面が食い違わない）。配信の鍵・合言葉・会議のパスコードは差し込んでも既定で伏せ字のままにし、サーバー側（`resolve`）が平文を返さない。PDF はサーバーに Chromium を入れず、進行台本の印刷（`client-techops/src/components/editor/previewExport.ts`）と同じブラウザ印刷（`@page size: 297mm 210mm`）で出す。③データは表3本（`qsheet_manuals`・`qsheet_manual_pages`・`qsheet_manual_templates`）で、ページ1枚＝1行・ブロックは JSONB。進行台本の `qsheet_documents.data`（Yjs の所有物・サーバーは書かない）とは別物で、こちらはサーバーが書き `updated_at` の突き合わせで取り合いを見つける。作る順は段A〜E（段D の PDF まで通して初めて使える）。④設計書は `docs/design/v4/production-manual.md`、モックは `docs/design/v4/mockups/native/production-manual/`（PC 4枚・スマホ 1枚・A4横の実寸 1枚・考え方の地図 1枚。押せる試作）。名前・「ブロック」という呼び名（進行台本の列の別名と重なる）・確定で凍らせる運用・秘密の伏せ字・同時編集の要否など7件は設計書 §10 に「決めていただきたいこと」として残し、回答を待ってから着手する。検証: `node scripts/check-md-links.mjs`・`npm run lint`。
