**BOX の片づけが「結局処理されない」理由を画面に出し、ゴミになった案件を案件台帳から外せるようにした**（ユーザー報告「このように出て結局処理されない」／依頼「失注やネタ見送りなどゴミになった案件は案件台帳等からも抹消したい」）。①**なぜ触らなかったのかが分からなかった** — 504 は直り名寄せも動いた（BOX のフォルダ 120 件を調べて 94 件を結び付けた）のに片づけは0件で、画面は「置き場所や名前が想定と違うか中身を数え切れなかった」としか言わなかった。⚠️ **理由は最初から DB（`box_cleanup_note`）に書いてあり、画面へ出していなかっただけ**なので、集めて数えて内訳を出すようにした（「BOX のフォルダ名がこのアプリの付け方と違う 12 件（例: 【社内】GLS-A001_旧い名前）」のように**実物の名前・親フォルダIDまで**出す）。置き場所が違うのか名前が違うのかで直し方は正反対なので、内訳が無いと次の一手が決められない。②**ゴミ案件を案件台帳から外す帯**を案件一覧の「終了」に足した。⚠️ **物理削除ではなく論理削除（`deleted_at`）にした** — 請求書・検収書は電子帳簿保存法の保存対象で、失注案件の見積は失注分析の唯一の材料、しかも失注は90日放置の自動見送りで**機械も付ける取り消せる状態**なので、取り消せない削除の根拠にしてはいけない。台帳・検索・集計からは完全に消えるが行は残るので戻せる。対象は**失注すべて＋90日動いていないネタ**（自動見送りと同じ日数を使う）で、**売上・仕入が付いているものは残す**（按分も見る — グループ案件では子は `revenue_allocations` にしかおらず、直接の行だけ見ると売上のある案件を外せてしまう）。⚠️ **外す直前に BOX の片づけを試す** — 片づけの対象は `deleted_at IS NULL` で絞っているので、先に外すとそのフォルダは二度と対象に選ばれない。片づかなくても外すが、**片づかなかった件数は画面に必ず出す**。残した件数（売上あり）も出す（消えていないことに人は気づけない）。検証: `npm run typecheck:all` 緑、`npm run test` 1743件緑（新規22件）、`npm run lint` 緑。⚠️ **実際の BOX に対しては未検証**（この環境も検証DBも `BOX_CONFIG_JSON` を持たない）。
