**終了した案件の BOX フォルダを「98_終了案件」へ移すようにした**（ユーザー依頼「案件が完了した(日付をベースに案件日の翌日)ものについては 98_終了案件 というフォルダを BOX に新たに作成した上でそこに移動するようにしたい」・migration 249）。⚠️ **移すだけで、絶対に消しません** — 終了した案件のフォルダには納品物・請求書・検収書が入っており法定保存の対象でもあるので、**空に見えても消しません**（数え間違いの余地を作らない）。失注の `99_失注・見送り` とは別の置き場・別の列（`box_done_at`）にした（同じ案件が「失注→戻す→終了」と両方を経験しうるため、`box_cleanup_state` に相乗りさせると復元がどちらの話か分からなくなる）。⚠️ **「終了」の判定はステージだけで決めない** — ご依頼どおり**日付**を見て、`stage = 's_completed'` **かつ** `event_end` が今日(JST)より前、の両方が揃ったものだけを移す。ステージだけだと**まだ本番が来ていないのに手で完了にした案件**のフォルダまで片づけてしまう。日付の式は日次ジョブの `completeElapsedWonProjects`（受注→完了の繰り上げ）と同じものを使い、**その直後に呼ぶ**ので、その朝に完了へ繰り上がったぶんが同じ朝のうちに片づく（人が押しに来なくても進む）。押したいときは案件一覧の帯からも動かせる。⚠️ **BOX が落ちていても日次ジョブは止めない**（通知という本来の仕事まで道連れにしない）。安全弁は失注の片づけと**同じ `checkFolderSafety` を通す**（別に書くと片方だけ緩んだ日に他人のフォルダを動かす）。**案件を完了から戻すと、置き場から親フォルダへ返り `box_done_at` も NULL に戻る。** 検証: 実 Postgres で①完了済み・案件日が過去→待ちに入る②案件日がまだ先→入らない③案件日が空→入らない④すでに移した印がある→入らない、の4通りを確認。`npm run typecheck:all` 緑、`npm run test` 1769件緑（この機能は54→61件）、`npm run lint` 緑。⚠️ **実際の BOX への書き込みは未検証**（この環境も検証DBも `BOX_CONFIG_JSON` を持たない）。 あわせて、**失注案件に仕入が付いているのは「残すべき正しいお金」ではなく異常の合図**であることを画面に書いた（ご指摘「失注になった案件で仕入れが発生することは理論上あり得ません。万が一そういった案件がある場合は何かしら処理が間違っている可能性があるので削除しないでください」）。台帳から外すと**その異常ごと画面から消える**ので、外さずに残したうえで「失注した案件に仕入が付いているのは、本来あり得ません — 中身をご確認ください」と出す。
