**BOX に残った空フォルダを、引き合いのぶんも「どの案件にも結び付かないぶん」も片づけられるようにした**（ユーザー報告「終了したとのことですが、まだ大量にゴミファイルが BOX にあります」）。⚠️ **今回は実物の BOX を読んで原因を特定している** — 親フォルダは 47 → 40 件に減っており（6件が実際に削除・1件がアーカイブへ）**v4.5.11 の直しは効いていた**が、残った 40 件の中に**中身が完全に空（`size 0`・空のサブフォルダ3枚だけ）なのにアプリが触らないフォルダ**があった。理由は「その案件がまだ失注になっていない」ため。①**引き合い（ネタ）のまま止まっている案件も対象に入れた**。⚠️ ただし**生きている引き合いは「空なら消す」だけ**で、中身があれば触らない — まだ失注ではない案件のフォルダを `99_失注・見送り` へ引っ越すのは間違いだから（消したあとその案件が先の段階へ動けば、既存の復元処理が同じ形のフォルダを作り直す）。②**どの案件にも結び付かないフォルダ**（実測: 77 件中 **13 件**）も片づけられるようにした。案件をたどる経路では照らす相手がいないため**永久に触れなかった**ぶん。⚠️ **消す条件は4つ全部**: 親フォルダの直下にある／案件フォルダでないと分かっている名前ではない（`00_DB_Backup` など）／どの案件の `box_url_*` からも指されていない／**このアプリの実行ユーザーが作ったものである**（`created_by` を BOX の `users.get('me')` と突き合わせる。**人が手で作ったフォルダには絶対に触らない**）。そのうえで**中身が空のときだけ**消し、**どの段でも再帰は指定しない**（ファイルが1枚でもあれば BOX が断る＝二重の守りはそのまま）。実行ユーザーが取れなければ1件も触らない。1往復は件数ではなく時間（20秒）で区切り、画面は別の往復で呼ぶ（504 の反省）。検証: `npm run typecheck:all` 緑、`npm run test` 1762件緑（この機能は41→54件）、`npm run lint` 緑。
