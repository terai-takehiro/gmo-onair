# 画面に出す言葉のルール

UI/UX 刷新 (v2.9.251〜) で決めた文言ルール。**PR レビューのチェック対象**。
画面に出るテキスト (ボタン・見出し・説明・エラー・トースト・メール本文) すべてに適用する。
コード内のコメントと変数名は対象外。

---

## 5つのルール

### 1. 1文に1つのことだけ書く

同じ情報を対象ごとに書き分けない。「AI が作った」という1つの事実に4通りの表記を作ると、
読む人には**表記の違いに意味があるように見えてしまう**。

| ✕ | ○ |
| --- | --- |
| AI起票 / AI取込 / AI登録 / AI (対象ごとに4通り) | **AI作成** (すべて統一) |

### 2. 次にやることを先に書く

状態の説明より、その人が次に押すもの・確かめるものを先に置く。

| ✕ | ○ |
| --- | --- |
| この案件は AI（問い合わせメール取込等）により起票されました。 | AI がメールから作った案件です。内容が合っているか見てください。 |
| 確定するまで想定金額には反映されません。 | 「確定する」を押すと想定金額に入ります。 |

### 3. 期限は「何月何日何時何分まで」

「今週中」「なるべく早く」「金曜まで」は**期限として成立していない**。
朝か夜かが決まらないものは期限ではない。日付だけ選ばれたときは 18:00 を補い、**補ったことを画面で示す**。

- 聞き方でも示す: 「いつまで？」ではなく **「何月何日何時何分まで？」**
- AI が曖昧な期限を読んだときは、黙って補完しない。補完した印を出して人に確認させる。
- 期限が読めない依頼も**捨てない**。残して期限を聞く。

### 4. 数字で書き、感想を書かない

「たくさん」「かなり」「だいぶ改善」は書かない。件数・金額・率・日時で書く。

| ✕ | ○ |
| --- | --- |
| 未対応の問い合わせが多数あります | 未対応の問い合わせ 7件 |
| だいぶ待たせています | 最も古い待ち 2日 3時間 |

### 5. 技術用語を画面に出さない

**禁止語** (画面テキストに出したら PR で落とす):

`MCP` / `監査ログ` / `actor` / `共用キー` / `トークン` / `500` / `タイムアウト` /
`Internal Server Error` / `Network Error` / `null` / `undefined` / `JSONB` / `SQL` /
`エンドポイント` / `ペイロード` / `スナップショット`

内部の詳細は**消すのではなくツールチップ (title 属性) に退避**する。ただし退避先も画面テキストなので、
用語そのものは平易な言い方に置き換える。

| ✕ | ○ |
| --- | --- |
| 実行: 共用キー | AI（担当者の記録なし） |
| AI (MCP 経由) が実行した書き込みの監査履歴です | AI が作ったり直したりした記録です。誰の指示だったかも残ります。 |
| 500 Internal Server Error | サーバー側で処理が止まりました。少し待ってから、もう一度お試しください。 |

エラー文の組み立ては `shared/src/client/states/ErrorPanel.tsx` の `humanizeError()` に集約してある。
**例外オブジェクトのメッセージを画面にそのまま出さない**こと。

## 言い換え表

| いまの言い方 | これから | なぜ |
| --- | --- | --- |
| 実行: 共用キー | AI（担当者の記録なし） | 認証方式は業務に関係ない。「特定の人ではない」という意味だけ伝わればよい |
| この案件は AI により起票されました | AI がメールから作った案件です。内容が合っているか見てください。 | 次にやることを先に書く |
| 確定するまで想定金額には反映されません | 「確定する」を押すと想定金額に入ります。 | 二重否定をやめる |
| 内容を確認済みにする | 確認した | 短く |
| エピソード | 回（第1回・7月分） | 社内で誰も「エピソード」と呼んでいない |
| 按分グループ | 費用を分け合う案件のまとまり | 会計用語を知らない人にも分かる |
| 二重計上スクリーニング | 同じ支払いが2回入っていないか調べる | 何をする機能なのかを名前にする |
| AI 活動フィード / AI 活動履歴 | AI がやったこと | 表記を1つに |
| データがありません | (対象ごとの文 + 次の一手) | 何が無いのか・次に何をするのかが分からない |
| アクセス権限がありません | (必要な権限名) の「(レベル)」が必要です | 何を依頼すればよいか分かる |
| 該当なし | 当てはまるものはありませんでした | 体言止めをやめる |
| 音声サポート画面 共有 URL | 本番のURLを配る | 何をする操作なのかを名前にする |
| 公開URL · リアルタイム同期中 (常時緑) | 同期中 / 放送同期が切断されました | **状態と関係なく出す表示は嘘になる**。切れているときは切れていると出す |
| ゴミ箱 | ゴミ箱と直前の変更 | 保存前に効くのはどちらかを名前で示す |
| 列 (サイドバーのタブ) | 出す列 | 「追加・削除する」のか「いま見る列を選ぶ」のかが分かれる |
| ユーザー管理 | 人と権限 | 「管理」だけでは何をする画面か分からない |
| 権限設定 | この人にできること | 設定の対象 (人) と結果 (できること) を名前に出す |
| reader / editor / manager | 見るだけ / 書ける / 任せる | DBの値は変えず、画面の言い方だけ日本語にする |
| 保存に失敗しました (409) | この案件は○○さんが先に保存しています。最新を読み込んでから直してください。 | 誰と競合したか・次に何をするかを書く。「失敗」だけでは打ち直せない |
| 重複の可能性があります | 同じ金額（¥330,000）の仕入が GLS-A004 にすでに 1 件あります。 | 金額と行き先を出す。**断定はしない** (同額の定額費用は普通にある) |
| 共有を解除 (音声サポート) | 配布をやめる | 止めるのは URL で、台本は消えない |
| 404 Not Found (無効にした配布URL) | この配布URLは無効になりました | 410 で返し「あったが今は無い」と伝える。404 だと URL を間違えたと思って探し続ける |
| AI起票の未確認案件 (Slack本文) | AIが作って、まだ人が見ていないもの | 社内語を Slack に持ち出さない。全社が読むので一番平易に書く |
| 次回アクション期限超過 (Slack本文) | 返事の期限が過ぎたもの | 誰が待っているかで書く |
| 通知設定 | 朝の1通（Slack） | 何が届くのかを名前にする |
| 添付ファイル / 添付書類 | 原本 | 何のためのファイルかを名前にする (承認のために原本を見る) |
| ファイルがありません | 原本がまだありません + その場の置き場所 | 無いことを言うだけで終わらせない |
| 返信を送信 | 保存する + 本文をコピー + 送った | **ONAiR はメールを送らない**。送信だと誤解されると「送ったつもりで届いていない」が起きる |
| 修正内容を入力してください | 直した理由（任意・AIの改善に使います） | 差分はサーバーが自動で取る。人に入力させる設計は続かない |
| 共同編集 / リアルタイム同期 | みんなで書くメモ + 保存ボタンはありません | 仕組みの名前ではなく、何ができるかで書く |
| 接続エラー (同時編集) | 同時編集に繋がりませんでした。いまは読むだけにしています | 黙って編集させると「書いたのに保存されていない」になる |
| 他のユーザーが編集中です | いま編集中: 案件名（寺井 岳宏） | 誰がどの欄かまで書く。保存は全項目まとめてなので、別の欄でも相手の変更を消す |
| アクセスなし | 見えない | 「メニューにも出ない」ことが伝わる |
| 報告資料 / 営業レビュー / 週次 | ふりかえり（タブで切り替え） | どれも「終わったことを見る」画面なので入口を1つに |

## 残す言葉 (社内語)

次は**社内の共通語なので残す**。ただし**初めて出る画面に1文の説明を必ず置く**。

| 語 | 説明文の例 |
| --- | --- |
| ネタ | まだ提案していない、見込みの段階。 |
| ヨミ | 受注の見込み。ネタから受注までの途中の段階。 |
| GLS番号 | 経理・請求で使う案件の番号。 |
| 押し / 巻き | 本番の進行が予定より遅れている / 早いこと。 |
| 稿 (第3稿) | 配った版の番号。「稿を上げる」を押したときだけ増える。 |
| ロール | 台本のかたまり (オープニング・受賞発表 など)。 |
| キープ | 隔週の報告会。ここに出す資料を「報告資料」と呼ぶ。 |

案件一覧の「用語」ボタン (`ProjectListPage`) がこの役目を担っている。

---

## 文字の大きさと色

- 補助テキストの**下限は 12px**。これより小さい文字は使わない。
- 補助テキストの色は **`#5d6470` (`text-secondary-foreground` / `text-muted-foreground`) 以上の濃さ**。
  `#8b929c` は白背景でコントラスト 3.08:1 しかなく AA を満たさないため**使用禁止** (装飾アイコンのみ許可)。

---

## チェックの仕方

```bash
# 禁止語が画面テキストに出ていないか (コメント行を除く)
grep -rn "共用キー\|MCP 経由\|監査ログ\|Internal Server Error\|Network Error" \
  --include=*.tsx client*/src | grep -v "^\s*//" | grep -v "\* "

# 使用禁止の色
grep -rn "8b929c" --include=*.tsx --include=*.css client*/src shared/src
```
