# 画面に出す言葉のルール

> **状態**: 現役の決めごと
> **最終確認**: 2026-09-13 — ルール10（通じるカタカナ語は言い換えない）を追加。旧: 2026-09-08（v4.6.10） — 「GLS番号」→ 画面表記「管理番号」（2026-09-08 のご指示）は「言い換え表」に載っている
> **位置づけ**: 画面に出す言葉の正。PR レビューのチェック対象で、`scripts/check-ui-tokens.mjs` と、ルート `CLAUDE.md`・`docs/README.md`・[v4-plan.md](v4-plan.md) の「大前提」（モックと衝突したらこの文書のほうを直す）から参照される。

UI/UX 刷新 (v2.9.251〜) で決めた文言ルール。**PR レビューのチェック対象**。
画面に出るテキスト (ボタン・見出し・説明・エラー・トースト・メール本文) すべてに適用する。
コード内のコメントと変数名は対象外。

---

## 5つのルール

### 1. 1文に1つのことだけ書く

同じ情報を対象ごとに書き分けない。「AI が作った」という1つの事実に4通りの表記を作ると、
読む人には**表記の違いに意味があるように見えてしまう**。

| ✕ | ○ |
| --- | --- |
| AI起票 / AI取込 / AI登録 / AI (対象ごとに4通り) | **AI作成** (すべて統一) |

### 2. 次にやることを先に書く

状態の説明より、その人が次に押すもの・確かめるものを先に置く。

| ✕ | ○ |
| --- | --- |
| この案件は AI（問い合わせメール取込等）により起票されました。 | AI がメールから作った案件です。内容が合っているか見てください。 |
| 確定するまで想定金額には反映されません。 | 「確定する」を押すと想定金額に入ります。 |

### 3. 期限は「何月何日何時何分まで」

「今週中」「なるべく早く」「金曜まで」は**期限として成立していない**。
朝か夜かが決まらないものは期限ではない。日付だけ選ばれたときは 18:00 を補い、**補ったことを画面で示す**。

- 聞き方でも示す: 「いつまで？」ではなく **「何月何日何時何分まで？」**
- AI が曖昧な期限を読んだときは、黙って補完しない。補完した印を出して人に確認させる。
- 期限が読めない依頼も**捨てない**。残して期限を聞く。

### 4. 数字で書き、感想を書かない

「たくさん」「かなり」「だいぶ改善」は書かない。件数・金額・率・日時で書く。

| ✕ | ○ |
| --- | --- |
| 未対応の問い合わせが多数あります | 未対応の問い合わせ 7件 |
| だいぶ待たせています | 最も古い待ち 2日 3時間 |

### 5. 技術用語を画面に出さない

**禁止語** (画面テキストに出したら PR で落とす):

`MCP` / `監査ログ` / `actor` / `共用キー` / `トークン` / `500` / `タイムアウト` /
`Internal Server Error` / `Network Error` / `null` / `undefined` / `JSONB` / `SQL` /
`エンドポイント` / `ペイロード` / `スナップショット`

内部の詳細は**消すのではなくツールチップ (title 属性) に退避**する。ただし退避先も画面テキストなので、
用語そのものは平易な言い方に置き換える。

| ✕ | ○ |
| --- | --- |
| 実行: 共用キー ／ 指示: 寺井武大 | AI が自動実行 |
| AI (MCP 経由) が実行した書き込みの監査履歴です | AI が作ったり直したりした記録です。 |
| 500 Internal Server Error | サーバー側で処理が止まりました。少し待ってから、もう一度お試しください。 |
| 429 Too Many Requests | 短い時間に何度も読み込んだため、少し待つ必要があります。10 秒ほど待ってから、もう一度お試しください。 |
| 504 Gateway Timeout | 時間内に読み終わりませんでした。期間や案件で絞ってから、もう一度お試しください。 |

エラー文の組み立ては `shared/src/client/states/ErrorPanel.tsx` の `humanizeError()` に集約してある。
**例外オブジェクトのメッセージを画面にそのまま出さない**こと。

## 開くか、残すか (2026-09-05 追加)

**ルール1〜5 は「どう書くか」だけを決めていて、「その語を開くかどうか」を決めていなかった。**
そのため現場では「とにかく開く」に倒れ、開いた語が別の語とぶつかったり
（按分グループ ⇔ 費用を分け合うグループ）、新しい造語になったり（レイヤー・投入口・月次ユニット）していた。

判断の材料にした調査は [docs/reviews/2026-09-05-terminology-review.md](reviews/2026-09-05-terminology-review.md)
（画面文字列 約6,500件の棚卸し＋Salesforce・Slack・Outlook・Google カレンダーほか8サービスの日本語UI調査）。

### ルール6: 開くかどうかは「画面の外で通用するか」で決める

**難しさでは決めない。** Salesforce は「商談」「取引先責任者」と開きながら
「フェーズ」「確度」「パイプライン」は残している。線は難易度ではなく**通用範囲**で引かれている。

| 条件 | 判定 | 例 |
| --- | --- | --- |
| 社外・帳簿・請求・契約・法令に出てくる | **残す** | 按分・検収・販管費・限界利益・売上総利益・税区分・適格事業者・役務提供完了日 |
| 業界標準語で、他社ツール・書籍・転職先でも同じ語 | **残す** | ステージ・パイプライン・確度・ガント・カンバン・ランダウン・プロンプター・香盤・尺・稿・押し／巻き・TAKE／PVW・ラック・U位置 |
| ONAiR の中でしか意味を持たない機能名・状態・操作 | **開く** | 未仕分け・今日さばくもの・見るだけ／書ける・仮押さえ |
| 単独では何のことか分からない | **語を足す**（開くのではない） | 「ルール」→「貸出のルール」、「レイヤー」→「表示するカレンダー」 |

**開いた結果が新しい造語になっていたら失敗**。造語は検索されず、引き継ぎで通じない。

### ルール7: ラベルは12文字まで。超えたら副題に落とす

**名前の場所に説明文を置かない。** 短く呼べない名前は、口頭でも検索でも指せない。

| ✕ | ○ |
| --- | --- |
| 費用を分け合うグループ（左メニュー・11文字） | **按分グループ** ＋副題「複数案件にまたがる費用・売上を案件ごとに分ける」 |
| アーカイブする（一覧から隠す。消えません） | **一覧から隠す**（対は「一覧に戻す」） |
| 売上・請求への登録を取り消して見積もりに戻す | **売上登録を取り消す** |
| 先行タスク（これが終わってから着手する） | **先行タスク**（定義は直下の説明文に） |
| あとから足された機材を取り込む | **機材を取り込む** |

### ルール8: 動詞は1組に固定する (標準語系)

**追加 / 編集 / 削除 / キャンセル / 保存** に統一する。
和語系（足す・直す・消す・やめる）とは**混ぜない**。

以前は和語系と標準語系が並走していた（実測: やめる 63 / キャンセル 27、追加 31 / 足す 13、
編集 11 / 直す 16、削除 11 / 消す 21）。分岐線は「v4 で作り直した画面かどうか」とほぼ一致しており、
**作業の切れ目がそのまま語彙の切れ目**になっていた（利用者から見ると理由なく言葉が変わる）。

- **業務上の意味がある動詞は残す**: 取り消す・複製する・提出済にする・稿を上げる・配布をやめる
- **進行中は「動詞＋中…」**（三点リーダは `…`。`...` は使わない）
- **失敗は `〈対象〉を〈動詞〉できませんでした。` ＋ 次の一手1文**。「〜に失敗しました」は使わない

### ルール9: 開くときも「基本語」で開く。口語・造語・比喩を作らない (2026-09-06 追加)

**ルール6は「開くかどうか」だけを決めていて、「開いた先にどんな語を使うか」を決めていなかった。**
そのため「開く」と判定した語が、一般に通用しない口語や、その場かぎりの言い回しに置き換わった。
利用者からのご指摘（2026-09-06）:「**基本単語がベースになるべきだし、表現も稚拙で一般的ではない**」。

| ✕ いま | ○ これから | 何が問題か |
| --- | --- | --- |
| 探す | **検索** | 同じアプリの中に「検索」が既に27件あり、左メニューと下タブだけ和語だった |
| 動いている案件 / 止まっている案件 | **更新のあった案件 / 停滞中の案件** | 「動いている」は状態語として業務語彙になっていない |
| 今日さばくもの / 今日片づける営業 | **本日対応** | 「さばく」「片づける」は口語・比喩 |
| 一覧をひらく / 全部ひらく | **一覧を開く / すべて開く** | 同じ操作が同じアプリで漢字と仮名の2表記 |
| 見るだけ / 書ける | **閲覧 / 編集** | `manager` だけ「管理」に直り、和語2＋漢語1という一番読みにくい形で残っていた |
| お金のルール | **請求・支払のルール** | 中身は締め日・支払サイト・消費税＝すべて帳簿語。入口だけ語彙が跳ぶ |
| 知らせと文面 | **通知とテンプレート** | 「知らせ」は名詞として一般語ではなく、検索もされない |
| 出すもの / 最近見たもの / よく行く先 | **表示するカレンダー / 最近見た項目 / よく使う画面** | 「〜もの」「〜先」で名詞を作る癖 |
| 期限が来た次の一手 | **期限超過の次アクション** | 将棋の比喩。同じ画面に「次のアクション」が既にある |
| 払う前に確かめる机です | **請求書・注文書を確認し、承認後に台帳へ登録します** | 比喩は説明にならない |

**判定の順序**（ルール6 の判定のあとに必ず通す）:

1. その語は**他社の業務ツール・履歴書・議事録に書ける**か → 書けないなら不可
2. **口頭で言えるか**（「動いているものを見て」は指示として成立しない）
3. **一語で言えるか**（「〜するもの」「〜してあるもの」は、たいてい漢語1語で言える）

**開くとは「漢語をやめて和語にすること」ではない。**
基本語であれば漢語のままでよい（進行中・停滞・検索・作成・承認・解除・登録・発行）。
避けるのは**専門語**であって、**基本語ではない**。
ルール6の「開く」に当たった語でも、行き先が口語・造語・比喩になるならそれは**開けていない**。

### ルール10: 通じるカタカナ語は、言い換えずそのまま使う (2026-09-13 追加)

**ルール6は「開くかどうか」、ルール9は「開いた先の語」を決めていたが、"開かずに残す側"の書き方を決めていなかった。**
そのため運営マニュアルの設計で、他のツールで通じるカタカナ語をわざわざ日本語に言い換えた造語が生まれた。
利用者からのご指摘（2026-09-13）:「**変な用語はやめてください。より一般的な用語にしてください（カタカナ語も適宜）。他のアプリでも同様です**」。

| ✕ 言い換えていた | ○ これから | なぜ |
| --- | --- | --- |
| 紙面 | **キャンバス** | Figma・Illustrator・Canva の日本語版はすべて「キャンバス」 |
| ひな形 | **テンプレート** | Word・PowerPoint・Canva の標準語 |
| すいつき | **スナップ** | Figma・Illustrator・PowerPoint の標準語。造語で検索もされない |
| 柱 | **ヘッダー** | 「柱」は印刷業界語で、社外・引き継ぎで通じない |
| 重なり | **重ね順**（前面へ・背面へ） | PowerPoint が「重ね順」。数字（z-index）は出さない |
| 冊子 | **マニュアル** | 印刷業の言い方。機能名（運営マニュアル）に合わせる |
| ひな形のブロック | **全ページ共通のブロック** | 「マスターページ」を開くなら、語を足して説明する（ルール6） |
| 段・箱（組織図） | **階層・チーム** | プロジェクト管理の画面が既に「チーム名」と呼んでいる |

**残す語**（言い換えない）: 差し込む／差し込み元（Word の「差し込み印刷」）・書き出す（Illustrator 等）・
ブロック（Notion・WordPress）・ステージ・ガント・カンバン・ランダウン（ルール6の業界標準語）。

**判断は難易度ではなく通用範囲**（ルール6と同じ）。**カタカナを避けること自体は目的ではない。**
避けるのは「そのツールの中でしか通じない言い換え」であって、業界で通っているカタカナ語ではない。

### 文型は3つだけ

```
エラー   : 〈対象〉を〈動詞〉できませんでした。〈次の一手〉。
空状態A  : まだ〈対象〉がありません。〈〜すると、ここに出ます〉。[ 〈対象〉を追加 ]
空状態B  : 条件に合う〈対象〉はありません。〈条件を変えてお試しください〉。
権限     : 〈アプリ名〉の「〈見るだけ／書ける／管理〉」が必要です。
```

正は `shared/src/client/states/ErrorPanel.tsx` の `humanizeError()` と
`shared/src/client/states/NoPermissionPanel.tsx`。**新しい型を作らず、ここに寄せる。**
`EmptyState` の `title` は**必須**（既定値「データがありません」は 2026-09-05 に廃止した。
渡し忘れると、このルールが名指しで禁止した文が出てしまうため）。

## チェックの仕方

**正は `npm run lint` の `scripts/check-ui-tokens.mjs`**（`forbidden-wording` の検査）。
下は手元で当たりを付けるための grep で、**門はスクリプトのほう**です。

```bash
# 禁止語が画面テキストに出ていないか (コメント行を除く)
grep -rn "共用キー\|MCP\|監査ログ\|論理削除\|Internal Server Error\|Network Error\|データがありません" \
  --include=*.tsx client*/src shared/src | grep -v "^\s*//" | grep -v "\* "

# 英語のロール名が画面に漏れていないか (reader/editor/manager/owner)
grep -rn "\b\(reader\|editor\|manager\|owner\)\b.*権限" --include=*.tsx client*/src shared/src

# 動詞が2系統になっていないか (和語系が残っていたら標準語系へ・ルール8)
grep -rho ">\(足す\|直す\|消す\|やめる\)<" --include=*.tsx client*/src shared/src | sort | uniq -c

# 「〜に失敗しました」が残っていないか (ルール8)
grep -rn "に失敗しました" --include=*.tsx --include=*.ts client*/src shared/src | grep -v "^\s*//"

# 三点リーダが `...` になっていないか
grep -rn '\.\.\.<' --include=*.tsx client*/src shared/src

# 使用禁止の色
grep -rn "8b929c" --include=*.tsx --include=*.css client*/src shared/src
```

### baseline を増やさない

`scripts/check-ui-tokens.mjs` は**既存の違反件数を baseline として持っています**。
`forbidden-wording` は 2026-09-05 の棚卸し時点で 40件超を容認しており、**事実上ザルでした**。
新しく足すときは baseline を**増やさず**、直してから通してください。
