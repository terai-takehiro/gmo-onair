# 案件管理 全面刷新提案 — 営業ジャーニー縦軸の再構成 (2026-07-18)

対象: 案件管理アプリ (`client/`)。GMOイズム (スピリットベンチャー宣言 第13版 + 自問自答10カ条) を設計原理として読み込み、
営業担当者のカスタマージャーニーを情報設計の縦軸に据えて全面再構成する提案。

---

## 0. ノーススター (この刷新が答えるべき1つの問い)

> **「今日、お客様を待たせているものはゼロか？」に、アプリを開いて3秒で答えられること。**

SV宣言より:
- 「広告・Webサイトの改善点、**営業窓口・電話・メールに届くお客様の声・ご意見、すべてのヒントは現場にある**」(ノウハウ7)
- 「お客様はもちろん、**すべての方との接点で最高のおもてなし**をし、ファンになってもらおう」(基本行動原理19)
- 「人はミスをする生き物である。**自動化+チェックリストでミスを最小化**」(C-27)
- 「期限は**『何日何時何分まで』と明確に**。検討中・確認中は使わない」(目標面5)
- 自問自答10カ条⑩「この報告に**提案(リコメンド・ネクストアクション)はあるか？**」

## 1. 現状診断 (何がイケていないか)

現在の IA は「**データ種別**」(案件/タスク/営業/マスター) で編成されており、
営業担当者の**時間軸 (ジャーニー)** とも**お客様軸**とも一致していない。

構造棚卸しで特定した6つの分断:

| # | 分断 | 実害 |
|---|---|---|
| D1 | **顧客軸ビューの欠如** (顧客一覧は一覧+編集ダイアログのみ。`/sales/customers/:id` が存在しない) | 「この会社と今どうなってる?」に答えるのに 案件検索→個別に開く の多段導線。活動記録も案件優先で顧客串刺し不可 |
| D2 | **お客様の声の二重管理** (問い合わせ/見積請求/内覧会の実体は別SPA `/daily`。案件管理からは件数バッジ+外部リンクのみ) | メール→案件化の連続導線が SPA 境界で途切れ、**見落としの温床** |
| D3 | **活動記録の編集場所が2系統** (案件のタイムラインは閲覧専用、記録は横断ページへ飛ぶ) | 商談の文脈を保ったまま「今の電話をメモ」ができない |
| D4 | **AI起票レビューの入口が3箇所** (ホーム/一覧/案件詳細) | どこで確認すべきか一意でない |
| D5 | **案件情報のルート離散** (確定案件・按分・タスク・エピソード・見積が別ページ、QuickLinks 頼み) | 案件を軸にした1つのワークスペースがない |
| D6 | **アラートの二重化** (「要対応」と「今日対応すべきこと」がホーム内で上下に分離) | 対応漏れ系の情報が2箇所に散る |

## 2. 設計原理 (GMOイズム → UI原則への翻訳)

| GMOイズム | UI原則 |
|---|---|
| お客様の声は現場にある (ノウハウ7) | **受信箱ファースト**: 全ての inbound (メール/問い合わせ/内覧会/AI起票) を1本のキューに。ゼロにする運用 (Inbox Zero) |
| すべての接点で最高のおもてなし (19) | **顧客360**: お客様単位で全接点履歴を1画面に。次に会う前に3秒で文脈復元 |
| 期限は何日何時何分まで (目標面5) | 全ての未対応アイテムに**経過時間/期限タイマー**を常時表示。「検討中」状態を作らない |
| 数字は毎日確認・毎日提供 (目標面6) | ホームは「今日の数字+今日の動き」。月次はレビューへ |
| 結論ファースト / 優先順位マトリックス | 画面の最上部は常に「今すべきこと」。参考情報は下へ |
| 逆算思考 (目標面3) | 案件画面はジャーニーステッパーで「ゴール(請求・報告)から逆算した現在地」を可視化 |
| 自問自答⑩ ネクストアクションはあるか | **次回アクションの無い進行中案件を「異常」として表示** (現在は空欄が普通) |
| ミスは自動化+チェックリストで防ぐ (C-27) | 漏れ防止をヒトの記憶でなく、**ステータス機械 (全 inbound が必ず終端状態を持つ)** で担保 |
| 情報のガラス張り (C-23) | 担当者不在でも誰でも顧客360で文脈を引き継げる |
| 複利志向 — 紹介なき営業は単利 (B-10) | ジャーニーの終端を「請求」でなく「**報告・ファン化**」まで延長 (イベント報告→お礼→次の相談) |

## 3. 新しい情報設計 — ジャーニー縦軸

### 3.1 営業ジャーニー (= サイドバーの新しい背骨)

```
 お客様の声   →   商談    →   受注・実施   →   請求    →   ファン化
 (受信箱)      (ヨミ管理)    (案件ワークスペース)  (財務連携)   (報告・レビュー)
```

**新サイドバー (営業管理):**

```
📥 受信箱                /sales/inbox          ← 新設 (D2/D4/D6 を解消)
🏠 今日                  /sales/today          ← ホーム再編 (旧ダッシュボード統合)
── お客様 ──
👥 顧客                  /sales/customers      ← 一覧 → 顧客360 詳細へ (D1 を解消)
── 商談 ──
📈 ヨミ・パイプライン    /sales/pipeline       ← 案件一覧の「ネタ/提案中」ビュー
📋 営業活動記録          /sales/activity-logs
── 案件 ──
📁 案件一覧              /sales/projects       (受注済み・実施中心)
✅ タスク                /sales/tasks/:view
🗂 確定案件・按分・旧GLS  (「案件」配下に集約)
── ふりかえり ──
🏆 営業レビュー          /sales/review
📊 報告資料              /sales/keep-report
✨ AI活動履歴            /sales/ai-activity
── マスター ──
取引先 / 顧客マスタ編集 / 料金表
```

### 3.2 📥 受信箱 (新設・最重要) — 「絶対に漏らさない」の装置化

**1本のキューに全 inbound を集約し、全件が必ず終端状態に到達する**ことを機械的に保証する。

集約対象 (既存データの union — **新規テーブル不要**):
| ソース | 既存ステータス | 終端 |
|---|---|---|
| AI起票案件 (未確認) | `ai_reviewed_at IS NULL` | 確認済み |
| 問い合わせ `misc_inquiries` | `handled_at IS NULL` | 対応済み / 案件化 |
| 見積・請求 `finance_docs` | `status IN (new, reviewing…)` | 処理完了 |
| 内覧会予約 `inview_registrations` | 未チェックイン・新着 | 確認済み |
| 期限超過の次回アクション | `next_action_date < 今日 AND 未完了` | 完了 / 延期 |
| メール由来の活動記録 (未返信) | `next_action` 未設定のAI取込活動 | 次アクション設定 |

UI 仕様:
- 各行に **経過時間タイマー** (受信からの経過を常時表示。24h 超は赤 — 「期限は何日何時何分まで」)
- 行内ワンタップ操作: 確認済み / 案件化 / 顧客360 を開く / 次アクション設定 (完了・延期は既存 API 流用)
- **0件のとき「お客様を待たせているものはありません 🎉」** を大きく表示 (Inbox Zero を報酬化)
- 上部に「最古の未対応: N時間」を常設 — チームの SLA が一目で分かる
- dailyops 系は権限に応じてブロック出し分け (処理详细は当面 `/daily` に deep link、Phase C で埋め込み)

### 3.3 👥 顧客360 (新設 `/sales/customers/:id`) — お客様ファーストの背骨

顧客を first-class に昇格。1画面の縦構成:

1. **ヘッダー**: 顧客名 / 担当 / 取引実績サマリー (累計売上・案件数・最終接点からの経過日数)
2. **未対応・次のアクション**: この顧客に紐づく受信箱アイテム + 次回アクション (最上部 = 結論ファースト)
3. **統合タイムライン**: 活動記録 (メール/電話/打合せ・AI取込チップ付き) + 案件のステージ変化 + 請求イベントを時系列1本で。**この場でインライン追記可能** (D3 解消)
4. **案件リスト**: この顧客の全案件 (進行中→完了)
5. **売上履歴**: 年次推移ミニチャート

既存データで成立: `activity_logs.customer_id` / `projects.customer_id` / `revenues` join。新 API `GET /customers/:id/overview` 1本。**マイグレーション不要**。

顧客一覧は行クリックで顧客360へ (現在は編集ダイアログのみ)。

### 3.4 📁 案件ワークスペース (ProjectFormPage の再構成)

現在の「巨大な1本のフォーム」を、**ジャーニーステッパー + 縦の優先順位**に再構成:

```
[ネタ] → [ヨミ] → [提案] → [受注] → [実施] → [請求] → [報告]   ← 現在地ハイライト
──────────────────────────────────────────
① 今すべきこと     — 次回アクション(期限付き)・ステージを進めるボタン。
                     次回アクション未設定の進行中案件は ⚠️ を表示 (自問自答⑩)
② お客様とのやり取り — タイムライン (インライン追記可・メール/AI由来チップ)
③ 商談・見積       — 想定金額 / 概算見積 / AI下書き確定
④ 実施             — スタジオ予約 / タスク / エピソード (別ページへ飛ばさずタブ内包)
⑤ お金             — 売上・仕入・粗利 (財務へのリンク)
⑥ 基本情報・書類   — 顧客 / 担当 / Box / 申込書 (編集頻度が低いものは下へ)
```

ポイント: **編集頻度・緊急度の高いものほど上**。現在は基本情報 (低頻度) が上、タイムライン (高頻度) が最下部で、優先順位が逆。

### 3.5 🏠 今日 (ホームの再編)

「数字は毎日確認」+「結論ファースト」で、朝一番に開く画面を再定義:

1. **受信箱サマリー** — 未対応 N件 / 最古 N時間 (1行、タップで受信箱へ)
2. **今日の次回アクション** — 今日が期限のものを時刻順 (完了/延期ワンタップ)
3. **今日・明日の現場** — イベント/収録/予約 (現行スケジュールの直近フォーカス版)
4. **今日の数字** — 今月売上/粗利の進捗 + ホット案件
5. 以下、現行のセクション (AI活動フィード等)

「今日対応すべきこと」(申込書未提出・イベント接近) は受信箱 or ②に統合し、**アラート源を1系統に** (D6 解消)。

### 3.6 AI レビューの一本化 (D4)

「AI起票の確認」操作の正式な入口は**受信箱のみ**。案件一覧・案件詳細はバッジ表示 (状態が見える) に留め、確認ボタンは受信箱へ誘導。

## 4. 実装フェーズ (dev 検証ごと・逆算)

| フェーズ | 内容 | 規模 | DB |
|---|---|---|---|

| **B. 顧客360** | `/sales/customers/:id` + `GET /customers/:id/overview` + 顧客一覧の行クリック遷移 + タイムラインのインライン追記 | 中 | 不要 |

| **D. IA 仕上げ** | サイドバーのジャーニー再編 / ホーム「今日」化 / パイプライン専用ビュー / (任意) 次回アクションの時刻対応・SLA 設定 | 中 | 任意 |

- モバイル 375px 基準・各フェーズ dev 検証 → ユーザー承認 → 本番、の通常フロー
