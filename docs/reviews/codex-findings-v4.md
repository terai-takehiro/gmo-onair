# Codex のレビュー指摘（v4 の全 PR・#38〜#105）

> **これは棚卸しの結果です。** v4 の PR 68 本すべてのレビューコメントを読み、
> `chatgpt-codex-connector` の指摘を1件ずつ書き出しました（2026-08-15 時点）。
>
> **合計 143 件・うち P1 が 48 件。返信または修正が確認できたのは 9 件だけ**でした。
> 残りは**指摘が付いたままマージ**されています（マージすると指摘は画面から消えるので、
> 誰も見なくなります。これがこの文書を作った理由です）。

## 読み方

- **P1 / P2 は Codex が付けた重みです。** P1 は「壊れている・データが壊れる・
  権限が抜けている」、P2 は「使えない・読めない・数が合わない」がおおよその目安
- **「状態」は 2026-08-15 に確かめたもの**です。⭕️ = 直っている（別の PR で直った分を含む）／
  ❌ = コードにまだ残っている／❓ = 未確認（読んだだけで、コードは見ていない）
- ⚠️ **❌ には「直さないと決めたもの」も入ります**（理由と、何が変われば直すかを書いてあります）。
  **決めたからといって表から消さないこと** — 消すと**次に読んだ人には無かったことになり**、
  同じところをもう一度掘るか、知らないまま「桁がそろう」と書いてしまいます
  （[#141](https://github.com/terai-takehiro/gmo-onair/pull/141) の指摘がまさにこれでした）
- **❓ を「残っている」と読まないこと。** 後の PR で偶然直ったものが実際にあります
  （`?tab=thread` のリンク・`/gpm/estimates/summary` のルート順・持ち帰りの二重登録）

渡しても黙って UTC のまま**になります（設定したのに効かない、いちばん気づけない形）。
`Intl` は ICU 内蔵の時間帯データを使うので、そちらで明示的に変換しています。

**5. 確定した記録が後から変わる** — ✅ **片づきました**（#113）。
**確定した週報**に後から行が足せた（ニュースの「週報へ送る」・MCP・直接叩き。画面だけが止めていた）／

⚠️ **`published` だけで判断しないこと** — デイリーニュースは*閲覧型*で

**ニュースが1行も書けなくなります**。

`npm run dev -w <アプリ>` で測り直した結果、**どの画面も横はみ出し 0px のまま**で
結論は変わりませんでしたが、当時それを言える根拠はありませんでした。
検査の script には**「`.flex` が本当に flex になっているか」を毎回確かめる行**を入れてあります。

（つまり締め日も支払日も、設定しても台帳には入っていませんでした）。
案件の二重登録は、**同じ瞬間に2回押すと2回とも通る**形でした
（`disabled` は描き直し1回ぶん遅れる）。**DB の一意索引で止め、
先に出来たほうを返します**（エラーにすると、出来ているのにもう一度作られる）。

**これで ❓ の P1 は残っていません。**（この時点で残っていたのは 69 件・すべて P2）

**切れた側には何も出ません。** 見積・請求の一覧は 300 件で切っているのに
**画面が並んだ行を数え、並んだ行を足して**いたので、**388 件 47,850,000 円 のところ
「300 件 4,136,000 円」**と出ていました（月末に突き合わせるまで気づけません）。
BOX は1回に 100 件しか返さないのに1回しか呼んでおらず、**101 個目からのファイルと

（番号を振る守りは「遅れて届いた結果で上書きしない」ためのもので、

❓ のうち **3件はすでに直っていました**（SearchPage の2件と、

読んだだけの行なので、**1件ずつコードで当たり直して**確かめています。

**10. 数字が嘘になる・記録が別のものに付く** — ✅ **片づきました**（#123）。
**それらしい数字が出る**ので誰も報告しません。やり取りの件数は**どの案件も「20件」**
（引いているのが 20 件まで・実データは 46 件）、「次にやること」にぶら下がる **①②③ は
概要から丸ごと消え**（数も出ないので**やることは1つ**に見える）、**`-10万円` の
マイナスは印として食われ**（符号が逆の金額が出る）、**鉤括弧で始まる文があとの行を
全部飲み込み**、**別の拠点の同じ名前の部屋が1つ消え**、AI の成果は
**`SUM(DISTINCT 金額)`** で**同じ金額の案件を1件に潰して**いました（50万円が3件で 50万円）。
短くできなかった印は、**引いてから失敗するまでに直された本文**に付き、
その本文は**二度と短くされません**でした。

⚠️ **#87（変換後も想定金額が古いまま）は、想定金額を上書きしないことにしました。**
`expected_amount` は**起票のときの見込み**で、AI の成果はそれと実績を比べるための値です。
受注のたびに上書きすると**比べる相手そのものが消えます**。代わりに**数えるほう**を直し、
**確定売上があればそれで数え、見込みで数えた件数を添える**形にしました。

**12. 壊れているのに「大丈夫」と出る** — ✅ **片づきました**（#129）。
設定画面の BOX は**空でなければ「つながっています」**（`BOX_CONFIG_JSON` は1行の JSON なので
貼り付けで欠けるのが普通に起きる）、書体の同梱の検査は **woff2 が1つ以上あるか**しか見ておらず
（断片1つが壊れると**その文字だけ**代替書体になる）、`shared` の参照の検査は
引用符が `"` だと**「alias が無い」という嘘の理由**を出していました。

**13. 保存が黙って失敗する・帯が2回目に動かない** — ✅ **片づきました**（#131）。
**いちばん大きいアプリ（案件管理）だけ、共通の「最後の受け皿」が効いていません**でした
（独自の `QueryClient` を作っていたため）。書き込み 296 か所に対して `onError` は 54 か所
しか無いので、残りは **400 / 403 / 500 が返っても画面に何も出ません**。
お知らせの帯は鍵が**中身**だったので、**同じ操作を続けたとき**
（「記録しました」→「記録しました」）に動きが再生されず、
**2回目が出たのか分からない**（そしてもう一度押される）状態でした。

**14. 止まったものが、止まったまま誰にも見えなくなる** — ✅ **片づきました**（#133）。
**ふりかえりの下書き**は「昨日終わった案件」を **20 件だけ**見ていたので、
同じ日に 21 件以上終わる週（大きなイベントの前後では普通に起きます）では
**21 件目から一生作られません** — 仕事は日に1回で、翌日はまた「その日の昨日」を
見るため、**取りこぼしは二度と拾われません**（実測: 25 件のとき 1晩目 20 件・
前の版の2晩目は **0 件**）。**録音の投入**は、サーバーが再起動すると
`transcribing` のまま残ります。

⚠️ **指摘は「一覧だけ直っていない」でしたが、実際は詳細も直っていませんでした。**
復帰の判定は `new Date(String(row.created_at).replace(' ', 'T'))` で日付を組み立て直して
おり、**pg は `timestamp` を `Date` で返す**ので
`Sat Aug 15 2026 10:53:12 GMT+0000 (…)` → `SatTAug …` → **必ず `Invalid Date`**。
`Number.isNaN` で早期に返していたので、**一度も失敗として見せたことがありません**でした。
止まった行は `pending` でも `failed` でもないので、**「確認待ち」の催促にも
「失敗」の一覧にも出ません** — 投げた本人には**録音が消えたようにしか見えません**。
しかも日常業務の投入ログは状態の日本語を3つしか持たず、**英語のまま**
（`transcribing`）出ていました。

**15. GLS-B（工事・構築）に放送の分類が付く** — ✅ **片づきました**（#134）。
`project-classification.ts` は「GLS-B は2段分類を持たない・**NULL のままにする**」と
決めていますが、**書く側で守っていません**でした。直す画面は GLS-B でも
**欄を出したまま**で、押せば保存されます。サーバーは2段から `project_type` を導くので、
**工事のプロジェクトが `hybrid_event`（ハイブリッド）になり**、標準工程の型・Excel・
集計が放送の案件として扱います。**押した人には何も出ません**（選べたのだから正しいと思う）。
**画面で欄を消すだけにせず、サーバーでも落とします** — MCP・古いタブ・直接叩きから通るため。
実測: コンサルの案件（GLS-B002）に2段を送っても `B / consulting / — / —` のまま
（**反証: 守りを外すと `B / hybrid_event / with_audience / broadcast`**）。

**16. AI の単価を書き替えると、過去の費用も一緒に変わる** — ✅ **片づきました**（#134）。
`ai_usage` に残しているのは**トークン数と録音の秒数だけ**で、金額は**読むときに**
いまの `AI_PRICING_JSON` を掛けて出しています。`.env.example` は「値は公開ページで
確認して入れること」と言うだけだったので、**手順どおりにやると先月の金額も変わります**。
さらにモデルを乗り換えて**古い鍵を落とすと、そのぶんが合計から静かに消えます**
（総額が下がるので「安くなった」と読めてしまう）。**「差し替えるのではなく足す」**を
`.env.example` に書き、画面には**いまの単価で出したこと**と、**単価の無いモデルを名前で**
出します。実測: 4 モデルのうちいちばん量の多い `gpt-5.4-old` の鍵を落とすと合計 $3.08 に
1セントも入らず、画面は「単価を入れていない 1 個のモデルは合計に含めていません
（gpt-5.4-old）」（**反証: 前の版は名前を出さない**）。

**⭕️ v4 の棚卸しは、これで全件に当たり終わりました**（143 件＝**元の #38〜#105 のぶん**）。
直したもの・すでに直っていたもの・再現しなかったものを、**どれがどれか分かる形**で
表に残してあります。**「再現しなかった」も測った結果を書いてあります** —
書いておかないと、次に読んだ人が同じところをもう一度掘ります。

**潰す作業そのものに付いた指摘**（#106 以降）は別勘定で、下の
[この棚卸しのあとに付いた指摘](#この棚卸しのあとに付いた指摘106-以降)にあります。
**そちらは #146 / #147 / #148 で片づきました。** 残っているのは
**直さないと決めた1件だけ**です（下の表を数えてください）。

**残件の数え方。** 件数は文章に書きません — **枝ごとに違う数になり、
毎回この1行がぶつかる**ためです（版の3か所を触らない決めごとと同じ理由。
[docs/changelog.d/README.md](../changelog.d/README.md)）。表を数えてください:

```bash

grep -c '^| .* | ❌' docs/reviews/codex-findings-v4.md   # コードに残っている
```

⚠️ **前の版は `grep -c '| ❓ |$'` と書いており、必ず 0 を返していました** —
状態の升目には `❓ **この作業中に見つけた**…` のように後ろに文が付くので、
**行末が `|` で終わりません**。**残件があっても「0 件」と出る**数え方で、
この文書が追いかけている「検査が嘘の OK を出す」形そのものでした。

## ⚠️ 実測で分かったこと — 数字は等幅になっていない（#45 を調べていて見つけた）

`font-number` は `font-feature-settings: 'palt' 0, 'tnum' 1` ＋
`font-variant-numeric: tabular-nums` を当てており、`shared/CLAUDE.md` は
**「金額を縦に並べたとき桁が一直線に」**なると書いています。**実測すると効いていません。**

## この文書の使い方

**これは決めごとです**（[docs/branching.md](../branching.md#マージしたらその-pr-のレビューを棚卸しに移す必須)）。

1. **マージしたら `npm run reviews:debt` を走らせる**（自分の PR だけでなく、その回のぶん）
2. 返していない指摘が出たら、**まずこの表に足す**。
   ⚠️ **直すのが先ではありません** — 書いてあれば、直すのは別の日でもよい
3. 潰したら状態を ⭕️ に変え、**直した PR 番号を書く**

### やってはいけないこと

- ⚠️ **「直さない」と決めたものを表から消すこと。** ❌ のまま残し、
  **理由と、何が変われば直すか**を書いてください。消すと**次に読んだ人には
  無かったことになり**、同じところをもう一度掘るか、知らないまま間違ったことを書きます
  （実際に #141 で指摘されました）
- ⚠️ **件数を文章に書いて、表と食い違わせること。** 数えるのは上の「数え方」で。
  文章の数字は古くなりますが、表は古くなりません（実際に1度食い違いました）
- ⚠️ **束に分けたあと、合計を数え直さないこと**（1件どの束にも入っていないことがありました）

### なぜここまで書くか

**マージすると指摘は GitHub の画面から消えます。** 直っていなくても消えるので、
**書かなければ存在ごと消えます**。実測: **143 件が埋もれ、それを潰す作業にも
26 件付き、24 件が記録されていません**でした（うち1件は**リリースが出せなくなる P1**）。
