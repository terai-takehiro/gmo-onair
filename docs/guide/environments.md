# 本番と検証・壊していい場所

間違えて会社の本物のデータを壊さないために、いま自分がどちらを見ているかを先に確かめましょう。

## 2つの環境は別物

| | 本番 | 検証 |
| --- | --- | --- |
| URL | `https://gmo-onair.jp` | `https://dev.gmo-onair.jp` |
| 中に入っているもの | 実際の業務データ | 練習用のダミーデータと、試しに入れたもの |
| 壊してよいか | ✕ | ○ |
| 新しい直しが届くとき | GitHub で Release を公開したとき（人の判断） | `main` にマージされた直後（自動） |
| AI（Claude）から使うときの接続先の名前 | `gmo-onair` | `gmo-onair-dev` |

- データベース（情報をためておく場所）は別々です（`onair_prod` と `onair_dev`）。
  本番のデータが検証に流れることも、検証のデータが本番に流れることもありません。
- 見た目は同じです。ログイン画面も同じです。**アドレスバーの `dev.` が付いているかどうか**で見分けてください。
- AI（Claude）から ONAiR を使うときも、検証用と本番用で接続先が分かれています。
  検証用は名前に `-dev` が付き、「これは検証環境です」と名乗ります（[docs/mcp-server.md](../mcp-server.md)）。

## 検証は自由に触ってよい

- 触って壊れても、業務には影響しません。新しい機能を試す・練習するときはここを使います。
- 最初からダミーの利用者・取引先・案件が入っています。自分で入れたものも残ります
  （毎回消えるわけではありません。まっさらに戻したいときはエンジニアに頼んでください）。
- 検証環境には、確認のために**一時的に昔の版の画面**が出ていることがあります
  （[直しが本番に届くまで](how-changes-ship.md) の「昔の版を検証環境で見る」）。
- ⚠️ 注意: 検証環境でも、BOX のフォルダ作成や Slack への通知のように**外のサービスにつながる操作は本物に届くことがあります**
  （設定しだいで本番と同じ接続先を使う作りです）。お客様や社外に何かが届く操作は、検証でも軽く押さないでください。

## 本番は慎重に扱う

- 実在するお客様・案件・お金の情報がそのまま入っています。練習のつもりで触らないでください。
- 本番が変わるのは、人が GitHub で Release（正式な版）を公開したときだけです。
  AI が自分の判断で本番に出すことはありません。
- データベースは3時間ごとに自動で控え（バックアップ）を取っています。
  万一のときの戻し方は [docs/ops/db-backup-restore.md](../ops/db-backup-restore.md)（エンジニア向け）。

## ログインのしかた

| 環境 | ログイン方法 |
| --- | --- |
| 本番 | メールアドレスとパスワード。携帯電話番号を登録している人は、SMS で届く6桁の確認コードも入力する |
| 検証 | 本番と同じ。メールアドレスとパスワード（SMS の確認コードが要るかは、その環境の設定と電話番号の登録しだい） |
| エンジニアが自分のパソコンで動かす開発環境 | 画面に並んだ人のカードから自分を選ぶだけ |

- 「カードを選ぶだけ」で入れるのは、エンジニアが手元で動かす開発環境だけです。
  検証環境（`dev.gmo-onair.jp`）は本番と同じログイン方法です。
- 検証環境には SMS を送る仕組みがつながっていません。携帯電話番号を登録した利用者は、
  確認コードがサーバーの記録にしか出ないため、検証環境にログインできないことがあります。
  検証環境で使う利用者は、電話番号なし（パスワードだけ）で作ってもらってください。
- ⚠️ 要確認: 検証環境のダミー利用者には共通のパスワードが設定されています。
  この説明書に書くかどうかは決めていないので、必要な人はエンジニアに聞いてください。
