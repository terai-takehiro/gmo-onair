# 直しが本番に届くまで

コードの直しがいつ・どうやって皆さんの見る画面に反映されるかを知っておくと、
「直したのにまだ変わっていない」と困ったときに、どこを見ればよいか分かります。

## 1. 直しは「ブランチ」という作業場所で行う

エンジニアがコードを直すときは、まず「ブランチ」（`main` という正の1本から分かれた、
作業専用のコピー）を作ります。ここで直している間は、まだ誰の画面にも影響しません。

直しがまとまったら「PR」（プルリクエスト。変更のかたまりを他の人に確認してもらう単位）
にします。PR は他のエンジニアのレビュー（読んで確認すること）と、自動の検査を通ってから
「マージ」（他の人の変更と自分の変更を1つに合わせること）されます。

## 2. マージすると、自動で検証環境に出る

PR が `main` にマージされると、そのタイミングで自動的に検証環境（`dev.gmo-onair.jp`）に
反映されます。人が改めて「出す」操作をする必要はありません。

検証環境は**確かめるための場所**です。実際の画面と同じ動きをしますが、本番（お客様や
社内の業務が実際に使う環境）とは別物です。何か問題が起きても、業務には影響しません。
その日のうちに検証環境には出ると考えてよく、確認はここで行います。

## 3. 本番に出るのは「Release」を出したときだけ

検証環境で問題がないと確認できたら、担当者が「Release」（リリース。正式な版として
世の中に出す操作）を行います。これで初めて本番（`gmo-onair.jp`）に反映されます。

マージしただけでは本番は変わりません。**本番に出す・出さないは、必ず人が明示的に
判断して行います。** 自動では絶対に本番へは進みません。

## まとめ

| 段階 | 場所 | 誰が動かす |
| --- | --- | --- |
| ブランチで直す | 誰の画面にも出ない | エンジニア |
| PR がマージされる | 検証環境に自動で出る | 自動 |
| Release を出す | 本番に出る | 人（明示的な判断） |

困ったときは、「まだ検証環境の段階か」「Release は出たか」を確認すると状況が分かります。
