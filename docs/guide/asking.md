# 直してほしいときの頼み方

「ここ分かりにくいな」「こうなったらいいのに」と思ったときの、伝え方をまとめました。
言うだけで終わらせず**記録に残す**と、忘れられずに後で直してもらえます。

## Issue（イシュー）とは

GitHub（ソースコードを管理しているサービス。エンジニアが作業している場所）にある、
**困りごとや要望を1件ずつ記録しておく場所**です。ここに書いたことが、実際の修正作業の出発点になります。

## 頼み方

1. GitHub のこのリポジトリ（`gmo-onair`）を開く
2. 「Issues」タブ → 「New issue」
3. 用意されている型（テンプレート＝あらかじめ決まった書式）から、近いものを選ぶ

型は3つあります。

| こんなとき | 選ぶ型 |
| --- | --- |
| 動かない・表示がおかしい・保存できない | 不具合の報告 |
| 新しい機能が欲しい・使い勝手を変えてほしい | 機能の追加・変更 |
| 現場から「こうしてほしい」と言われた（自分の要望ではなく取り次ぎ） | 利用者からの依頼 |

**白紙のまま作ることはできません。** 必ずどれかの型を選ぶ仕組みになっています。

## 書くとよいこと

型ごとに項目は少しずつ違いますが、次の3つがあれば直せます。

- **どの画面・どのアプリで**（例: 案件管理の見積タブ）
- **何をしたら**（押した順番。「①案件を開く ②見積タブを押す ③PDFを押す」のように）
- **どうなってほしいか**（不具合なら「本当はどうなるべきか」、要望なら「できるようになってほしいこと」）

画面に出た文言やエラーの文章は、自分の言葉に直さずそのまま貼ってください。
スクリーンショットがあれば、なお伝わりやすくなります。

「利用者からの依頼」を選ぶときは、頼まれた言葉をそのまま書くのがコツです。
自分の言葉に直してしまうと、あとで「本当は何を頼まれたのか」が分からなくなります。

## GitHub を使えない・分からないとき

無理に自分で Issue を立てなくても大丈夫です。開発を担当している人に、上の3つ
（どの画面で・何をしたら・どうなってほしいか）を伝えれば、代わりに記録してもらえます。
